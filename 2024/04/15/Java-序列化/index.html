序列化与反序列化

序列化把对象字段写成字节流，便于落盘或通过网络发送。反序列化按字节流重建对象。

Java 原生实现在 java.io：类实现 Serializable 或 Externalizable，再用 ObjectOutputStream / ObjectInputStream。这套机制和具体 JVM 版本、类的私有字段绑在一起，不适合作为对外接口的数据格式。

Serializable

java.io.Serializable 是标记接口，没有方法。实现它表示「允许按默认规则读写字段」。

serialVersionUID 用来判断字节流和当前类是否算同一版本。请显式写成 private static final long。不声明时，不是由 javac 写进 class 文件，而是序列化运行时按类名、接口、字段、方法签名算出一个默认值。你一改字段或方法，默认值就变，旧文件会 InvalidClassException。

兼容的小改动（增加字段、把字段标成 transient）可以保持原来的 UID。语义已经不兼容时，应换 UID，或直接换一种格式做迁移，不要在 readObject 里无限堆分支。

读写对象

反序列化不会调用普通构造器。password 是 transient，读回来是 null。静态字段属于类，不写入对象流。ObjectInputStream.readObject 声明抛出受检异常 ClassNotFoundException。

父类没实现 Serializable、子类实现了时，父类字段不进字节流，反序列化时会调用父类可访问的无参构造器来初始化父类部分。父类没有这样的构造器，子类就无法序列化。父类也实现了 Serializable 时，则父类字段一并按规则处理，且不会为了父类再调无参构造器。

同一对象被多个字段指到时，对象流会记下句柄，反序列化后仍是同一实例，不会复制成两份。writeObject 两次写入同一个对象，读出来仍是 ==。

transient 与自定义读写

transient 用来跳过缓存、可再计算的值、密码等不应落盘的字段。

readObject 里要检查不变量。反序列化可以构造出构造器本来会拒绝的对象。

Externalizable

Externalizable 继承 Serializable，要求自己实现 writeExternal 和 readExternal，默认机制不再帮你写字段。反序列化时先调用 public 无参构造器，再调用 readExternal。少了无参构造器会失败。

它适合格式必须完全自己控制的场景。多数业务类型用明确的 schema（JSON、Protobuf）更直接。

枚举、记录与版本

枚举即使实现序列化，写出的也是常量名，读回来仍是原来的单例，不会调用枚举构造器。record（Java 16）实现 Serializable 时按组件序列化，并在反序列化时走规范构造器，不变量可以放在构造器里。

普通类增加一个带默认逻辑的字段、并保持 serialVersionUID 不变，旧数据里该字段为类型默认值。删除字段或修改字段类型通常不兼容。

安全

不要对不可信字节流做原生反序列化。攻击者可以挑选类的 readObject 链，在旧版本 JDK 上造成远程代码执行。对外接口用 JSON、Protobuf 等显式 schema，并校验字段。

必须使用 ObjectInputStream 时：限制数据来源、尽快升级 JDK，并用 ObjectInputFilter（Java 9 引入，Java 17 起有更严格的默认工厂）做类白名单。serialVersionUID 解决的是版本不一致，不是恶意载荷。

小结

需求 做法
允许默认序列化 implements Serializable
固定版本判断 手写 serialVersionUID
排除字段 transient，或自定义 writeObject
完全自己写格式 Externalizable 或换 schema
不可信输入 不要用原生反序列化

原生序列化适合进程内、信任边界内的短生命周期数据。跨服务、落库、给浏览器的数据换明确的数据格式。
