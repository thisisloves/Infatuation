红叶有霜终日醉,醉到深处是相思。

用哪套 API

新代码用 java.time（Java 8 引入）。java.util.Date 和 Calendar 是遗留 API：可变、月份从 0 开始、线程不安全，很多方法已经废弃。

类型 表示
LocalDate 日期，无时区、无时间
LocalTime 一天中的时间
LocalDateTime 日期加时间，仍无时区
Instant 时间线上的一点，UTC
ZonedDateTime 带时区的日期时间
Duration / Period 一段时间 / 日历上的年月日

Date 仍会在旧接口里出现。它表示的是时刻（自 epoch 起的毫秒），不是日历字段。未废弃的构造器主要是无参（当前时刻）和 Date(long epochMilli)。

new Date(99, 2, 12) 属于废弃构造器：年份是「自 1900 起」，所以 99 表示 1999；月份 2 表示三月而不是二月。不要再用它比较日期。

java.time 示例

now() 不带参数时用系统默认时区，服务器时区一改，LocalDate.now() 的「今天」可能不同。要可重复的结果，传入 ZoneId 和 Clock。

这些类不可变，修改操作返回新对象：today.plusDays(1) 不会改变 today。

比较

LocalDate、Instant 实现了 Comparable，用 compareTo、isBefore、isAfter、equals。

遗留 Date 也可以 before / after / equals / compareTo / getTime。相等看的是同一毫秒，不是「同一天」。Date 的 compareTo(Object) 这种原始类型重载来自泛型之前的文档，现在实现的是 compareTo(Date)。

不要用 == 比较两个 Date 或两个 LocalDate 是否同一天，LocalDate 的 equals 才比较年月日。不同时区的 ZonedDateTime 表示同一瞬间时，toInstant().equals 可能为真，而 equals 本身还看时区，两者不一定同时成立。

格式化

DateTimeFormatter 不可变，可以做成 static final 给多线程用。模式里 H 是 0–23 时，h 是 1–12 时，12 小时制还要配 a 才不会把下午两点格式化成 02。

SimpleDateFormat 能格式化 Date，但不是线程安全的，不要放进静态字段共享。模式同样区分 HH 和 hh：

写成 hh 又不加上午/下午标记，14 点会显示成 02，这是格式错误，不是时区问题。

月份 M 是月份，m 是分钟。yyyy 是日历年，周历年用 YYYY，跨年那一周很容易差一年。

printf 也可以打 Date 和 Calendar：%tF 是 yyyy-MM-dd，%tT 是 HH:mm:ss，%tc 是较完整的日期时间。它不接受 LocalDateTime，要先转成遗留类型或自己 format。

和旧类型互转

Date 没有时区。转成 LocalDateTime 时必须指定用哪个时区解释这个时刻，否则「哪一天」没有定义。

常见坑

  1. Calendar.MONTH 或废弃的 Date 月份从 0 开始，java.time 的月份从 1 开始。
  2. SimpleDateFormat 作为静态变量，多线程下结果错乱或抛异常。
  3. 用 hh 格式化 24 小时时间。
  4. 把 LocalDateTime 当成绝对时刻存进数据库。跨时区要用 Instant 或带偏移的类型。
  5. 解析失败抛 DateTimeParseException，它是非受检异常。模式和输入字符串必须同一套字段。

小结

新代码用 java.time：日期 LocalDate，时刻 Instant，展示再格式化。Date(long) 只表示 epoch 毫秒。格式化用 HH 表示 24 小时，共享格式化器时用 DateTimeFormatter，不要共享 SimpleDateFormat。
