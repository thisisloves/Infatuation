Java 枚举

2024-06-20
  • Java
本文总阅读量次

山海自有归期，风雨自有相逢。

枚举不是整型常量

变量只有固定几种取值时，用枚举把它们收成类型，例如星期、订单状态。Java 的 enum（Java 5 引入）是类，不是 C 语言那种「一组 int」。每个枚举常量都是该枚举类的一个 public static final 实例，全虚拟机通常只有这一份。

常量名用大写。greed 这类拼写会变成一个真的常量名，编译器不会帮你改成 green。

不能写 public 构造器。枚举构造器隐式为 private，写 public 会编译失败，外部也不能 new Color()。

旧写法 public static final Color RED = new Color(); 是 Java 5 之前的类型安全枚举模式，缺私有构造器时谁都能再 new。它不是今天 enum 的等价物，也不要靠 ordinal() 当稳定的业务编号。

基本用法

枚举常量可以用 == 比较，因为它们是单例。equals 的默认实现也是比身份。switch 可以直接分支枚举，没覆盖的常量在较新的编译器里会警告。

switch 表达式是 Java 14 正式可用的写法。更早的版本用传统 switch 加 break 即可，漏 break 会贯穿到下一个分支。

字段、构造器与抽象方法

枚举可以有字段和方法。常量要写在第一行，常量与后面的成员用分号隔开。构造器只能私有，参数由常量声明处传入。

若枚举声明了抽象方法，每个常量都必须写出自己的方法体。

常用方法

方法 谁提供的 作用
values() 编译器生成 返回包含全部常量的数组，每次调用都是新数组
valueOf(String) 编译器生成 按声明时的名字查找，没有则 IllegalArgumentException
name() Enum 声明时的名字，不受 toString 影响
ordinal() Enum 声明顺序，从 0 起。只适合内部，不宜入库
compareTo Enum 按 ordinal 比较

values() 写在循环条件里会反复分配数组。热路径上把结果存下来，或改用 EnumSet。

EnumSet 与持久化

java.util.EnumSet 是给枚举用的位集，比 HashSet<Color> 更小更快。EnumMap 用枚举做键，内部是数组。

枚举天然可序列化，序列化的是常量的 name，不是字段快照。反序列化得到的仍是原来的那个单例，不会调用构造器再造一个。所以即使用了自定义字段，也不会出现第二个 RED。改常量名字会让旧数据反序列化失败。

不要给枚举写 readObject 一类的自定义序列化来「克隆」常量。需要稳定对外编码时，单独设 code 字段，用自己的 fromCode，不要把 ordinal() 写进数据库。

常见坑

  1. 用 ordinal() 表示「男 0 女 1」，中间插入一个常量，所有旧编号错位。
  2. valueOf 传入展示文案而不是常量名。
  3. 在 equals 里比较 label，却用 == 比较两个不同枚举类型，编译期就会因类型不符失败，这反而是优点。
  4. 枚举构造器里调用外部可失败的逻辑（例如发网络请求）。类初始化失败后，这个枚举在该加载器里会一直处于无法使用的状态。
  5. 把枚举当成可以随意 new 的可变对象，在常量上改字段，所有使用者一起被改。

小结

Java 枚举是带名字的单例对象，不是 int 集合。常量在前、构造器私有，可以用字段和方法表达状态。查找用 valueOf 和 values，对外编号用自己的 code。集合优先 EnumSet / EnumMap。
