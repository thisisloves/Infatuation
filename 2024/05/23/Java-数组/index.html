Java 数组

2024-05-23
  • Java
本文总阅读量次

水遥山远谩相思，情知难舍弃，何似莫分飞。

数组是对象

数组是定长、同质的引用类型对象，不是基本类型。长度在创建时确定，之后不能改变；要变长用 ArrayList。

声明时方括号写在类型旁边更清晰。写在变量名旁边合法，但不是首选，多个变量时还容易看错。

创建与初始化

new 分配数组并给出默认值（数值 0，boolean 为 false，引用 null），再把引用交给变量。

下标从 0 到 length - 1。length 是 public final 字段，不是方法，不要写 length()。越界抛 ArrayIndexOutOfBoundsException。

没赋值的元素保持默认值 0.0，求和不会抛空指针，但业务上可能把「没填」和「真的是 0」混在一起。

遍历还可以用增强 for。它只读元素，改不了数组槽位里的引用；需要下标或要替换元素时用普通 for。

作为参数和返回值

数组传的是引用的拷贝。方法里执行 array[i] = ... 会改到调用方的数组；执行 array = new int[0] 只是让形参指向新数组。

reverse 不修改原数组。如果就地反转，左右指针交换即可，不必再分配。

多维数组

Java 的「二维数组」是数组的数组，每一行可以不等长。

grid.length 是行数，grid[i].length 才是该行的列数。只写 new int[2][] 时，行已分配，每行仍是 null，立刻访问 grid[0][0] 会空指针。

Arrays 工具类

java.util.Arrays 的方法都是静态的。基本类型和对象各有重载，不要把 byte 写成包装类 Byte。

方法 作用
sort(int[] a) 基本类型升序。对象数组要求元素可比较，内部用 TimSort
fill(int[] a, int val) 每个元素都设为 val。只填一段用四参数重载 fill(a, from, to, val)，to 不含
equals(long[] a, long[] b) 长度相同且对应元素相等。嵌套数组要用 deepEquals
binarySearch(int[] a, int key) 在已升序数组上二分查找
copyOf / copyOfRange 复制到新数组，可顺便加长（多出来的是默认值）
toString / deepToString 打印内容。直接打印数组只看到类型和哈希
asList 固定长度的列表视图，不能 add / remove

binarySearch 找到则返回下标；找不到返回 -(插入点) - 1，插入点是「若要保持有序应插入的位置」。返回值 >= 0 才表示找到。数组必须事先升序，否则结果没有意义。对 double 查找还有 NaN 的特例，业务代码少依赖它。

Arrays.equals(new int[]{1}, new int[]{1}) 为 true，但 == 为 false。两个 int[][] 用 equals 只比较内层数组的引用，内容比较用 deepEquals。

float / double 的 Arrays.equals 按 doubleToLongBits 比较，因此 NaN 会被当成相等，和 == 不同。

常见坑

  1. int[] a = new int[3]; a = {1, 2, 3}; 花括号初始化只能在声明时使用。
  2. Arrays.asList(1, 2, 3) 得到 List<Integer>；Arrays.asList(new int[]{1, 2}) 得到的是「一个元素、元素类型是 int[]」的列表。基本类型数组要装箱后再包装，或用 List.of（Java 9，同样不可变）。
  3. 把数组当可变长容器，越界后才想 new 一个更长的再复制。频繁加元素直接用 ArrayList。
  4. 排序对象数组时元素没有实现 Comparable，也没传入 Comparator，运行期 ClassCastException。
  5. 方法参数写成 int... 后又写 int[]，对编译器是同一个签名。

小结

数组定长、下标从 0、length 是字段。创建用 new 或初始化列表，传递的是引用。打印、比较、排序、二分查找优先用 Arrays，并记住二分查找的负数返回值公式和「必须已排序」。
