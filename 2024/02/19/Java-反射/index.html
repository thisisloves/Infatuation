Java 反射

2024-02-19
  • Java
本文总阅读量次

咫尺天涯处，似假几若真。

反射在做什么

Java 本身按静态类型编译。反射（java.lang.reflect）让程序在运行时查看类的字段、方法和构造器，并能越过编译期写死的类名去创建对象、调用方法。框架、序列化、测试桩靠它实现插件化和依赖注入。业务代码里到处反射，类型检查和重构都会变脆。

类加载之后，会有一个 java.lang.Class 对象描述这个类。这个 Class 实例在堆上。类的元数据自 Java 8 起放在元空间（Metaspace，本地内存），不再是「堆里的方法区 / 永久代」。一种类加载器里，同一个全限定名对应唯一的 Class 对象。

通过它可以看到结构，所以叫反射。它让 Java 具备一部分动态能力，并不把 Java 变成动态语言。

取得 Class 的三种方式

方式 写法 特点
类字面量 Student.class 编译期就知道类型，不触发初始化
已有对象 obj.getClass() 最直接
全限定名 Class.forName("pkg.Student") 按字符串加载。单参数形式会初始化类（执行静态块）

三者在同一加载器下得到的是同一个 Class。不想执行静态块时，用 ClassLoader.loadClass，或三参数的 Class.forName(name, false, loader)。

基本类型用 int.class。Integer.class 是包装类，两者不相等。数组的类名是 [Ljava.lang.String; 这种形式，用 String[].class 即可，不必手写。

常用类型

  • Class：入口，获取成员。
  • Constructor：构造器。Java 9 起不要用已废弃的 Class.newInstance()，改 getDeclaredConstructor().newInstance()。
  • Field：读写真字段。
  • Method：调用方法。
  • Modifier：把 getModifiers() 的位掩码解成 public、static、final。

getXxx 多为 public 成员，包含从父类继承的 public 方法。getDeclaredXxx 只看本类声明的成员，包含 private，不含父类。

invoke 的返回值是 Object，基本类型会被装箱。方法抛出的异常包在 InvocationTargetException 里，要用 getCause() 看真正原因。找不到成员抛 NoSuchFieldException / NoSuchMethodException。setAccessible 失败在 Java 9+ 模块系统里常是 InaccessibleObjectException。

setAccessible 与模块

Field、Method、Constructor 都是 AccessibleObject。setAccessible(true) 跳过 Java 语言的访问检查，从而读写 private 成员。这在 ORM、序列化和测试里常见，只应发生在可信代码里。

它不是安全边界。目标包若没有对当前模块 opens，Java 9 及以后即使用了 setAccessible(true) 也会失败。需要在 module-info.java 里开放包，或不要反射未导出的 JDK 内部类。

能做什么，代价是什么

运行期按类名创建对象，可以把 if (type.equals("csv")) return new CsvParser(); 收成配置里的类名，Spring 创建 Bean、JDK 动态代理（java.lang.reflect.Proxy）都建立在这上面。注解也要靠反射在运行时读取（前提是注解的保留策略是 RUNTIME）。

代价：

  • Method.invoke 比直接调用慢，还有装箱。热点路径应缓存 Method / Field，或改用 MethodHandle、生成字节码。
  • 方法名、字段名写成字符串，重命名不会跟着改，错误到运行期才出现。
  • 可以破坏封装，调用方会依赖私有字段布局。

框架边界、插件加载、测试里集中使用即可。普通业务逻辑优先公开 API。

反射与泛型擦除

泛型参数在字节码里大多被擦掉，ArrayList<String> 的 add 在运行期仍接受 Object。因此可以用反射绕过编译期限制，这不表示这样做是安全的。

之后若某段代码按 String 取出元素，会在那里 ClassCastException。需要参数化类型本身时，读 getGenericSuperclass() / getGenericReturnType() 得到的 ParameterizedType，而不是只看 getClass()。

常见坑

  1. 把 Class 对象说成放在「堆内存的方法区」。Java 8 以后元数据在元空间。
  2. getMethod 找不到父类的私有方法，或 getDeclaredMethod 找不到继承来的公有方法，两者用反。
  3. 忽略 InvocationTargetException 的 cause，日志里只有反射外壳。
  4. 每次调用都 getMethod 再 invoke，不做缓存。
  5. Class.forName 意外执行了静态块里的注册逻辑。

小结

Class 描述已加载的类型，三种取得方式在同一加载器下是同一个对象。创建用构造器的 newInstance，读写用 Field 和 Method，私有成员才考虑 setAccessible。反射灵活，也慢、也容易在重构时断掉，并且受模块封装约束。
