Java 休眠

2024-01-31
  • Java
本文总阅读量次

诉不尽的前尘往事,忘不掉的浮生三千。

sleep 暂停的是当前线程

Thread.sleep 让当前线程进入限时等待（TIMED_WAITING），把 CPU 让给别的线程。它不是让整个 JVM 停住，其他线程照常运行。

休眠期间不释放已持有的监视器锁。别人若在等这把锁，你睡得越久，他们等得越久。需要等待并放开锁时，用 Object.wait（必须在同步块里）或 Condition.await。

参数是毫秒，Thread.sleep(3000) 大约 3 秒。Java 5 起还有 Thread.sleep(long millis, int nanos)。更易读的写法是 TimeUnit.SECONDS.sleep(3)，它最终仍调用 Thread.sleep，并处理中断。

时间不是越长越好。sleep 的 long 上限是 Long.MAX_VALUE 毫秒，这不表示适合拿来做「睡到进程结束」。调度也不保证刚好醒来：它只保证尽量不少于这段时间，实际会偏长。

可能的输出差大约 3 秒，例如 10:20:30 和 10:20:33。多出来的几毫秒到几十毫秒都正常。

中断

sleep 抛出受检异常 InterruptedException。这表示有人要求这个线程停止等待。正确做法是恢复中断标记，或把异常继续抛出，让上层决定。

捕获后只打印 "Got an exception!" 再往下跑，会把中断吞掉，线程池和关闭逻辑就看不到这次取消请求。也不要写成 catch (Exception)，那会把别的故障一起掩盖。

interrupt() 不会把正在运行的普通代码打断，它只是设标记。线程若正阻塞在 sleep / wait / 可中断的 join 上，会以 InterruptedException 醒来，并清除中断标记，所以捕获后要再次 interrupt()。

测量实际睡了多久

墙钟 System.currentTimeMillis() 和 new Date() 会被校时拨动，不适合做间隔测量。间隔用 System.nanoTime()，它只保证同一 JVM 里两次差值有意义，不能当成当前日期。

一次 3 秒的休眠打印出 3019 这类略大于 3000 的数是正常的。不要写成 sleep(5 * 60 * 10) 又在注释里说成 5 分钟：那是 3000 毫秒，也就是 3 秒。5 分钟应是 TimeUnit.MINUTES.sleep(5) 或 sleep(5 * 60 * 1000L)。

和其他等待方式

方式 是否释放锁 典型用途
Thread.sleep 否 当前线程单纯等一段时间
Object.wait 释放进入 wait 时持有的那把监视器 等条件，需 notify
LockSupport.parkNanos 不涉及 synchronized 锁 并发库底层的挂起
Thread.yield 否 暗示调度器可以换人，可能立刻又跑回来
ScheduledExecutorService 否（任务本身不占调用方的锁） 延迟或周期任务，不要占用业务线程硬睡

sleep(0) 不是精确的「让出 CPU」，和 yield 也不等价。循环里 sleep 做轮询会既慢又耗调度，条件等待应使用 wait / Condition / 阻塞队列。

对象的 wait 必须在持有该对象锁时调用，否则 IllegalMonitorStateException。sleep 没有这个要求。wait 醒来后要在 while 里重新检查条件，不能只 if 一次，因为存在虚假唤醒，也可能通知时条件又变了。

不要用休眠做周期任务

固定间隔的工作应交给调度器，而不是在业务线程里写死循环加 sleep。sleep 的误差会累加，线程被中断后循环还要自己处理。

scheduleAtFixedRate 按计划触发。任务若超过间隔，下一次会延后，且同一次任务不会和自己重叠执行。任务抛出异常会导致后续周期被取消，所以异常要在任务内部处理。进程退出前调用 scheduler.shutdown()。

join 是等另一个线程结束，可以带超时 join(millis)。它也不释放调用方已经持有的锁，和 sleep 一样只阻塞当前线程。

常见坑

  1. 在 synchronized 方法里 sleep，锁一直不放。
  2. 吞掉 InterruptedException。
  3. 用 currentTimeMillis 的差值当基准测试结果，中途校时会导致负数或突然变大。
  4. 以为 sleep 能控制另一个线程。它只能让调用它的那一个线程等待。要停止别人，用中断或协作标记（volatile boolean），由那个线程自己结束循环。
  5. 用休眠掩盖竞态：测试里 sleep(100) 偶发通过，负载一高就失败。测试应等待条件达成，而不是猜一个时间。

小结

Thread.sleep / TimeUnit.sleep 只让当前线程等待，不释放锁，时间到了也不保证分毫不差。捕获中断后要恢复标记或继续抛出。量间隔用 nanoTime。需要放开锁等别人通知时用 wait 或并发库，不要用长休眠占着锁。
