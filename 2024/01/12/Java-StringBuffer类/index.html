可变字符序列

String 不能改。需要反复追加、插入、删除时，用 StringBuilder 或 StringBuffer。二者都实现 CharSequence，API 几乎相同，改的是自己内部的 char[]（容量不够时会换一块更大的数组），而不是每次都 new 一个不可变 String。

toString() 仍会复制出一份新的 String。说「完全不产生新对象」不准确：不产生的是中间 String，数组扩容和最终 toString 还是要分配。

StringBuilder StringBuffer
引入 Java 5 JDK 1.0
线程安全 否 是，方法用 synchronized
速度 单线程更快 每次调用都争用同一把锁
继承关系 都继承同一个包内可见的抽象父类，二者不是父子 同左

单线程（包括方法里的局部变量）用 StringBuilder。多个线程真的共用同一个缓冲区时才用 StringBuffer。多数业务方法里缓冲区是局部变量，不会被共享，所以默认 StringBuilder。不要再为了「保险」一律 StringBuffer。

追加、插入、删除

默认容量 16。可以在构造器里给出预估长度，减少扩容。length() 是当前字符数，capacity() 是内部数组能装多少，二者不同。

insert 有多个重载：insert(int offset, String str)、insert(int offset, int i) 等。插入的是对应参数的文本形式，不是「每个重载都插入一个叫 str 的字符串」。下标从 0 开始，delete(start, end) 和 substring 一样不含 end。

append 返回 this，可以链式调用：sb.append("a").append("b")。StringBuffer 的链式调用仍然是同一把锁一次次加上再放开，不是整条链持有同一把锁不放。

常用方法

方法 作用
append(...) 追加基本类型、字符、字符串或任意对象（走 String.valueOf）
insert(offset, ...) 在下标处插入，后面的字符后移
delete(start, end) 删除半开区间
deleteCharAt(index) 删除一个码元
replace(start, end, str) 用 str 替换这段区间，str 长度不必等于区间
reverse() 反转码元顺序
charAt / setCharAt 读取或替换一个下标
substring / subSequence 复制出一段，不修改原缓冲区
indexOf / lastIndexOf 查找子串。带 fromIndex 的重载才是从指定位置开始
setLength(n) 变短会截断；变长用 '\u0000' 填充
ensureCapacity(n) 保证容量至少为 n
toString() 复制成不可变 String

indexOf(String str) 从 0 开始找。文档若写成「从指定索引开始」，对应的是 indexOf(str, fromIndex)。

reverse() 按 char 交换，会把增补字符的代理对拆开，emoji 可能损坏。只处理 BMP 字符时没有这个问题。

和字符串拼接的关系

预估容量能避免内部数组多次复制。拼接分隔符时，最后多出来的逗号用 setLength 去掉即可，不必先拼再 substring。

StringBuffer 作为公开字段或静态变量，同步的只是单次 append。buffer.append(a); buffer.append(b); 两步之间别的线程可以插进来，结果仍可能交错。要原子地追加多段，需要在外部再加一把锁，或改用并发队列，不要以为 StringBuffer 能把业务操作绑成一个事务。

常见坑

  1. 多线程共用 StringBuilder，字符互相覆盖，且没有同步来建立可见性。
  2. 把 StringBuffer 当局部变量，白白付出同步。
  3. delete / substring 的结束下标写成「包含末尾」。
  4. 构造时容量给 10，随后追加远超 10 的文本，多次扩容。容量只是初始值，不是最大长度。
  5. 对 reverse() 的结果假设「一个 Unicode 字符一定占一个 char」。
  6. 调用 toString() 之后继续改 builder，已经返回的 String 不会跟着变；这是优点，别当成视图。

小结

要改字符序列就用 StringBuilder。StringBuffer 只在缓冲区本身被多线程共享时才有意义，而且它只保证单个方法调用的原子性。分清 length 和 capacity，区间一律是含头不含尾。最终需要字符串时再 toString()。
