Servlet 是什么

  • Servlet 是运行在 Web 容器（Tomcat、Jetty 等）里的 Java 组件，用来处理 HTTP 请求并生成响应。
  • 规范接口是 javax.servlet.Servlet（Jakarta EE 后为 jakarta.servlet）；日常更常用 **HttpServlet**。
  • 练习项目：servletDemo（Demo、Cookie、Session、Context、上传下载）。

部署要点

  1. 打成 war 或用 IDEA 的 Artifacts 部署到 Tomcat。
  2. @WebServlet 需要 Servlet 3.0+；老项目则在 web.xml 配 <servlet> / <servlet-mapping>。
  3. 访问路径 = 应用上下文 + 映射路径，例如 /servletDemo/servlet01。

生命周期（务必背熟）

阶段 方法 次数
初始化 init 1
服务 service → doGet / doPost N
销毁 destroy 1
  • 容器可能在 首次请求 或 启动时 load-on-startup 创建实例。
  • 默认单例，不要用成员变量存用户状态（并发会串数据）。

Session 原理

  1. 服务器创建 Session，生成 SessionId。
  2. 通过 Cookie（常见名 JSESSIONID）或 URL 重写带回浏览器。
  3. 下次请求带上 Id，服务器找回同一 Session。
  4. 超时未访问会失效（web.xml 的 session-timeout，单位分钟）。

Cookie

操作 API 思路
写 Cookie new Cookie(name, value) → response.addCookie
读 Cookie request.getCookies() 遍历
作用域 setPath / setDomain / setMaxAge
  • 敏感信息不要明文放 Cookie；登录态更常见 JWT 或 SessionId。

Cookie vs Session

Cookie Session
存放 浏览器 服务器内存 / Redis 等
容量 有限 相对更大
安全 易被篡改，需谨慎 Id 泄露仍有风险，需 HTTPS + 过期策略

上传思路

  • 表单 enctype="multipart/form-data"。
  • Servlet 3.0+ 可用 @MultipartConfig + request.getPart("file")。

ServletContext

  • 整个 Web 应用一份，可存全局参数、读真实路径 getRealPath。
  • 不要往里面塞大量用户级数据。

过滤器 / 监听器

  • Filter：统一编码、登录校验、日志（Spring 的 Filter / 拦截器同源思想）。
  • Listener：HttpSessionListener、ServletContextListener 做启动初始化。

与 Spring MVC 的关系

  • 学完本篇再看 @GetMapping，只是「映射与参数绑定」被框架接管了。

小结

  • Servlet 是 Java Web 的地基：生命周期、请求响应、会话、线程模型。
  • Cookie、Session、上传下载跑通后，再进 Spring MVC 会轻松很多。
