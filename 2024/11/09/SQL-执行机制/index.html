SQL 执行机制

2024-11-09
  • SQL
本文总阅读量次

流云千丈堪醉卧，是谁月下独酌。浮生谁能一笑过，明灭楼台上灯火。

一条查询在逻辑上的顺序

  • 写出的顺序是 SELECT ... FROM ... WHERE ... GROUP BY ... HAVING ... ORDER BY ... LIMIT。处理时的逻辑顺序不同，所以 SELECT 里的别名不能给 WHERE 用，却常常能给 ORDER BY 用。
  1. FROM（含 JOIN 与 ON）：得到输入行。
  2. WHERE：丢掉不满足条件的行。这里还没有分组，不能用聚合函数。
  3. GROUP BY：按键分组。
  4. HAVING：过滤分组之后的结果，可以用聚合。
  5. SELECT：计算输出列和窗口函数。
  6. DISTINCT：对输出列去重。
  7. ORDER BY：排序。
  8. LIMIT / OFFSET：截取。
  • 优化器可以改写物理顺序（先用索引过滤、再嵌套循环或哈希连接），只要结果符合上面的语义。老资料里「FROM 从右往左、WHERE 把选择性高的条件写在最右边、大表放最后」来自早期规则优化器的习惯，现在的 MySQL、PostgreSQL、Oracle 按代价选计划，谓词顺序和表的书写顺序不是执行顺序。

例子

  • 除会计专业外，各专业的最小年龄，只要这个最小值大于 18，再按最小年龄升序。HAVING 里的年龄是分组之后的最小值，写进 WHERE 会在分组前就删掉年龄不到 18 的学生，语义变成「先去掉未成年人再求最小」，和原意不同。
  • WHERE 里写 MIN(age) > 18 属于语法或语义错误。GROUP BY 的列要出现在选择列表里，或被聚合，否则在 ONLY_FULL_GROUP_BY 下会被拒绝。

看计划，再谈改写

  • 关注 type、key、rows、Extra。Using filesort、Using temporary 说明要额外排序或临时表，是否成问题以数据量和响应时间为准。
  • 对列套函数（WHERE YEAR(birth) = 1998）常常用不上 birth 上的索引。改成范围：birth >= '1998-01-01' AND birth < '1999-01-01'。
  • SELECT * 让优化器必须回到表里取所有列，覆盖索引就用不上。列出需要的列。
  • UNION 会去重并排序，UNION ALL 保留重复。两段结果本来就不会重叠时用 ALL。

连接与半连接

  • 多表连接把条件写全，并给列加上表别名，避免同名列含糊。
  • NOT IN (子查询) 在子查询结果含 NULL 时，整个条件会变成未知，外层一行都留不下。不确定有没有 NULL 时，用 NOT EXISTS 或 LEFT JOIN ... WHERE 右表键 IS NULL。
  • IN 与 EXISTS 谁更快由两侧行数、索引和优化器决定。MySQL 经常把两者改写成同一种半连接，没有「子查询表大就一定用 EXISTS」这条固定规则。先看 EXPLAIN。
  • 判断是否存在用 EXISTS 或 LIMIT 1，不要 SELECT COUNT(*) 再和 0 比较。计数会把匹配行都数完。

常见坑

  • WHERE 别名无效：SELECT age + 1 AS next_age 之后，过滤要重复表达式，或包一层子查询。
  • 在 JOIN 的 ON 和 WHERE 之间搬条件：内连接下两者常等价；外连接时，写到 WHERE 的右表条件会在连接之后过滤，右表没配上的 NULL 行会被丢掉，外连接变成内连接。
  • 给 ORDER BY 的列建索引，才能避免大结果集的额外排序。索引顺序要和排序方向、前面的等值条件一致。
  • 复杂语句拆成临时表之前，先确认是逻辑太绕还是缺索引。多一次临时表就是多一次写入。

EXPLAIN 上先看这几列

列 含义
type 访问方式。const、ref、range 通常用了索引，ALL 是全表扫描
key 实际选用的索引。为空就是没走索引
rows 优化器估计要检查的行数，不是精确结果行数
Extra Using index 表示覆盖索引；Using filesort 表示还要另做排序
  • major_id 等值、再按 id 排序时，索引 (major_id, id) 可以同时完成过滤和顺序。只有 id 上的索引，过滤专业仍要回表检查很多行。
  • 估计行数和真实差很远时，先 ANALYZE TABLE 更新统计信息，再看计划有没有变。不要按「把大表写在 FROM 最后」去调整语句。

子句写不出别名的位置

  • ORDER BY next_age 可以用选择列表里的别名，WHERE 不行，所以过滤条件把 age + 1 再写一遍。包一层派生表之后，外层才能把 next_age 当普通列来过滤。
  • GROUP BY 在 MySQL 里有时接受别名，别的数据库不接受。要移植的语句里，分组键写原始列。
