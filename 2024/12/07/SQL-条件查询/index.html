WHERE 留下满足条件的行

  • 比较运算符：=、<>（或 !=）、<、>、<=、>=。字符串按排序规则比，数值按数值比，不要让列上的函数破坏索引。
  • 与 NULL 比较要用 IS NULL、IS NOT NULL。WHERE address = NULL 的结果不是真，这行不会出现。

AND 与 OR

  • AND 的优先级高于 OR。sex = '女' OR age < 20 AND major_id = 208 实际是「女生，或者（年龄小于 20 且专业为 208）」。要「（女生或小于 20）且专业为 208」时加上括号。

排序

  • ORDER BY age DESC 降序，ASC 升序，省略时为升序。DESC 来自 descending。
  • MySQL 里 NULL 视为最小：升序时 NULL 在前，降序时 NULL 在后。别的数据库可以用 NULLS FIRST / NULLS LAST，MySQL 用表达式把空值拨到一侧，例如 ORDER BY (age IS NULL), age。
  • 没有 ORDER BY 时，行顺序不保证稳定，分页会重行、漏行。

LIKE

  • % 匹配任意长度（含空），_ 匹配一个字符。
模式 匹配
'Mc%' 以 Mc 开头
'%inger' 以 inger 结尾
'%en%' 任意位置含 en
'_heryl' 共 6 个字符，且后 5 个是 heryl
  • 前导 % 用不上普通 B-Tree 索引。要搜任意位置的词，考虑全文索引。
  • 字面量里的 %、_ 用 ESCAPE：LIKE '%\_%' ESCAPE '\' 查找含下划线的文本。
  • 是否区分大小写由排序规则决定。utf8mb4_general_ci 一类的 _ci 不区分大小写。

IN 与 BETWEEN

  • IN 是一组等值。列表里的 NULL 不会帮你匹配「值是 NULL」的行。
  • BETWEEN 19 AND 22 含两端，等价于 age >= 19 AND age <= 22。下界写成比上界大的数时，条件恒假。日期也含两端，BETWEEN '2021-07-01' AND '2021-07-31' 若列带时间，会漏掉 7 月 31 日零点之后的时刻。更稳的是 >= '2021-07-01' AND < '2021-08-01'。

限制行数

  • LIMIT 在排序之后截取。只要前几名时必须带 ORDER BY，否则「前 5 条」没有定义。深分页见《SQL-分页》。

常见坑

  • WHERE age = '22' 会发生类型转换，可能让 age 上的索引仍可用（字符串转成数字），反过来 WHERE name = 22 会把每一行的 name 转成数字，索引失效，转换失败的行变成 0。类型和列保持一致。
  • NOT IN ('小强', NULL) 的结果往往是空。排除列表改用 NOT EXISTS，或保证列表里没有 NULL。
  • 条件下推：写在外层的条件若依赖内层别名，要确认是在过滤原始行，还是在过滤聚合结果（HAVING）。
  • NOT 作用在它后面的整个比较上。要否定一组 AND，给括号。NOT sex = '女' 写成 sex <> '女' 更直白，也避免和 NULL 的三值逻辑缠在一起：NULL <> '女' 的结果仍是未知，这行不会留下。
