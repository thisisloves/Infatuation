窗口函数不把行折成一组

  • 聚合函数配合 GROUP BY 后，每组只剩一行。窗口函数在 OVER 划定的窗口上计算，原行都保留，结果写在每一行旁边。
  • MySQL 8.0、MariaDB 10.2 起支持。逻辑顺序上，窗口函数在 WHERE、GROUP BY、HAVING 之后计算，因此不能把窗口结果放进同一层的 WHERE。要过滤名次，包一层子查询。
  • 同一层 SELECT 里，窗口的 OVER 引用不了本层才起的别名。排序表达式重复写一遍，或放到子查询外面。
  • PARTITION BY 划分窗口，省略则整张结果是一个窗口。ORDER BY 规定窗口内的顺序，排名和按行累计都依赖它。

排名

  • ROW_NUMBER 给每一行唯一序号，并列时仍按 ORDER BY 的后续键分出先后。RANK 并列时名次相同并跳号（1、1、3）。DENSE_RANK 并列时不跳号（1、1、2）。
  • 每个学生内部按分数从高到低编号，并在每一行带上该生的平均分。平均分的窗口没有 ORDER BY，它看的是整个分区。
  • 只要每个学生的总分和名次时，先聚合再排名，避免在明细上 SUM() OVER 之后再 DISTINCT：

各科最高分、最低分、及格率

  • 「每科一行」用 GROUP BY 更直接。及格按 score >= 60 计，NULL 分数不计入及格人数。
  • 明细旁边要挂上该科最高分时才用窗口，行数与 SC 相同：
  • 用 DISTINCT 把窗口结果收成每科一行，要求选出的每一列在分区内都相同。一旦多选了 sid 这种会变的列，DISTINCT 就收不拢。分组报表优先 GROUP BY。

帧与前后行

  • 默认帧在有 ORDER BY 时往往是「从分区第一行到当前行」。累计和因此会一行比一行大。要整窗一起加总，去掉 ORDER BY，或写明帧：
  • LAG / LEAD 取同一分区里的前一行、后一行，越界时是 NULL，第二个参数可以改偏移。

和 GROUP BY 的差别

  • GROUP BY 把一组收成一行，没进分组键、也没被聚合的列不能再出现。
  • PARTITION BY 只划定计算范围，明细列原样返回。它没有「汇总功能」这一说，汇总是 SUM、COUNT 这些函数做的，窗口决定它们看哪些邻居。
  • 过滤发生在窗口计算之前。WHERE score >= 60 之后再 AVG() OVER (PARTITION BY cid)，平均的是及格分，不是全班分。

常见坑

  • ROW_NUMBER 当作名次时，同分两人会变成相邻的两个名次。成绩排名要并列时用 RANK 或 DENSE_RANK。
  • 窗口函数不能写在 WHERE 里。WHERE rn = 1 必须放在外层。
  • ORDER BY 不唯一时，ROW_NUMBER 对剩余并列行的先后没有保证。加上主键作为最后一键。
  • MySQL 8 之前没有窗口函数。旧实例上用用户变量模拟排序，变量求值顺序不稳定，升级后应改成 OVER。
