四种创建方式

线程要做的事是任务，Thread 是执行任务的载体。面试先把四种入口分开，再说明哪一种该用。

继承 Thread。 重写 run，start 才会进入调度；直接调 run 只是在当前线程里执行方法。类只能单继承，任务和线程绑死，测完即弃。

实现 Runnable。 任务与线程分离，同一个任务对象可以被提交多次。没有返回值，异常只能在 run 里自己处理。

Callable 与 Future。 Callable.call 有返回值，受检异常可以抛出去。交给线程池后得到 Future：get 阻塞到结束，get(timeout, unit) 限时，cancel(true) 发出中断。

线程池提交。 生产代码走这条。池负责复用线程、排队、拒绝过多任务。ExecutorService.submit(Runnable) 或 submit(Callable) 返回 Future。

Executors 的工厂方法适合演示。队列长度、拒绝策略要自己控制时，用 ThreadPoolExecutor，参数在并发那一篇展开。

六种状态

Thread.getState() 只有这六种，名字以源码枚举为准。操作系统里的运行、就绪，在 Java 里都叫 RUNNABLE。

状态 何时进入
NEW new Thread 之后、start 之前
RUNNABLE 正在跑，或已经在等 CPU
BLOCKED 等 synchronized 的监视器，还没拿到
WAITING Object.wait()、join()、LockSupport.park()，没有期限
TIMED_WAITING sleep、wait(timeout)、join(timeout)、parkNanos
TERMINATED run 结束。同一个 Thread 不能再次 start

等 ReentrantLock 时线程停在 AQS 的队列里，状态一般是 WAITING 或 TIMED_WAITING，不是 BLOCKED。BLOCKED 专指监视器锁。看线程转储时这两类不要当成同一种锁。

sleep 与 wait

两者都会让出 CPU，差别在锁和谁来唤醒。

sleep wait
所属 Thread 的静态方法 Object 的实例方法
锁 不释放持有的监视器 必须先拿到该对象的监视器，调用后释放，返回前重新竞争
醒来 时间到，或被中断 notify / notifyAll、中断、或超时
状态 TIMED_WAITING 无限期是 WAITING，带超时是 TIMED_WAITING

wait 放在 while 里检查条件，不要放在 if 里。notify 不指定唤醒谁，可能唤醒一个条件并不满足的线程；被唤醒后也可能被别人再次改掉条件，这叫虚假唤醒。循环回去再判一次才安全。

sleep(0) 只是让出当前时间片的一次机会，不保证其它线程一定跑到。需要「等到某个条件」时用 wait / notify 或 java.util.concurrent 的工具，不要用循环 sleep 去猜。

join

t.join() 是当前线程等待 t 结束，内部是在 t 这个对象上 wait，t 结束时由 JVM 做 notifyAll。因此 join 会受中断影响，也会出现 TIMED_WAITING（带超时）或 WAITING。

它不传递 t 的返回值，Runnable 任务的结果要用共享变量或改成 Future。多个子任务都要等完，可以对每个线程 join，也可以用 CountDownLatch，后者在线程池里更常见，因为池里的线程不该被业务代码 join 掉。

interrupt 是协作

interrupt() 不是把线程杀掉。它只做两件事里的一件：

  • 线程正阻塞在 sleep、wait、join、可中断的 lockInterruptibly 上：清除中断标记，抛 InterruptedException。
  • 否则：把该线程的中断标记置为 true，线程自己决定何时收工。

isInterrupted() 只查询。Thread.interrupted() 查询并清除标记，静态方法，作用对象是当前线程。捕获 InterruptedException 之后标记已经是 false；如果这个方法自己处理不了，应该再次 interrupt() 把标记设回去，让上层看到。吞掉异常又不恢复标记，取消信号就丢了。

Future.cancel(true) 对正在跑的任务也是发中断，任务不看标记的话取消不会生效。

不要用 stop

Thread.stop() 早已废弃。旧实现会在任意字节码边界抛 ThreadDeath，并立刻释放该线程持有的全部监视器。写到一半的对象会暴露给其他线程，数据已经坏了，锁却没了。较新的 JDK 里这个方法直接抛 UnsupportedOperationException。

suspend / resume 同样废弃：线程在持有锁时被挂起，恢复它的线程如果还要这把锁，就死锁。

正确的停法是协作：用中断标记，或用一个 volatile boolean 让循环自己退出，进入 TERMINATED。标记只能保证「对方会看见」，看见之后的收尾代码仍要自己写。为什么一个普通布尔在别的线程里可能永远看不见，是可见性的问题，下一篇用 volatile 和锁来讲。
