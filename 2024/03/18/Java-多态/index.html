多态

多态：同一段按父类型编写的调用，运行时落到不同子类的实现上。调用方依赖 Shape，不必为 Circle、Square 各写一套流程。

它减弱的是「调用方对具体类的依赖」，不是把父子之间的耦合消掉。子类仍然依赖父类的契约。

运行时多态的条件

要观察到「同一句调用、不同行为」，需要三件事：

  1. 有继承或接口实现。
  2. 子类重写了实例方法（接口则是实现该方法）。
  3. 父类型引用指向子类对象：Shape s = new Circle();

缺第 2 条时，语句仍合法，但行为与父类一致，看不出差异。缺第 3 条、直接 Circle c = new Circle() 时，只是普通调用，编译器已经知道具体类型。

重载（同名不同参数）在编译期就选定了，叫编译期多态也可以，但它不靠对象的运行时类型。下文的「多态」指重写带来的动态分派。

一个完整例子

只用子类变量调用 draw()，演示不了多态。关键是父类引用上的调用。

paint 只认识 Shape。以后增加 Triangle，只要重写 draw() 并传入，paint 不用改。这就是可扩展性。若 Shape.draw() 没有子类版本，三种调用都会打印「形状」。

接口同样成立：List<String> list = new ArrayList<>();，list.add 执行的是 ArrayList 的实现。抽象类把「必须重写」写成抽象方法，效果同类。

哪些成员有多态

成员 看编译期类型还是运行期类型
实例方法 运行期，走重写后的版本
字段 编译期，子类字段只是隐藏
静态方法 编译期，子类静态方法只是隐藏
final 实例方法 不能重写，没有多态
private 方法 不能重写，没有多态

Parent p = new Child(); 时，p.hello() 打印 child，p.name 是 "parent"，p.ping() 打印 P。字段和静态方法不要当成重写。

好处与边界

  • 可替换：凡是要 Shape 的地方，可以给任意合规子类。
  • 可扩展：新子类实现约定即可，旧调用代码不动。
  • 简化调用方：分支从一串 instanceof 收拢到各自的方法里。

这些好处依赖子类遵守父类契约（前置条件不更严、后置条件不更弱）。子类若把 draw() 改成抛异常或什么都不画，调用方的假设会被打破。

多态也不意味着能调用子类新增方法。Shape s = new Circle(); s.radius(); 编译失败，因为 Shape 没有 radius。需要时先判断再向下转型，或把操作提升到父类型里。

常见坑

  1. 重载被当成重写：参数列表不同，@Override 会直接报错，应利用这个注解。
  2. 构造器里调用可重写方法，子类尚未完成字段初始化就进入重写版本。
  3. 用静态方法模拟多态，调用哪一个只看引用类型。
  4. 父类方法是 final 或 private，子类写同名方法也不会被动态分派。
  5. 为了「以后可能扩展」预造很深的继承树，多数情况下一个接口加若干实现更清晰。

小结

多态的运行时形态是：父类型引用、子类对象、被重写的实例方法。调用方针对父类型编程，具体行为由对象的真实类决定。字段、静态方法、final / private 方法都不参与这套分派。
