Java 泛型

2024-07-09
  • Java
本文总阅读量次

蓝桉已遇释槐鸟，不爱万物唯爱你，释怀来去无归期，梦回已逐浮云散，我愿为蓝桉。

为什么需要泛型

没有泛型时，集合里什么都能放，取出来只能当 Object，再强制转换。放错类型要等到某次强转才 ClassCastException。

  • 编译期检查：List<String> 里 add(1) 直接编译失败。
  • 省掉转换：list.get(0) 的静态类型就是 String。

泛型在编译后擦除，JVM 看到的主要是原始类型，再加上编译器插入的检查转换和桥接方法。它不让 List<String> 和 List<Integer> 变成两套运行期类。

泛型类与泛型方法

类型参数写在类名后面。约定：T 表示类型，E 表示元素，K / V 表示键值，N 表示数字。

接口同样：interface Comparable<T> { int compareTo(T other); }。

方法可以有自己的类型参数，写在返回类型之前，和类上的 T 不是一回事。

调用时通常能从实参推断出 T，不必写成 Box.<String>first(...)。

有界类型

<T extends Number> 表示 T 必须是 Number 或其子类，方法里就能调用 intValue()。上界可以是类加若干接口，类最多一个且放在最前：<T extends Number & Comparable<T>>。

这里的 extends 也适用于 T 实现某接口，泛型边界不写 implements。

多个上界让你同时使用几组方法，但 T 仍然是某一个具体类型，不是「Number 或 Comparable 二选一」。

通配符

  • ?：某种未知类型。
  • ? extends T：T 或 T 的子类型。适合从这个结构里读，读出来当 T。不能随便 add 具体元素（除了 null），因为编译器不知道实际是 List<Integer> 还是 List<Double>。
  • ? super T：T 或 T 的父类型。适合向里面写 T。读出来只能当 Object，除非你自己再转。

记忆：PECS，Producer Extends，Consumer Super。

List<Integer> 不是 List<Number> 的子类型，这叫泛型不变。允许协变的是通配符，不是裸的 List<子类> 赋值。

类型擦除

编译后，T 多半变成上界或 Object。因此：

  • 不能 new T()，也不能 new T[]，没有 T.class。需要构造时传入 Class<T> 或 Supplier<T>。
  • 静态成员属于类，不能引用类上的类型参数。静态方法要自己声明 <T>。
  • instanceof 不能写 o instanceof List<String>，只能 o instanceof List<?> 这种与参数无关的形式。
  • 不能声明两个擦除后签名相同的方法，例如 void m(List<String>) 和 void m(List<Integer>)。

擦除是为了和 Java 5 之前的字节码兼容。运行期要保留完整参数类型（例如 JSON 反序列化 List<User>）时，用匿名子类把泛型写进父类签名，再通过 getGenericSuperclass() 读 ParameterizedType，库里常见的 TypeReference 就是这个技巧。

原始类型

List list = new ArrayList(); 是原始类型，为兼容旧代码才留下来。它关掉大部分泛型检查，把 List<String> 赋给原始 List 再塞进整数，是堆污染，取出来会在强转处爆炸。新代码不要省略类型参数；完全不关心元素类型时写 List<?>，而不是原始类型。

可变参数若是泛型数组（List<String>...），调用处可能出现 heap pollution 警告。确认方法不会依赖这个数组的运行期组件类型时，用 @SafeVarargs，并且方法应是 static 或 final（Java 9 起也可以是 private 实例方法）。

不能创建带具体参数的数组：new List<String>[10] 非法。需要一组列表时用 List<List<String>>。

实践对照

场景 写法
元素类型固定 List<String>、Box<Integer>
方法自己的类型 <T> T first(List<T> list)
只读、元素是 T 的子类 List<? extends T>
写入 T List<? super T>
要 new 或要 Class 传入 Class<T>、Supplier<T>
运行期保留参数 ParameterizedType、TypeReference

常见坑

  1. Box<Integer> 不能赋给 Box<Number>。
  2. 在 List<? extends Number> 上 add(Integer.valueOf(1))。
  3. 静态字段写成 private static T cache;。
  4. 用原始类型接收泛型集合，警告被忽略。
  5. 以为擦除之后强转一定安全。反射或原始类型都能把别的对象塞进去。

小结

泛型把类型错误提前到编译期，运行期则擦成上界。读用 extends，写用 super，不要用原始类型。要在运行期知道 List<String> 里的 String，得另走反射里的泛型签名，不能指望擦除后的 Class。
