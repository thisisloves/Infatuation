Java 转型

2024-07-28
  • Java
本文总阅读量次

花开两生面，人生佛魔间。

转型在转什么

父子类型之间转的是引用的视角，不是新造一个对象，也不是把对象从一种类变成另一种类。new 的时候对象的真实类已经确定，转型只决定编译器允许你通过这个变量看见哪些成员。

数值上的「小类型转大类型」不能照搬过来。子类引用并不是「范围更小的父类对象」。子类对象通常比父类多出字段和方法。

向上转型 向下转型
写法 Father f = new Son(); Son s = (Son) f;
是否自动 是 否，必须写强转
是否 new 否 否
失败时机 编译期就能挡住不兼容类型 运行期类型不符则 ClassCastException

向上转型

把子类对象的引用交给父类型变量，编译器自动完成。

通过父类引用：

  1. 编译器只允许访问父类里声明过的成员，子类新增的方法暂时「看不见」，对象本身并没有丢掉这些方法。
  2. 调用实例方法时，若子类重写过，执行子类版本，不是父类原方法体。
  3. 若子类没重写，执行的就是父类方法。说「不会是父类原有的方法」太绝对。
  4. 字段和静态方法不多态，看引用的声明类型。
  5. 之后还可以再向下转回真实的子类类型。

A a = new B(); 之后堆上只有一个 B。不存在第二个被「实例化出来的父类对象」。

向下转型

向下转型是把父类型引用强转成子类型。对象必须本来就是目标类型或其子类，否则运行期抛 ClassCastException。

A a = new A(); B b = (B) a; 会失败。不是因为「没有先向上转型」这句口诀，而是这个对象的真实类是 A，它不是 B。先向上再向下，只是为了让引用的静态类型变成父类；真正的条件是运行期类型。

不确定时先判断：

Java 16 起可以写成模式匹配：if (a instanceof B b) { b.print2(); }，作用域里可以直接用 b。

父类引用为 null 时，instanceof 为 false，强转结果仍是 null，不会立刻抛 ClassCastException，后面用它调用方法才会空指针。

向下转型不会复制对象，a 和 b 仍指向同一实例，改字段双方都看得见。

常见坑

  1. 把向下转型理解成「用父类对象实例化子类」。父类对象变不成子类，缺的字段无从产生。
  2. 注释写成「a.print() 调用 A 的 print」，重写后实际执行的是 B。
  3. 连续强转绕过编译器：(B) (A) new C()，只要 C 不是 B 的子类，运行期一样失败。
  4. 用转型代替多态，调用方堆满 instanceof。能放进父类方法里的行为就不要转回去。
  5. 接口转型同样适用：Runnable r = task; if (r instanceof AutoCloseable c) c.close(); 只有真实类实现了该接口才成功。

小结

向上转型安全、自动，换一个更抽象的视角，实例方法仍走子类重写。向下转型要你保证对象本来就是那种子类，它不创建对象。拿不准就用 instanceof，能用多态表达的分支就不要向下转。
