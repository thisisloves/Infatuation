SQL 去重

2024-10-02
  • SQL
本文总阅读量次

东风夜放花千树，更吹落、星如雨。宝马雕车香满路。凤箫声动，玉壶光转，一夜鱼龙舞。

DISTINCT 作用在整行投影上

  • SELECT 默认就是 SELECT ALL，重复行都保留。DISTINCT 写在字段列表最前面，对后面所有选出的列一起去重，留下唯一的组合。
  • 它是 SELECT 的修饰，可以出现在 INSERT ... SELECT DISTINCT 里。UPDATE、DELETE 没有这个子句；要按唯一键改或删，用子查询圈出要动的行。
  • 只写 name 时，同名不同年份合成一行，年份信息被丢掉。两个列都写出时，去重的是 (name, year) 这一对，同名不同年会各留一行。
  • NULL 在 DISTINCT 里彼此相等，多行 name 为 NULL 只会留下一行。这和 WHERE name = NULL 对不上：比较里 NULL = NULL 的结果是未知。

和 GROUP BY 的分工

  • 只为去掉重复组合时，DISTINCT 和 GROUP BY 那些列往往得到同一结果。还要计数、求和时用 GROUP BY，聚合函数才有分组可算。
  • SELECT DISTINCT name, COUNT(*) 这种写法把聚合和未分组的列混在一起，在开启 ONLY_FULL_GROUP_BY 的 MySQL 里会报错。先决定是「唯一组合」还是「每组统计」。

计数时去重

  • COUNT(DISTINCT name) 统计不同名字的个数，NULL 不计入。COUNT(*) 统计行数，不去重。COUNT(name) 统计名字非空的行数，同名算多行。

留下整行里的一条

  • DISTINCT 只保证选出的那些列唯一。要按人名留一条完整记录（带工资、部门），需要规定留哪一条。窗口函数给每组编号，再滤出编号 1（MySQL 8.0+）：
  • ORDER BY 决定留下的是最新一年还是最小 id。没有排序时，留哪一行没有保证。
  • 没有窗口函数时，可以用 GROUP BY name 得到要留的 MAX(id)，再把这个结果联回原表取出整行。

常见坑

  • SELECT DISTINCT * 要求整行每一列都相同才合并。有一列是自增主键时，结果和没写 DISTINCT 一样。
  • UNION 会在两段结果之间去重，UNION ALL 保留重复。只是上下拼接时用 ALL，省掉一次去重排序。
  • 对大表 DISTINCT 常常要临时表或排序。能用主键、唯一索引把重复挡在写入时，就不要每次查询再去重。
  • DISTINCT 写在单个列前面（SELECT name, DISTINCT year）是语法错误。它只能修饰整个选择列表，或放进 COUNT(DISTINCT ...) 这类聚合里。

删掉重复行，留下一条

  • 这是 MySQL 的自连接删除：同一人同一年里，id 更大的行被删掉，最小 id 留下。执行前先把 DELETE 换成 SELECT s.id 看将要删的名单。
  • 没有事务保护的引擎上，删到一半失败就收不回。InnoDB 里包进事务，核对行数再 COMMIT。
  • 唯一索引 UNIQUE (name, year) 让以后的插入直接失败，比每次查询 DISTINCT、每次清理重复行便宜。已有重复数据时，先清再加索引，否则建索引会因重复值失败。

排序规则也算「相同」

  • 不区分大小写的排序规则下，DISTINCT name 会把 Ann 和 ann 收成一行，留下哪一种写法没有保证。
  • 要按字节区分，把列的排序规则改成 _bin，或在查询里写 DISTINCT BINARY name（MySQL）。展示用的大小写和去重用的键最好分成两列。
  • 这张名单是「哪些键重复了、重复几行」。DISTINCT 只告诉你去重后还剩什么，不告诉你丢掉了几行。清理之前先跑这段，确认重复是数据错误而不是同名的两个人。
