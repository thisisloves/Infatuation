增删改查对应四条语句

  • INSERT 插入，DELETE 删除行，UPDATE 改列，SELECT 查询。查询不锁死数据怎么改；前三条是 DML，在 InnoDB 的事务里可以回滚。
  • 建表、删表是 DDL，和这四条分开。下面的学生表与本系列其它篇共用 student_info_table 这个名字。

建表与查看列

  • NOT NULL 三个字母都要大写习惯即可，写成 NOt 也能过解析，但容易看成别的单词。INT 不要靠括号里的显示宽度限制取值。
  • 看列：

查

  • 列出要用的列。SELECT * 在对表、导出时省事，业务代码会在别人加列之后悄悄改变结果形状。
  • like 在 MySQL 里是保留字。列若叫这个名字，写 `like`。

增

  • 列清单和值的个数、顺序一一对应。自增主键可以不写 id，让引擎分配，避免和已有主键冲突。
  • 一次插入多行时，每个括号是一行，类型仍然按列对齐。某列违反唯一索引，默认整条语句回滚，不会只跳过那一行。

改

  • 没有 WHERE 的 UPDATE 会改全表。 先用同一条件 SELECT 出将要改的行，再执行更新。
  • SET id = 7 WHERE like = '温柔' 可能命中多行，第二行起会因主键重复失败，事务里这条语句之前的修改也会一起考虑回滚。用主键或唯一键圈定一行。

删

  • 同样，没有 WHERE 会删光整张表的行，表还在，自增值不一定回到起点。
  • 三种「清空」：
语句 结果
DELETE FROM t 逐行删除，可在事务中回滚，WHERE 可选
TRUNCATE TABLE t 清空并重置自增，DDL，不能按行回滚
DROP TABLE t 表定义一并删除

常见坑

  • 字符串日期写成 1998-4-1 多数时候能转换，比较和索引更稳的是 1998-04-01。非法日期在严格 SQL 模式下会直接报错。
  • DELETE / UPDATE 联表时别名要写对：UPDATE t SET ... 与 UPDATE student_info_table AS t SET t.address = ...。条件漏写表别名可能改到另一张表。
  • 影响行数为 0 不一定是失败：WHERE 没有命中，语句仍然成功。应用要看受影响行数，而不是只看有没有异常。
  • 大表上无索引的 WHERE name = ... 会锁住扫描过程中碰到的更多行（隔离级别和执行计划不同，范围不同）。更新条件走主键或唯一索引。
