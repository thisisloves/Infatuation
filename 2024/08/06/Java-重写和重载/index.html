Java 重写和重载

2024-08-06
  • Java
本文总阅读量次

树红苞浑烂漫，风轻日暧竞芳华。

重写

重写（override）是子类用自己的实例方法替换父类中签名相同的方法。参数类型必须相同。返回类型可以相同，也可以是父类返回类型的子类，这叫协变返回类型，自 Java 5 起合法。Java 5 之前返回类型必须完全相同，不是到 Java 7 才放开。

「外壳不变、核心重写」里的外壳指方法签名。返回类型允许协变，所以不能写成「返回值也不能变」。

父类方法若是 static，子类再写同名方法只是隐藏，不是重写。dog.eat() 若解析到静态方法，写不写 @Override 都会报错。参数列表不同也不是重写，那是重载，@Override 同样会失败。

重写规则

  1. 参数列表（类型、个数、顺序）必须相同，参数名可以不同。
  2. 返回类型相同，或是被重写方法返回类型的子类型（Java 5+）。
  3. 访问权限不能更严。public 不能改成 protected，包级可以改成 protected 或 public。
  4. 只有子类能重写父类的实例方法。跨包时，只能重写 public 和 protected，看不到父类的包级方法。
  5. final 方法不能重写。private 方法对子类不可见，子类同名方法是新方法，加 @Override 会编译失败。
  6. static 方法不能重写，只能隐藏。
  7. 不能抛出比父方法更多、更宽的受检异常；可以抛更少、更窄的受检异常，也可以随意抛非受检异常。
  8. 构造器不能重写。父类若是 final，或方法所在类根本没被继承，就无从重写。

同包时子类可以重写除 private、final、static 以外的可见实例方法，不是「除 private 和 final 之外的所有方法」。

重载

重载（overload）是同一个类里（或父子类之间）方法名相同、参数列表不同。返回类型可以跟着不同，但不能只有返回类型不同。

每个重载都要有独一无二的参数类型列表。构造器重载很常见：无参构造器里用 this(...) 转到带参构造器。

重载规则

  1. 必须改变参数列表（个数、类型或顺序）。
  2. 可以改变返回类型、访问修饰符，但仅改返回类型无法通过编译。
  3. 可以声明新的或更宽的受检异常。重载是不同方法，不受重写那套异常限制。
  4. 发生在同一个类中，也可以是子类新增一组参数。子类方法若签名与父类完全相同，那是重写，不是重载。
  5. 绑定发生在编译期，看引用的静态类型和实参，不看对象运行期类型。

f(1) 选择 f(int)。若只有 f(long) 和 f(Integer)，传入 int 会优先做拓宽转换成 long，而不是装箱成 Integer。重载决议的顺序很容易和直觉不一致，公开 API 不要靠一堆相近重载表达不同含义。

对照

重写 重载
位置 父子类之间 多在同一个类
方法名 相同 相同
参数列表 必须相同 必须不同
返回类型 相同或协变 可不同，但不能作为唯一区别
绑定 运行期，随对象真实类型 编译期，随引用类型和实参
多态 运行时多态 不产生动态分派

重载是同一类里的多个方法，重写才是子类替换父类行为。两者都可以和多态一起出现，但只有重写会在 Parent p = new Child() 时改变被调用的方法体。

常见坑

  1. 子类方法多写了一个参数，以为自己重写了父类，实际是重载，父类引用上仍然走父类方法。
  2. 把 Java 5 的协变返回类型记成 Java 7。
  3. 重写时把 public 收成 protected，或抛出更宽的受检异常。
  4. 静态方法加 @Override。
  5. null 实参面对 f(String) 和 f(Integer) 两个重载，编译器认为引用不明确。

小结

签名相同才是重写，签名不同才是重载。重写看运行期对象，访问权限不能变严，返回类型自 Java 5 起可以协变。重载看编译期参数，不能只改返回类型。拿不准时加上 @Override。
