SQL 事务

2024-08-25
  • SQL
本文总阅读量次

取次花丛懒回顾，半缘修道半缘君。

事务是一起提交的一组语句

  • 事务把多条读写入收成一个单位：要么全部留下，要么全部撤销。单条 INSERT 在自动提交下自己就是一个事务。
  • MySQL 里只有 InnoDB 这类支持事务的引擎会遵守下面的行为。MyISAM 遇到 ROLLBACK 不会把已执行的修改改回去。

四个属性

  1. 原子性
  • 事务中的修改一起生效。中途失败时，已做的修改回到事务开始前的状态。
  1. 一致性
  • 事务结束时，数据满足库里定义的约束：主键、外键、检查以及业务上应保持的不变量。中间步骤可以暂时让应用看到「钱已扣、货未加」，这些步骤不能留在已提交的状态里。
  1. 隔离性
  • 并发事务按隔离级别决定能看见对方的哪些已提交或未提交版本，避免读到不该看见的中间状态。级别从读未提交、读已提交、可重复读到可串行化，详见《SQL-事务隔离》。
  • 引擎允许多个事务同时跑，这是并发。隔离是对这些并发读写附加的可见性规则，两者一起才有「同时跑而且结果可解释」。
  1. 持久性
  • 一旦提交成功，修改经重做日志落下，进程崩溃后重启仍能恢复。提交返回之前断电，由日志决定这笔事务算不算完成。

控制语句

语句 作用
START TRANSACTION 或 BEGIN 关闭这一段的自动提交，开始事务
COMMIT 提交，修改对后续事务可见
ROLLBACK 撤销本事务中尚未提交的修改
SAVEPOINT s 在事务内部做标记
ROLLBACK TO s 撤到标记点，事务继续，不结束
RELEASE SAVEPOINT s 丢掉标记，标记之后的修改仍在
  • BEGIN 之后若连接断开，未提交的事务回滚。连接池把连接交还之前要提交或回滚，避免下一位借用者还停在别人的事务里。

提交

  • 两条语句要么都在，要么都不在。UPDATE 用主键圈定刚插入的那一行，避免按非唯一列改到别的学生。

回滚与保存点

  • ROLLBACK 之后，本事务里的删除不会留在库中。别的事务在读已提交级别下，也看不见这次未提交的删除。
  • ROLLBACK TO s 只撤销标记之后删除 id 8 的那条，id 7 的删除还在这个未结束的事务里。同一连接上再查询，看不到 id 7；其他连接在提交之前仍看得到 id 7。
  • 必须 COMMIT，id 7 的删除才会持久化。只执行到 ROLLBACK TO 就断开连接，两行删除都会被整笔回滚。

常见坑

  • DDL（CREATE、ALTER、DROP，以及 InnoDB 的 TRUNCATE）会隐式提交。事务中间建表，前面的 DML 已经提交，后面的 ROLLBACK 收不回它们。
  • 自动提交是默认的。没有 START TRANSACTION 时，每条成功的 DML 立刻提交，随后的 ROLLBACK 没有事务可撤。
  • 提交成功后再 ROLLBACK 不会取消已提交的行。要反向修改，写补偿语句或新的事务。
  • 大事务里循环更新几十万行，回滚段和锁都会撑很久。按主键范围拆成多笔提交，每笔仍保持自己的原子性。
  • autocommit = 1 时每条成功的 DML 自己提交。脚本里需要多语句原子时显式 START TRANSACTION，结束时 COMMIT。连接归还连接池前确认没有未结束的事务。
