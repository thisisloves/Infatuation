题目:阶梯问题

2023-10-19
  • 算法
本文总阅读量次

纤云弄巧，飞星传恨，银汉迢迢暗度。

题目

楼梯有 n 级，每次可以爬 1 级或 2 级，问爬到顶端有多少种不同顺序。n 是正整数。

到第 n 级的最后一步，要么从 n - 1 爬 1 级，要么从 n - 2 爬 2 级。两条路没有重叠，所以：

于是 f(3) = 3，f(4) = 5，f(5) = 8。这是错开一位的斐波那契数列。

f(0) 不是 0。人已经站在地面、还没有台阶时，什么都不做是 1 种走法。若规定 f(0) = 0、f(1) = 1，递推会得到 f(2) = 1，把「直接跨两级」丢了。若误设 f(0) = 0，会和「一次走一级或两级」矛盾。代码里对 1 和 2 直接返回自身，f(2) 是 2，这段基线才是对的。

递归

climb(5) 会把 climb(3) 算很多次。时间约是 O(φⁿ)，φ 约 1.618。调用深度是 O(n)，n 到几千时栈会先溢出，答案还没算出来。它适合对一下 f(1) 到 f(5)，不适合做最终实现。

递推

只保留前两项。从 3 推到 n，每一步做一次加法。

n 走法 f(n)
1 1 1
2 1+1，2 2
3 1+1+1，1+2，2+1 3
4 在 3 级的每种走法后加 1，或在 2 级的每种走法后加 2 5

时间 O(n)，额外空间 O(1)。循环里的 next 必须单独保存。若写成 prev = cur; cur = prev + cur，前一句已经把 prev 盖掉，加出来的是 cur + cur。

还可以怎么改

一次能爬 1、2 或 3 级时，递推变成 f(n) = f(n - 1) + f(n - 2) + f(n - 3)，基线是 f(0) = 1，f(1) = 1，f(2) = 2。不要沿用只允许两级时的 f(2) = 2 再随便加一项，基线要按「台阶数小于最大步长」重新数。

若每级台阶还有代价，问的是最小代价而不是走法种数，递推改成取最小值：dp[i] = cost[i] + min(dp[i - 1], dp[i - 2])。种数相加和代价取最小是两道题。

n 很大而只要种数对 10⁹+7 取模时，仍用这个循环，每一步取模。矩阵快速幂可以把 O(n) 降到 O(log n)，这道题的常规数据用循环就够。

注意

  • 顺序不同算不同走法。1+2 和 2+1 都要计入 f(3)。
  • 返回值增长是指数的。n = 46 左右就会超过 32 位有符号整数，语言若会溢出，应改用大整数或按题目要求取模。
  • 记忆化递归也能变成 O(n)，但要一张长度为 n 的表，空间不如只留两个变量省。

把 f(4) 摊开

五种顺序是 1+1+1+1、1+1+2、1+2+1、2+1+1、2+2。少算 2+2 或把 1+2+1 当成和 1+1+2 相同，都会得到 4，那是组合不是排列。这道题要的是排列。

若错误地把 f(0) 设成 0，又用 f(2) = f(1) + f(0)，得到的 f(2) 是 1，后面每一项都小 1 拍。代码直接 return n 避开了这个错误，文字说明必须和代码一致。

注意

  • n = 0 若出现在调用里，按「已经在顶端」返回 1 才和斐波那契定义衔接；题目通常保证 n ≥ 1。
  • 递归不加缓存时，f(5) 会多次计算 f(3)。画一下调用树就能看见重复。
  • 结果是整数加法。在会静默溢出的语言里，先用小 n 对拍，再换大整数或取模。

基线

一次走 1 级或 2 级时，f(1)=1，f(2)=2，其后每项是前两项之和。f(0) 若取 0，再推出的 f(2) 会变成 1，把「直接走两级」丢了。递归不加缓存是指数时间。循环只保留前两项，时间 O(n)，空间 O(1)。1+2 和 2+1 是两种走法。
