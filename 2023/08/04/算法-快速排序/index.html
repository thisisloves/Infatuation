快速排序

2023-08-04
  • 算法
本文总阅读量次

两处相思同淋雪，当年一别共沧桑。

思想

快速排序用分治。选出一个基准，分区之后基准左侧都不大于它，右侧都不小于它，基准落在最终位置上。再对左右两段递归。平均时间 O(n log n)，额外空间主要是递归栈，平均 O(log n)。

它不稳定。分区时的交换会跨过相等元素。最坏情况是每次基准都偏到一端，递归深度和比较次数都变成 O(n²)，例如数组已经有序，又总拿最左或最右元素当基准。

分区

下面用 Lomuto 分区：基准取当前区间的最后一个元素，i 左边都小于基准。

[3, 1, 4, 2] 第一轮基准是 2。扫描后 1 被换到前面，基准再换到下标 1，得到 [1, 2, 4, 3]。然后分别排序 [1] 和 [4, 3]。

结束条件必须是 start >= end。区间空或者只剩一个元素就返回。写成 start > end 时，单元素区间仍会做一次无意义分区，虽然多半能停，但边界更难检查。

旧写法还有两处不该留在算法里：分区过程中打印左右指针，以及每次递归打印整段数组。那是调试输出。基准固定取左端时，对升序数组会一路退化成 O(n²)。左右指针的写法若先从右边找、再从左边找，属于 Hoare 分区，左右交错时要单独证明基准最后的位置，不能把 Lomuto 的下标直接套上去。

复杂度

项 结果
平均时间 O(n log n)
最坏时间 O(n²)，分区极度不平衡
最好时间 O(n log n)
额外空间 平均 O(log n)，最坏 O(n) 栈
稳定性 不稳定

随机选基准，或取首、中、尾三个数的中值，能明显降低「已经有序就退化」的概率。需要严格最坏 O(n log n) 时用堆排序，需要稳定时用归并排序。标准库的排序通常会混合快排、堆排序和插入排序，避免单纯快排的最坏情况。

注意

  • 分区之后基准不要再参加左右递归，否则 partition 若没把区间缩小，会无限递归。
  • 相等元素全部进一侧时，大量重复值也会退化。三路分区把小于、等于、大于分成三段，重复值多时更好。
  • 递归改成显式栈可以避免调用栈溢出，复杂度不变。小区间（例如长度小于 16）改用插入排序，能减少递归开销。

已经有序时为什么会退化

基准永远取区间末尾，输入又是升序时，每一轮基准就是当前最大值。分区后左段长度是 n - 1，右段是空。比较次数是 (n - 1) + (n - 2) + … + 1，正好 O(n²)。随机交换一个下标再当基准，这种输入就不再特殊。

Hoare 分区从两端向中间扫描，交换次数通常更少，但基准的最终下标不是循环结束时的右指针那么直观。调试时打印指针可以，交卷前的实现里不应留下 console.log。

注意

  • 分区若没有把基准放到不再参与递归的位置，左右区间有一边会和原来一样大，函数不会返回。
  • 相等元素很多时，Lomuto 把等于基准的值全部堆到一侧，仍然偏斜。三路分区单独划出等于基准的一段。
  • 快速排序适合内存里的比较排序。链表上分区要改成按结点拆链，数组下标版本不能直接套。

基准要让区间变小

分区结束后，基准下标 p 不再进入左右递归。若左右一边仍是原来的 [start, end]，调用不会结束。start >= end 时直接返回，单元素区间不必再分区。固定取最左元素又遇到升序数组时，每层只排好一个元素，比较次数变成平方级。随机基准用来避开这种输入。

Lomuto 分区把小于基准的元素换到左侧，最后把基准换到分界点。等于基准的元素留在右侧，大量重复值时仍然偏斜。三路分区把等于基准的一段划出来，递归只处理严格小于和严格大于的两段。

递归栈平均 O(log n)，最坏 O(n)。小区间改插入排序能减少一层层调用的开销，不改变最坏情况下的平方比较。
