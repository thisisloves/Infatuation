Scanner 读什么

java.util.Scanner 自 Java 5 引入，用来把字符流拆成标记（token）再解析成类型。它不是控制台专用类，数据源可以是 InputStream、File、Path、Readable 或字符串。

默认分隔符是空白（空格、制表符、换行等），可用 useDelimiter 修改。小数点是否是 . 取决于区域设置，解析时最好 useLocale(Locale.US) 或 Locale.ROOT，避免在使用逗号作小数点的环境下 nextDouble 失败。

Scanner 有内部缓冲，不是线程安全的。一个流只交给一个 Scanner。

next 与 nextLine

next() 读下一个标记：

  • 先跳过前导空白。
  • 读到后续空白为止，不包含这段空白。
  • 没有标记会阻塞；若流已经结束，抛 NoSuchElementException。先用 hasNext() 判断可避免异常。

输入 hello world 再回车，next() 只得到 hello，world 仍留在缓冲区。

nextLine() 读到当前行结尾（换行符），返回这一行里剩余的内容，换行符本身不包含在结果里。可以读到空格，也可以读到空字符串。

最常见的混用问题

nextInt、nextDouble、next() 都不消费行尾的换行。紧接着 nextLine() 会读到这一行剩下的空串。

不写中间那个 nextLine()，姓名会变成空字符串，程序像是「跳过了输入」。整段输入都按行读，再 Integer.parseInt(line.trim())，边界更清楚，也容易给出格式错误提示。

nextInt 与 hasNextInt

hasNextInt() 看下一个标记能不能当成 int，不消费它。能解析时 nextInt() 才真正读走。不能解析时标记还在，必须 next() 把它丢弃或读出来，否则死循环里会一直看到同一个错误标记。

nextFloat / nextDouble 读的是 Java 浮点字面量风格的标记，不是「任意带小数点的本地写法」，除非你设置了对应 Locale。整数标记也可以被 nextDouble 接受。hasNextFloat 为假时，不要假设缓冲区已经清空。

nextBoolean 只认 true / false（忽略大小写，仍受模式影响）。

关闭

Scanner 实现了 Closeable。它关闭时会关闭底层流。

  • 扫描字符串或你自己打开的文件：用 try-with-resources。
  • 底层是 System.in：不要 close()。关掉之后，这个进程里再读标准输入都会失败，而且关不上的是「控制台」本身这一说法不准确，关掉的是 System.in 这个流。

Scanner(Path) 在 Java 7 加入，按平台默认字符集读文件。文件编码不是默认字符集时，用 new Scanner(Files.newBufferedReader(path, StandardCharsets.UTF_8))。

Scanner 用正则切分，读大文件比 BufferedReader.readLine 慢。只是逐行处理文本时，BufferedReader 更合适。

常见坑

  1. import 写成 mport，源文件直接编译失败。
  2. nextInt 之后直接 nextLine，读到空行。
  3. hasNextInt 失败后不消费标记，循环空转。
  4. 关闭包着 System.in 的 Scanner。
  5. 默认 Locale 下用 nextDouble 解析 "1.5"，在小数点为逗号的地区失败。
  6. 把 Scanner 交给多个线程。

小结

Scanner 按分隔符把输入拆成标记。next 读一个标记，nextLine 读剩余的一整行。数字方法和 nextLine 混用时，主动吃掉换行。标准输入上的 Scanner 不要关闭；文件和字符串用 try-with-resources。区域相关的小数解析先固定 Locale。
