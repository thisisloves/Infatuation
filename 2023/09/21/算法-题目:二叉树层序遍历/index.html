二叉树层序遍历

给定二叉树根节点 root，返回节点值的层序遍历：逐层、每层从左到右。空树返回 []。

力扣题面里的 [3,9,20,null,null,15,7] 只是层序序列化示意。代码里处理的是带 left / right 的树节点。缺孩子用 null 占位，但数组下标不能按 2^i 切层：不规则的树会把下一层的节点算进这一层。

队列 BFS

一层开始前记下这一层还剩多少个节点，只弹出这么多个。子节点入队，留给下一层。若不记下 size，刚入队的孩子会在同一轮被弹出来，层与层就混在一起。

每个节点入队、出队一次，时间 O(n)。队列里同时存在的节点不超过最宽的一层，输出本身也要 O(n)，空间 O(n)。

q.shift() 每次都把后面的元素往前搬，n 次弹出的总代价是 O(n^2)。上面用下标 head 前进，避免这段搬移。旧文按 Math.pow(2, i) 切数组，只对理想满二叉树的下标成立，已不能用。

按深度收集

先序遍历时把节点追加到 ret[depth]，同一层仍然从左到右。这不是「先序打印的顺序就是层序」：先序打印是根、左子树、右子树，层序必须按深度分桶。

时间 O(n)。除了输出，递归栈是树高 O(h)，最斜的树是 O(n)。先左后右不能对调，否则同一层会变成从右到左。

注意

  • 只有根时返回 [[root.val]]。只有左孩子或只有右孩子时，那一层就一个数，不要给缺失的一侧补 0。
  • BFS 适合逐层停下来的变体：右视图取每层最后一个，锯齿形遍历隔层反转。反转的是已经收集好的那一层，不是把入队顺序改成先右后左再叫层序。
  • 序列化数组里的 null 表示没有那个孩子。真正建树之后，叶子的 left、right 是空引用，遍历时直接跳过。

按满二叉树宽度切数组为什么不够

把输入当成 [3,9,20,null,null,15,7]，第 i 层取 2^i 个位置，这个例子可以切对。它要求空孩子已经占了下标，并且函数收到的是数组。题目给的是结点：有 val、left、right，没有 length。值为 0 的结点若写成 if (root[j]) 还会被当成空。所以这一题用队列按层弹出，不要用层宽去切片。

shift 从数组头删除是 O(n)，整棵树会变成 O(n²)。用头下标前进，每个结点只入队出队一次。

空树返回空数组。根的左右都空时，结果只有一层。孩子入队时就不要把空引用放进去，否则下一层会出现无意义的空位。

自底向上的层序可以先按普通层序收集，再把各层数组反转顺序。时间仍是 O(n)。递归写法用深度当层号，把值放进对应的列表，调用栈深度等于树高，链状树会比队列更深。

队列在一轮开始时的长度就是这一层的结点数。本轮新放进去的孩子属于下一层，不能在这一轮弹出。因此每一层自然分成一个数组。

右视图取每一层最后一个值，平均每层取中间值，都是在这个循环上改收集方式，不必再写一种遍历。

层序的时间是 O(n)，队列里同时存在的结点不超过一层的最大宽度。用递归按深度收集时，空间取决于树高，而不是这一层有多宽。两种写法的输出顺序应一致：同一层从左到右。
队列用头下标出队，避免 shift 把后续元素整体左移。左孩子先入队、右孩子后入队，同一层就是从左到右。

根结点入队之前先判断空树，避免对空引用取 val。
