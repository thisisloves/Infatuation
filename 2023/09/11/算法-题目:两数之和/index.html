题目:两数之和

2023-09-11
  • 算法
本文总阅读量次

倚柱寻思备惆怅，一场春梦不分明。

题目

给定整数数组 nums 和目标值 target，找出和刚好等于 target 的两个元素，返回它们的下标。同一个元素不能用两次。假定恰好有一组答案。

下标从 0 开始。返回顺序可以是先小后大，调用方若只要求两个下标，不要返回值本身。

两重循环

枚举每一对 (i, j)，j 从 i + 1 开始，避免把一个位置用两次，也避免 (0, 1) 和 (1, 0) 算成两对。

比较次数约 n² / 2，时间 O(n²)，额外空间 O(1)。数组里没有答案时返回空数组，而不是 undefined。n 到几千以上时，这个写法会明显变慢。

哈希表

扫到下标 i 时，需要的另一个数是 target - nums[i]。若它已经出现过，答案就是那次的下标和 i。否则把 nums[i] 放进表，值为下标。

每个元素最多进表一次、查一次，时间 O(n)，空间 O(n)。必须先查再放入。若先放入，nums = [3]、target = 6 会用同一个下标配对自己。

[3, 2, 4]、目标 6 的过程：

相同的数可以出现两次。[3, 3]、目标 6：第二个 3 查表时，第一个 3 已经在表里，返回 [0, 1]。表的值保存下标，不保存「这个数出现过」的布尔值，否则两个 3 无法区分位置。

后来的下标覆盖先前的下标也没问题，因为只要还存在一个可用的配对，当前元素会在覆盖之前被查到。这道题只有一组答案，覆盖不会漏掉那一组。

有序数组时的另一种做法

若数组已经升序，并且只要两个值、不要原始下标，可以用左右指针：和偏小就左指针右移，和偏大就右指针左移，时间 O(n)。这道题要的是下标，排序会打乱下标，除非先把 (值, 下标) 绑在一起再排。那样是 O(n log n)，比哈希表慢，但额外空间可以只有排序本身。

注意

做法 时间 空间 是否改动下标
两重循环 O(n²) O(1) 否
哈希表 O(n) O(n) 否
排序加双指针 O(n log n) O(n) 或 O(1) 要额外保存原下标
  • 整数相加在有的语言里会溢出。判断时应使用能放下 target - nums[i] 的类型，或者改成比较，避免先加再溢出。
  • Map 用值作键。普通对象作表时，键会被转成字符串，数值本身没有问题，但代码更容易和「下标当键」混在一起。
  • 题目若改成返回所有不重复的对，哈希表仍可用，但要规定一对数的输出顺序，并跳过已经用过的组合。

先放入会配对自己

nums = [3]、target = 6。若循环一开始就把 3 放进表，再问「需要 3 吗」，会返回 [0, 0]。正确顺序是先问再放，表在看到第二个 3 之前只有别的下标。[3, 3] 才能返回 [0, 1]。

两重循环的内层从 i + 1 开始，已经排除了同一个下标。哈希表没有这层下标约束，要靠「放入的时机」补上。

注意

  • 答案下标不要排序后再找值。排序破坏原下标，除非把下标和值绑在一起。
  • Map.has 才能区分「值为 0 的下标」和「没有这个键」。用普通对象时，键 0 和键 "0" 可能撞在一起。
  • 没有答案时返回空数组，调用方不必判断 undefined。题目保证有答案时，这行只是防守。

先查再放入

需要的另一个数是 target - nums[i]。表里已经有它，就返回那个下标和 i。然后才把当前值放进表。先放再查会让 [3] 和目标 6 配成同一个下标。两重循环从 i+1 开始能避开这个问题，时间是 O(n²)。哈希表是 O(n) 时间和 O(n) 空间。
