题目:数组转换树

2023-09-30
  • 算法
本文总阅读量次

神女生涯元是梦，小姑居处本无郎。

题目

每个结点有 id、name 和父结点 pid。pid 在数组里找不到对应 id 的，就是根。把扁平数组收成树，孩子放进 children。

部门 1 是根。部门 2、3 是它的孩子。部门 4 挂在 3 下面，部门 5 挂在 4 下面。输入顺序不保证父亲在孩子前面。

一次建表

先为每个结点做一个带空 children 的副本，用 id 做键。第二遍看 pid：父亲在表里就把自己放进父亲的 children，否则自己是根。

每个结点各看两次，时间 O(n)，空间 O(n)。孩子先出现也没有关系，因为挂接发生在全部结点都进表之后。副本用展开运算，不改原数组；若直接把 children 写进原对象，调用方的扁平数组会被污染。

id 必须唯一。重复 id 时，Map 只保留最后一条，前面的结点会丢。pid 指向自己会造成结点既在自己的 children 里又可能被当成根，数据应先拒绝这种环。

三种容易写错的写法

两重循环只在 j > i 时把结点挂到父亲上，并且直接修改原对象。父亲的下标必须小于孩子。把部门 5 放到数组最前面，它的父亲还没被遍历到，或者遍历父亲时孩子的下标更小，这条边就丢了。时间也是 O(n²)。

只过滤一层孩子的写法：

部门 1 的 children 里是部门 2 和部门 3 的原始对象，部门 3 下面没有部门 4。看起来像树，实际只有两层。要把孙子挂上，孩子数组里的元素必须是「已经带孩子的结点」，不能是原数组里的扁平对象。

递归按 pid 向下找，结果可以是对的，但每一层都扫描全表，链状部门时比较次数是 O(n²)。递归深度等于树高，一条长链会把调用栈用完。上面的 Map 写法没有这个问题。

多个根

pid 同为 0 的两名员工都是根，返回数组长度是 2。不要在找到第一个根之后就 return。森林是这道题的正常输出，不是异常。

若还要按名字或 id 排序，应在挂到 children 时插到有序位置，或者全部挂完后对每个 children 排序。排序不要放进 Map 的构造过程里，否则比较的是插入顺序。

注意

写法 时间 顺序要求 结果
下标 j 必须大于 i O(n²) 父亲在前 顺序不对就丢边
只过滤直接孩子 O(n²) 无 只有一层
每层扫描全表的递归 O(n²) 无 深树易栈溢出
先建 Map 再挂接 O(n) 无 完整的森林
  • 判断根用「pid 不在 id 集合里」，不要写死 pid === 0。有的数据用 null 或空字符串表示根。
  • 宽松相等 == 会把字符串 "1" 和数字 1 当成同一个 id。id 的类型应先统一。
  • 输出若不允许空的 children，叶子就不要加这个字段。同一函数里要么都加，要么都不加，避免调用方一会儿判断数组、一会儿判断 undefined。

样例挂接顺序

部门 5 即使排在数组第一位，第一遍也会先进入 Map。第二遍看到它的 pid 是 4，4 已经在表里，就推进部门 4 的 children。部门 4 再挂到 3，3 和 2 挂到 1，1 的 pid 0 不在表里，1 进入 roots。返回值只有部门 1 这一棵，深度到部门 5。

只做一层 filter 时，部门 1 的孩子是原始的部门 2 和部门 3，部门 4 不会出现在任何 children 里。测试若只断言根的直接孩子，这个错误看不出来，要断言 children[1].children[0].id === 4。

父亲可以出现在后面

建完 Map 再挂接，就不要求父亲的下标更小。两重循环若只看 j > i，把孩子写到数组前面会丢边。只给根结点填一层 filter 结果时，孙子仍是扁平对象，部门 4 不会出现在部门 3 的孩子里。断言要检查到叶子的上一级。

id 重复时 Map 只留下后一条。pid 指向自己会把结点放进自己的 children。这两种输入应在建树前拒绝。多个 pid 都找不到父亲时，返回的是森林，不要只取第一个根。

叶子的 children 用空数组还是省略字段，整个函数只能选一种，调用方才不必同时判断 undefined 和长度。
