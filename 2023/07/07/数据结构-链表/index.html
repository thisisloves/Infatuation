数据结构 链表

2023-07-07
  • 数据结构
本文总阅读量次

钟情怕到相思路。盼长堤，草尽红心。动愁吟，碧落黄泉，两处难寻。

概念

链表用一组结点存储数据。每个结点除数据域外还有指针域，指向下一个或上一个结点，内存不必连续。结点按需分配，中间插删不用搬移后续元素；代价是每个结点多存指针，按下标访问要顺着指针走，缓存也通常比数组差。

常见形态

  • 单链表只有 next，只能向前走。在已有结点后面插入是 O(1)。在它前面插入，或删除它，都要先找到前驱，那是 O(n)。
  • 双链表有 prev 和 next。手里已经有这个结点时，向前插入、向后插入、摘掉它自己，都是 O(1)。Java 的 LinkedList 是带首尾指针的双链表，所以两端插入删除是 O(1)，get(i) 仍是 O(n)。
  • 循环链表的尾结点指回头。判断结束要看是否回到起点，不能再把「指针为空」当成结尾。

「删除是 O(1)」要看手里有什么。单链表在前驱已知时改两个指针，确实是 O(1)；只有当前结点、没有前驱时就不是。双链表不必另找前驱。

和数组比

操作 单链表 双链表 数组
按下标访问 O(n) O(n) O(1)
按值查找 O(n) O(n) O(n)
头部插入 O(1) O(1) O(n)
尾部插入 无尾指针 O(n)，有尾指针 O(1) 有尾指针 O(1) 均摊 O(1)
已知结点之后插入 O(1) O(1) O(n)
已知结点之前插入 O(n) O(1) O(n)
删除已知结点 O(n)，要前驱 O(1) O(n)

单链表有一个常被说成 O(1) 的技巧：把后继的值拷进当前结点，再删掉后继。它删不了尾结点，因为没有后继；外部若还握着后继指针，那个结点的身份也变了。这不是双链表那种真正的 O(1) 摘链。

单链表头插与释放

虚拟头结点（哨兵）可以让头插、删头和中间操作走同一段代码。下面这段不用哨兵，头插时直接换头指针。

list_prepend 是 O(1)。释放时必须先记下 next 再 free，否则下一个结点找不回来。没有尾指针时，单次尾部追加是 O(n)；连续追加 n 次、每次都从头走到尾，总代价是 O(n^2)。

双链表摘掉已知结点 n 只改两侧：n->prev->next = n->next，n->next->prev = n->prev。头尾要判断某一侧是否为空。循环链表还要把「尾的 next 是头」算进去，不能按空指针结束。

适合放什么

LRU 需要把命中的结点挪到一端，双链表配合哈希表可以 O(1) 定位再 O(1) 移动。内核里的队列、频繁在已知位置插删的序列，也常用链表。高频随机下标访问仍然用数组。有环的链表不能用「走到 NULL」判断结束，判环要另做快慢指针一类的算法，不能靠多走几步碰运气。

反转先保存后继

三个指针依次是前驱、当前、后继。先把后继记下来，再把当前的 next 扭向前驱，然后一起前进。先改 next 再去读后继，后半段就丢了。空表和单结点不用特殊返回值。释放时同样先保存 next 再 free，否则结点释放后无法找到下一个。

哨兵结点不存业务数据。头插、删除第一个结点都变成改哨兵的 next，调用方不必替换头指针。

按下标访问要从头数，是 O(n)。已知结点之后插入只改指针，是 O(1)。单链表删除已知结点仍要先找前驱，除非把后继的值拷过来再删后继，而尾结点没有后继，这个技巧用不了。

循环链表的尾指向头，结束条件是回到起点，不是看到空指针。双链表已知结点时可以 O(1) 摘掉，单链表做不到。

头插得到的顺序与输入相反。若要保持顺序，就维护尾指针，新结点接到尾部。只在头上插入再指望顺序不变，结果一定是反的。
