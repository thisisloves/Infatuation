算法 冒泡排序

2023-07-26
  • 算法
本文总阅读量次

江雨霏霏江草齐，六朝如梦鸟空啼。

思想

冒泡排序反复比较相邻元素，逆序就交换。每一轮把当前未排序区间的最大值推到末尾，像气泡上浮。它是稳定排序：相等元素不交换，相对顺序就保持。

平均和最坏时间是 O(n²)，额外空间 O(1)。加上「这一轮没有交换就结束」之后，已经有序的数组只要一轮，最好情况是 O(n)。比较次数在没有提前结束时是 n(n - 1) / 2。

和选择排序分开

有一种写法用 j = i + 1 去和 arr[i] 比，找到更小的就交换。那是选择排序的交换过程，不是冒泡。冒泡只和相邻位置交换，选择排序是先找最值的下标，再和区间起点交换一次。

冒泡 选择
交换对象 相邻 当前位和最小（大）值的位置
稳定性 用严格大于才交换则稳定 不稳定
最好情况 有序且提前结束时 O(n) 仍然 O(n²)
交换次数 多，每次逆序都交换 少，每轮最多一次

过程

以 [5, 1, 4, 2] 为例，每一轮的内层都少看一个已经就位的末尾。

5 先到末尾，然后 4 到次末尾。第三轮若没有 swapped 标志，仍会把剩下的元素再扫一遍，结果相同，比较次数更多。

实现

判断写成 > 而不是 >=。相等时交换会把相同键的原始次序打乱，排序就不再稳定。slice 让函数不修改调用方的数组；若题目允许原地排序，可以直接改 arr。

注意

  • 内层右边界是 n - 1 - i。写成 n - 1 也能排序，但已经就位的最大值会被反复比较。
  • 从右向左扫，可以把最小值沉到开头，复杂度相同。
  • 数据量稍大就不要用它。需要稳定排序时，库里的归并或 Timsort 仍是 O(n log n)。冒泡的价值是把「相邻交换」和「提前结束」讲清楚。

相等元素

[2a, 1, 2b] 用 > 比较时，2a 和 2b 从不交换，排序后仍是 2a 在 2b 左边。改成 >= 会在相等时也交换，稳定性消失，比较次数还可能变多。提前结束的标志只在一整轮都没有交换时才成立。某一轮后半段有序、前半段仍有逆序，不能中途 break 内层循环。

内层上界写成 n - 1 - i 后，第 i 轮不再碰已经就位的末尾。少写这个减 i，结果仍正确，只是把已经确定的最大值又比较了一遍。

相邻才叫冒泡

内层只比较 a[j] 和 a[j+1]。若用 j = i+1 去找最小值再和 a[i] 交换，那是选择排序。冒泡加上「本轮无交换则结束」后，有序数组是 O(n)。条件必须是 >，相等不交换，排序才稳定。

[5, 1, 4, 2] 第一轮结束后 5 在末尾，第二轮 4 就位，第三轮若没有交换就可以停止。没有 swapped 标志时，后面几轮仍会比较已经有序的前缀，结果相同，比较更多。

Java 和 JavaScript 的实现用同一边界：外层到 n - 2，内层到 n - 2 - i。拷贝一份再排序可以不改调用方的数组。
