前端 浏览器缓存

2023-03-25
  • 前端
本文总阅读量次

他想自己在她眼里出现的时候，璀璨如星辰。可即使有那么一天，他披挂着漫天的星辰归来，可是仰望天空的瞳孔已经不在，看星星的女孩已经走了，那璀璨又有什么意思呢？孤单得连星星也想坠落。

缓存分强制缓存和协商缓存

浏览器发出请求前，先看这份资源还能不能直接用。能用且未过期，就是强制缓存，不再访问服务器。过期了但本地还有副本，就带标识问服务器「变了没」，这是协商缓存。都没有，才重新下载。

开发者工具里还能看到内存缓存和磁盘缓存。当前文档还开着时，Chrome 常把刚用过的脚本、图片放在内存里；内存放不下或标签关掉之后，再从磁盘的 HTTP 缓存读。这是浏览器的存放位置，不是另一套 Cache-Control 规则。除此之外还有 Service Worker 可以抢在 HTTP 缓存之前响应。下面讲的强缓存、协商缓存指 HTTP 缓存。

普通刷新会重新向服务器确认 HTML，子资源仍可能命中缓存。强制刷新（绕过缓存）会让浏览器忽略未过期的副本。把它说成「请求头里写了 Cache-Control: no-cache，所以服务器一定返回 200」并不准确：no-cache 的含义是「可以存，但使用前必须向服务器确认」，确认后服务器经常返回 304，而不是一份新的 200。真正禁止存储的是 no-store。

强制缓存

响应头告诉浏览器，在一段时间里可以不请求服务器。

Cache-Control 优先于 Expires。Expires 是一个绝对时间，受客户端时钟影响。Cache-Control: max-age=3600 表示从响应生成起 3600 秒内新鲜。

指令 含义
max-age=秒 新鲜时间
s-maxage=秒 只约束共享缓存（CDN），覆盖 max-age
public 允许共享缓存存储
private 只允许浏览器存，CDN 不要存
no-cache 可以存，用之前必须协商
no-store 不要存储
immutable 新鲜期内刷新也不必再问服务器，适合带内容哈希的文件

带哈希的 app.8f3a.js 可以用较长的 max-age 加 immutable。HTML 入口不要这样，否则用户长期拿不到新的资源表。HTML 适合 no-cache，让浏览器每次确认。

新鲜期内命中强缓存时，状态码仍显示 200，尺寸一列会标 memory cache 或 disk cache，这次没有网络往返。

协商缓存

副本过期，或指令要求每次确认时，浏览器带上标识：

响应 之后的请求 未修改时
ETag: "abc" If-None-Match: "abc" 304，正文用本地的
Last-Modified: <日期> If-Modified-Since: <日期> 304

两者都有时以 ETag 为准。Last-Modified 精度是秒，一秒内多次发布可能对不上；文件只改了时间戳也会误伤。ETag 可以是内容哈希。带弱校验前缀 W/ 的 ETag 表示语义相同即可，不一定字节相同。

304 没有正文，所以协商缓存省的是传输，不是往返。强缓存连往返都省。

谁先谁后

  1. 若存在 Service Worker 并拦截了这个请求，先看它的策略。
  2. 再看 HTTP 缓存是否新鲜。新鲜则直接用。
  3. 不新鲜则带 If-None-Match 或 If-Modified-Since 请求。
  4. 304 继续用本地副本；200 则用新正文并更新缓存标识。

没有 Cache-Control / Expires 时，浏览器可能按启发式缓存猜一个时间，行为不稳定。生产资源应显式写出 Cache-Control。

接口响应默认不要长缓存。带用户数据的响应使用 private, no-store。CDN 上的公开静态文件才用 public。

发布时怎么配

HTML：Cache-Control: no-cache。
带内容哈希的 JS、CSS、字体、图片：max-age=31536000, immutable。
不带哈希、又会原地覆盖的文件：短 max-age 或 no-cache，否则用户会一直用旧文件，直到过期。
