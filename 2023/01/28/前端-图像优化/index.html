前端 图像优化

2023-01-28
  • 前端
本文总阅读量次

桃花流水窅然去，别有天地非人间。

图片慢，通常是体积和张数

图片优化是让首屏少下载字节，并且下载的尺寸接近屏幕上显示的尺寸。HTTP/1.1 下浏览器对同一主机的并发大约是 6 个，所以曾经把图片放到另一个域名，让 CSS、脚本和图片并行。HTTP/2 之后一个连接可以多路复用，再拆很多域名反而多了握手。新站点用同一主机或一个 CDN 域名即可，不要为了并行再做域名分片。

图片流量大时，用对象存储加 CDN 分担，和应用服务器的动态接口分开，避免动态机器被静态流量占满。这是容量规划，不是浏览器的跨域技巧。

格式

格式 适合
JPEG 照片。有损，没有透明
PNG 需要透明或硬边图形。体积通常比照片的 JPEG 大
WebP 照片和透明图都能比 JPEG/PNG 小，浏览器已普遍支持
AVIF 同样画质下往往更小，编码更慢，老浏览器要准备后备
GIF 只适合很短、颜色很少的动图。短视频用更合适的视频格式
SVG 图标和简单矢量，放大不失真

Base64 不是一种图片格式。把图片嵌进 CSS 或 HTML 会让体积大约增加三分之一，而且不能单独缓存。只对大约 1KB 以内、和文档一起使用的小图标有意义。

有损压缩（如 TinyPNG 一类工具）在肉眼几乎看不出的前提下减小文件。导出时就按显示尺寸出图：页面上 800 像素宽，就不要传 4000 像素的原片。

<picture> 按浏览器支持选择第一份能用的格式。img 留作最后的后备，并写上宽高，避免加载后布局跳动。

按屏幕给尺寸

srcset 配合宽度描述，浏览器按视口和设备像素比挑选。只准备一张最大图时，手机也会下载它。

屏外图片加 loading="lazy"。首屏主图不要懒加载。CSS 背景图没有 srcset，复杂主视觉改用 <img> 才能响应式。

精灵图和图标

HTTP/1.1 时代把小图标拼成一张精灵图，用 background-position 切。请求数下来了，但改一个图标就要整张缓存失效。现在图标用 SVG，或一张 SVG sprite。位图精灵只留在还要兼容很老浏览器的页面上。

展示时少触发重排

图片标签写 width 和 height，CSS 用 height: auto 保持比例。容器可以用 aspect-ratio。不要在 onload 里再把高度从 0 改到实际高度，那会让下方内容跳一次。

同一页面不要把几十张无压缩 PNG 照片直接打进仓库。构建时压缩，运行时走 CDN 缓存，缓存时间和内容哈希一起定，换图才换地址。
