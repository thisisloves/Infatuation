前端 页面渲染过程

2023-05-02
  • 前端
本文总阅读量次

遇见喜欢的人，就像浩劫余生终遇大陆。

从地址到像素

在地址栏输入 URL 后，浏览器要先找到服务器，取回 HTML，再把 HTML 和 CSS 变成屏幕上的像素。导航和渲染是前后两段，不要合成一步「查缓存」。

导航

  1. 浏览器先看这段地址有没有未过期的 HTTP 缓存（针对整次文档请求）。这和 DNS 缓存不是同一层。
  2. 解析主机名。DNS 结果可能来自浏览器自己的缓存、操作系统缓存、路由器或解析器。经典 DNS 查询常用 UDP 53，响应太大时改走 TCP，现在也有 DNS over HTTPS / TLS。不能说 DNS 只能是 UDP。
  3. 按协议选端口：未写端口时，http 是 80，https 是 443，不是永远 80。
  4. 建立传输连接。TCP 需要三次握手；HTTPS 还要在这之后完成 TLS。HTTP/3 走 QUIC，握手和加密叠在一起。HTTP 请求可以在某些实现里附在握手的最后一段上，但有 TLS 时，应用数据在握手完成之后才发。不要把「HTTP 报文就是第三次握手的数据」当成固定步骤。
  5. 服务器返回 HTML。Cache-Control、ETag 可能让这次变成 304。
  6. 连接多半不会立刻四次挥手关掉。HTTP/1.1 默认保持连接，后面的 CSS、JS 可以复用；HTTP/2 还在同一连接上多路复用。

关键渲染路径

HTML 一边下载一边解析，生成 DOM。遇到没有 async / defer 的脚本会停下来执行，因为脚本可能改文档。CSS 不阻止解析，但会阻止渲染：没有 CSSOM 时，浏览器不知道元素该长什么样，不会先画一版再重来。

  1. HTML 解析成 DOM。
  2. CSS 解析成 CSSOM。
  3. 两者合成渲染树。display: none 的节点不进渲染树；visibility: hidden 仍占据位置。
  4. 布局（layout / reflow）计算每个节点的几何位置。
  5. 绘制（paint）生成像素信息，层（layer）可能分开。
  6. 合成（composite）把层合到屏幕上。只改 transform 和 opacity 时，往往可以只走合成，不必重新布局。

读 offsetWidth 这类布局属性会迫使浏览器提前布局。在循环里读写交替，就会反复重排。

两个时间点

DOMContentLoaded：文档解析完成，阻塞脚本已执行。不等待样式表之外的图片。
load：文档依赖的图片、样式等资源都加载完。

首屏优化看的是最大内容绘制（LCP），它往往早于 load。把所有脚本堆到 load 里执行，会让页面很久不能交互。

渲染之后脚本做了什么

框架会在 DOM 之上再维护一棵虚拟树，数据变化时算出最小 DOM 操作。这一步已经是应用自己的更新，不属于浏览器第一次把 HTML 变成像素的那条路径。服务端渲染则是服务器先给出 HTML，浏览器先走一遍上面的路径，再由脚本注水。
