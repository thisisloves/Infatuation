哈希表

哈希表用哈希函数把键映射到桶。理想情况下插入、查找、删除的期望时间是 O(1)。最坏情况下所有键落进同一个桶，链地址法退化为 O(n)。

函数要快，并且把键尽量打散。整数可以用乘法哈希再取模。字符串常用 FNV 或 MurmurHash 一类的非加密哈希。加密哈希太重，不适合做桶下标。

冲突

方法 做法 后果
链地址 每个桶挂一条链表或平衡树 删除简单，多一个指针
开放寻址 冲突后按探测序列找下一个空位 表要预留空位，删除要做标记

线性探测实现简单，但冲突会连成一段，称为一次群集。二次探测减轻一次群集，仍可能出现二次群集。双重哈希用第二个函数决定步长，分布更好，也更难写对。

Java 的 HashMap 用链地址。链表长到一定程度，且键实现了可比较接口时，会把这条链树化，避免恶意碰撞把一条链拉成 O(n)。

负载因子

负载因子等于元素个数除以桶数。Java HashMap 默认阈值为 0.75。过高则冲突变多，过低则空桶浪费。超过阈值就扩容并重哈希：桶下标全部重算，旧数组作废。单次扩容是 O(n)，按倍数扩容时，连续插入的均摊代价仍接近 O(1)。

扩容期间不能继续使用按旧容量算出来的下标。迭代器在扩容后也应视为失效。

相等和哈希必须一致

若 a 与 b 相等，则 hash(a) 必须等于 hash(b)。反过来，哈希相同不代表键相同，还要再比较键。只改哈希、不改相等，查找会去错误的桶，元素像是丢了。C 里用指针当键时，要事先决定比的是地址还是指针后面的内容，两种哈希不能混用。

遍历顺序不是插入顺序，除非额外用链表把插入次序串起来，例如 LinkedHashMap。

整型键的链地址表

hash_int 已经对桶数取模，桶下标不要再取一次。第二次取模结果相同，只是多余。

42 先入桶，再放入 10。查找 42 得到 4200。同一个键再次 put 只改值，不新增结点。这段没有扩容，也没有释放结点，只说明桶和链表怎么接。负的 int 转成 unsigned 后再乘，避免负数取模得到负下标。

注意

  • 用哈希表统计、去重、做两数之和，是用 O(n) 空间换 O(n) 时间。
  • 多线程共享一张表时，整次 put 必须互斥，只保护哈希函数不够。
  • 自定义键若会变，而且变化影响到哈希或相等，放进表以后就不能再改。

先比哈希，再比键

哈希相同只说明要进同一个桶，键还要用相等比较。相等的键必须算出同一个哈希，否则查找去了别的桶。负载因子过高就扩容重哈希，均摊仍接近 O(1)，最坏的全冲突是 O(n)。这里的取模在哈希函数里做一次即可。
