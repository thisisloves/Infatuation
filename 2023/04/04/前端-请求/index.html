浏览器里发 HTTP

页面和服务器之间就是 HTTP 请求和响应。前端要分清三件事：用什么 API 发、正文是什么格式、怎样判断成功。

常见 API：

API 特点
XMLHttpRequest 浏览器原始接口，能看上传进度
$.ajax jQuery 对 XHR 的封装，并带 Deferred
fetch 浏览器内置，基于 Promise，不包装业务错误
axios 第三方库，拦截器、超时、JSON 转换都内置

jQuery 的 $.ajax 不是「只为 MVC 设计」，也没有和 MVVM 冲突。它的问题是：只要发请求就带上整个 jQuery、上传进度和取消要碰底层 XHR、拦截器不如后来的库清楚。项目里已经有 jQuery 时，继续用 $.ajax 完全合理。

jQuery 3 里，HTTP 4xx/5xx 和网络失败都会进入 fail。

fetch

fetch 只有网络层失败（断网、DNS、CORS 被拒）才 reject。404 和 500 仍是 resolved，必须看 response.ok 或 status。

默认 credentials 是 same-origin，跨域不带 Cookie。需要跨域 Cookie 时写 include，且服务端 CORS 不能用 *。

超时用 AbortSignal.timeout(10000) 或自己的 AbortController。fetch 没有上传进度回调；需要进度时用 XHR。

GET 不要写 body。Content-Type: application/json 会触发跨域预检。

axios

axios 在状态码超出 validateStatus（默认 2xx）时走错误分支，这一点比 fetch 接近 $.ajax。取消请求使用 AbortController 的 signal。旧的 CancelToken 已不推荐。

拦截器适合统一加令牌、处理 401。不要在拦截器里无限重试同一个失败请求。

正文格式

格式 何时
JSON 结构化接口。自己 JSON.stringify，并设置 Content-Type
x-www-form-urlencoded 传统表单。jQuery 默认把对象编成这种
FormData 文件上传。不要手写 Content-Type，让浏览器带上 boundary
查询串 GET 的过滤条件。用 URLSearchParams 编码

状态码

2xx 成功，201 常表示已创建。304 是协商缓存未修改，不是错误。401 未认证，403 已认证但没权限，404 资源不存在，409 冲突，422 参数不合法，429 太频繁。5xx 是服务器故障，可以有限次重试；4xx 重试同样的正文没有意义，要先改请求。

幂等的 GET 可以重试。POST 创建订单这类请求重试前要有服务端的幂等键，避免双倍提交。
