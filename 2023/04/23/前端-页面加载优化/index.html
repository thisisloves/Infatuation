前端 页面加载优化

2023-04-23
  • 前端
本文总阅读量次

优化目标是首屏可用

加载优化要缩短用户看见主要内容并能操作的时间。HTTP/2 和 HTTP/3 可以在一个连接上并发很多资源，为了把请求数压成一个而把全站拼成一张雪碧图、一个巨大的 JS，常常更慢。仍值得合并的是大量极小且一起变化的图标，以及不会再改的第三方小片段。

资源本身变小

压缩有两层：

  • 压缩源码：去掉空格、注释和未使用的导出，缩短变量名。CSS、JS 在构建时做。能降多少取决于注释和死代码，没有固定的百分之五十。
  • 压缩传输：服务器对文本开 Brotli 或 Gzip。图片换成合适的格式和尺寸，而不是把 JPEG 再 Gzip 一遍指望体积腰斩。

带内容哈希的文件名配合长期缓存，回访时不再下载未改动的包。HTML 用协商缓存，保证能指向新的哈希文件。大段 CSS 和 JS 使用外链，跨页面才能命中缓存；首屏关键的一小段 CSS 可以内联，避免多一次往返。

静态资源放到 CDN，缩短往返时间。源站只处理 HTML 和接口。

少做阻塞

CSS 放在头部，让首屏样式尽早参与渲染，避免先出一版没有样式的 HTML 再跳变。

defer 并行下载，文档解析完后按顺序执行。async 谁先下完谁先执行，适合互不依赖的统计脚本。type="module" 默认就是 defer。业务包不要用 async，顺序没有保证。

关键字体和首屏大图用 <link rel="preload" as="image">。下一跳才需要的包用 prefetch，不要把所有路由都 preload，那会和首屏抢带宽。

expression() 是旧 IE 的 CSS 写法，滚动时反复执行脚本。现在用普通 CSS 和少量 JS，不要再写它。

代码按路由拆开

登录后才用的图表、编辑器做成动态 import()。Vue 路由上写 () => import("./Chart.vue")。首屏只下载当前路由。第三方库单独成 chunk，业务小改时用户还能用缓存里的依赖包。加载过程留占位，失败要能重试。

图片、字体和 DOM

首屏图写尺寸、用现代格式，不要懒加载。屏外图片用 loading="lazy"，配合 srcset 和 sizes。图标优先 SVG。字体使用 font-display: swap，并做子集化。

DOM 不要又深又碎。上万行的表格用虚拟列表，不要一次创建全部节点。动画用 transform 和 opacity。避免在解析期间 document.write 插入脚本。

怎么确认有效

用网络面板在禁用缓存时看瀑布，用性能面板看长任务。实验室和真实用户都看 LCP、INP、CLS。一次只改一类资源，否则分不清是拆包生效还是图片变小生效。请求数变少，不代表首屏更快。
