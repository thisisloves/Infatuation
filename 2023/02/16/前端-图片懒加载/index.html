前端 图片懒加载

2023-02-16
  • 前端
本文总阅读量次

人生到处知何似？应似飞鸿踏雪泥。

懒加载推迟非首屏图片

长页面若一次性请求全部图片，会占满连接和带宽，首屏更慢。懒加载让视口附近的图片才去请求，其余只保留占位。

浏览器是否请求图片，取决于 <img> 有没有可用的 src（或 srcset）。不要先写上真实 src 再指望脚本阻止，解析到 src 时请求可能已经发出。

原生写法

现代浏览器支持：

loading="lazy" 由浏览器决定何时去取，一般在离视口还有一段距离时就开始，避免滚到了才出现空白。首屏最重要的那张图不要加 lazy，应尽早请求，必要时用 <link rel="preload" as="image">。

同时写上 width 和 height，或用 CSS 留出宽高比，避免图片进来之后把版面往下顶。

loading 管的是文档里的图片和 iframe。CSS 背景图没有这个属性，背景图要么改成 <img>，要么自己观察元素。

IntersectionObserver

需要兼容更老的浏览器、或要统一做占位图淡入时，用观察器。它不监听整个页面的滚动，只在目标进出视口时回调。

rootMargin 提前 200px 开始加载。图片解码完成前可以先显示低清占位或纯色块。失败时在 error 里换一张兜底图，并 unobserve，避免逻辑反复触发。

new Image() 预加载适合鼠标悬停前提前取一张，不是懒加载的必要步骤。懒加载本身就是「先不请求」。

判断位置时别用错尺寸

视口宽度用 window.innerWidth 或 document.documentElement.clientWidth。document.body.clientWidth 是 body 的内容宽度，body 有外边距或没撑满时和视口不一致。

element.offsetWidth 含边框，clientWidth 不含边框但含 padding。它们描述元素，不是屏幕。

滚动距离用 window.scrollY。标准模式下 document.documentElement.scrollTop 才是文档滚动，document.body.scrollTop 在多数现代页面里是 0。

window.screenTop / screenLeft 是浏览器窗口相对屏幕的位置，不是页面滚过了多少。用它们判断「图片是否进入网页可视区」会得到错误结果。

若必须自己算：

滚动事件要节流，并在图片进入后移除监听。元素在 transform 的容器里滚动时，getBoundingClientRect 相对视口仍然有效，但监听的应是那个滚动容器，而不是一律 window。

响应式图片一起懒加载

有 srcset 时浏览器会选接近显示尺寸的那张，再叠加 loading="lazy"。不要只懒加载最大的原图，手机仍会下载桌面尺寸。
