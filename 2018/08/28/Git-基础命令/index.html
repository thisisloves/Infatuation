Git 基础命令

2018-08-28
  • Git
本文总阅读量次

一壶酒，一竿纶，世上如侬有几人。

创建仓库

命令 说明
git init 在当前目录初始化 .git
git init -b main 初始化并把默认分支命名为 main
git clone <url> 克隆远程，记下 origin 和默认分支
  • clone 得到完整历史。只要最近一层提交时用 git clone --depth 1，之后查更早提交会缺对象。

看状态与差异

  • 不带参数的 git diff 不含已经 add 的内容。提交前两段都看一眼。

暂存与提交

工作流是：工作区 → git add 暂存区 → git commit 本地仓库。

命令 说明
git add <path> 把该路径当前内容写入暂存区
git add -p 按块挑选，一个文件可以只暂存几段
git commit -m "说明" 把暂存区做成一次提交
git commit -a 已跟踪文件的修改一并提交，新文件不会进去
git restore --staged <file> 撤出暂存区，工作区修改保留
git restore <file> 用暂存区内容覆盖工作区
git rm / git mv 删除或重命名，并记入暂存区
  • 空暂存区时 git commit 会拒绝。改完文件忘记 add，说明写了也没有新快照。
  • git commit --amend 会改写最近一次尚未推送的提交并生成新哈希。已经推送后再 amend，别人手里的旧哈希就对不上。

一次完整的本地提交

  1. status 看改过哪些路径、哪些还没跟踪。
  2. git diff 核对还没暂存的内容。
  3. 只 add 这一次要提交的文件。
  4. git diff --staged 就是即将写入的差异。
  5. git log -1 --stat 看这次动了哪些文件。

历史

命令 说明
git log --oneline --graph --decorate -20 最近 20 条，带分支线
git show <commit> 某次提交的说明和差异
git blame <file> 每一行最后来自哪次提交
  • git log 从当前 HEAD 沿父提交往回走。其它分支上还没合并过来的提交要用 git log --all 才看得到。

远程

命令 说明
git remote -v 查看远程别名与 URL
git fetch 更新远程跟踪分支，不改工作区
git pull fetch 再合并或变基，由 pull.rebase 决定
git push -u origin HEAD 推送当前分支并设置上游
  • HEAD..origin/main 是对方有、本地还没有的提交。先看这段，再决定合并还是变基，比直接 git pull 不容易把意外的历史搅进当前分支。

撤销时先分清三层

目的 命令
丢掉工作区里未暂存的修改 git restore --source=HEAD -- <file>
取消暂存，保留修改 git restore --staged <file>
移动分支指针 git reset --soft / --mixed / --hard
保留历史、追加反向提交 git revert <commit>
  • --hard 会改写工作区。已经公开的提交用 revert。三种 reset 的差别见《Git-版本回退》。

常见坑

  • git add . 会纳入当前目录下所有未忽略的新文件，包括构建产物。提交前看 git status。
  • 路径和分支重名时，git checkout 可能歧义。用 git switch 切换分支，用 git restore 还原文件。
  • git clean 会删除未跟踪文件。先 git clean -n 预览，再考虑 -f。
