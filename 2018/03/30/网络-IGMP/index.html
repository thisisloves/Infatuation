IGMP 管什么

IGMP（Internet Group Management Protocol）在主机和同一网段的组播路由器之间维护组成员关系。它不管组播路由怎么在路由器之间计算，那是 PIM 等协议的事。IGMP 是 IP 协议号 2，没有传输层端口，报文 TTL 为 1，路由器不按普通路由转发它。版本有 v1、v2、v3。

路由器只需要知道「这个接口后面还有没有人要组 G」，不需要知道每一个成员的名单。主机负责报告，查询器负责定期询问。224.0.0.0/24 是链路本地组播，留给协议自己用，不要拿来当业务组地址。

三个版本

IGMPv1 IGMPv2 IGMPv3

报告发往 组地址 G 组地址 G 224.0.0.22
离开 不通知，静默离开 向 224.0.0.2 发送 Leave 用新报告更新过滤模式
查询器 自己不选，靠上层组播路由 IP 最小者 同 v2
报告抑制 有 有 取消
源过滤 无 无 INCLUDE 或 EXCLUDE

v1 的报告发往正在加入的组地址，不是发往 224.0.0.1。224.0.0.1 是本网段所有主机，用来收查询。224.0.0.2 是本网段所有路由器，v2 的 Leave 发到这里。

IGMPv1

路由器向 224.0.0.1 发送成员查询。希望接收组 G 的主机把 Report 发往 G。不接收任何组播的主机不回答。路由器记下（*，G），以后从上游来的 G 会从这个接口转发出去。

主机离开时不发消息。查询器若干次问不到该组的报告，才删掉表项，所以离开很慢。v1 没有查询器选举，一个网段上谁发查询，要靠 PIM 等上层协议约定。

主机发送报告前会等待一段随机时间。若在这段时间内听到同组的报告，就不再发送，避免同一网段上千台主机同时回答。这叫报告抑制。想加入时不必干等查询，可以立刻发送 Report。

IGMPv2

普遍查询仍然周期性地发往 224.0.0.1，默认间隔 125 秒。同一网段 IP 地址最小的路由器成为查询器，其他路由器只听报告，并启动「其他查询器存在」计时器。计时器超时还没听到更小地址的查询，自己才接任。

离开时主机向 224.0.0.2 发送 Leave，里面写明组地址。查询器马上发指定组查询，问这个网段是否还有成员。有成员就再报告一次；在重试次数内没有报告，就删除该组。这比 v1 的静默超时快得多。指定组查询期间，该组的报告抑制仍然存在。

Leave 只说明「我走了」，不能说明别人也走了。没做指定组查询就删表，会把还在看的成员一起切断。

IGMPv3

主机可以指定接收哪些源，或排除哪些源。报告里带组地址、过滤模式和源列表，发往 224.0.0.22。路由器据此维护（S，G）或排除列表，而不仅是（*，G）。

离开某个源：主机发送新的报告，源列表里不再包含它。查询器可以发针对该组和该源的查询。没有人还要这个源，就从转发状态里删掉。

离开整个组：主机发送过滤模式变为 INCLUDE、源列表为空的报告。查询器再确认没有其他成员后删除该组。

v3 取消报告抑制。每台主机的源列表可能不同，听到别人的报告不能代表自己，而且报告发往 224.0.0.22，普通成员默认并不处理它。

注意

  • 交换机上的 IGMP Snooping 只窃听报告和离开，用来限制组播帧的泛洪。它不是组播路由器，自己也不建立 PIM 邻居。
  • 一个网段应只有一个查询器。出现两个，多半是选举没完成，或地址配重了。网段里没有任何查询器时，成员关系会一直挂到超时。
  • 主机加入组播组，只表示本网段的路由器知道要转发。源到这里的组播树还要靠 PIM 和单播路由。
  • v1、v2、v3 的报告目的地址不同。抓包时用 224.0.0.1 去滤 v3 报告，会什么都看不到。

加入和离开各发到哪

v2 主机想收 239.1.1.1 时，Report 的目的地址就是 239.1.1.1，不是所有主机。查询器默认每 125 秒向 224.0.0.1 问一次。主机在最大响应时间（默认 10 秒）内随机等待；若听到同组报告就不再发，这是抑制，不是固定等满 10 秒。

v1 没有 Leave，成员表要等到若干个查询间隔都没有报告才删，通常是两分钟以上。v2 在 Leave 之后马上做指定组查询，没有人回答就删，一般是秒级。把两个版本都写成「主机一走就停转」是错的。

查询器不在交换机里

Snooping 只决定组播帧从哪些端口出去。表项靠听到报告来刷新，而报告往往是被查询激出来的。一个 VLAN 里如果没有组播路由器，就要有一台设备充当查询器，否则侦听表老化之后，组播又在整个 VLAN 里泛洪。

查询器宕机时，其他路由器等到「其他查询器存在」超时，由剩下的最小 IP 接替。地址配重会导致两个查询器同时在问，成员表来回刷新，先查 IP 冲突，再查版本是不是混用了 v1。

时间量级

v2 查询间隔常见 125 秒，健壮性系数常见 2，再加一次最大响应时间，成员没人回答时大约两百多秒才删表。Leave 之后的指定组查询把这个时间压到秒级。v3 报告里的 INCLUDE 空列表表示离开整组，EXCLUDE 或带源的 INCLUDE 表示还要过滤源。只改组地址、不看源列表，源特定转发不会更新。

主机一上线就可以主动发 Report，不必干等下一个查询周期。v1 听到同组报告会抑制自己的报告；v3 不抑制，因为每台主机的源列表可能不同。

业务组地址不要用 224.0.0.0/24。这一段是链路本地的协议地址，例如 224.0.0.1 和 224.0.0.22，路由器不会把它当成普通组播路由的数据组。

v2 的指定组查询发往组地址本身。若错误地发往 224.0.0.1，其他组的主机也会被问到，抑制和计时都会乱。

离开报文发往 224.0.0.2。主机自己不处理别人的 Leave，只有查询器据此再问一次。

IGMP 的 TTL 是 1，查询和报告都不应被路由器转发到别的网段。跨网段的组播要靠 PIM 建树，而不是把 IGMP 报文路由过去。协议号是 2，抓包时不要去传输层找端口。
v1 报告发往组地址，v2 的 Leave 发往 224.0.0.2，v3 报告发往 224.0.0.22。这三个目的地址对调之后，查询器收不到该收的报文。
