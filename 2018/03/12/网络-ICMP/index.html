网络 ICMP

2018-03-12
  • 网络
本文总阅读量次

ICMP 的位置

ICMP（Internet Control Message Protocol）在主机和路由器之间传递控制信息：目的是否可达、报文为何被丢、时间是否超过。它和 IP 同属网络层，但 ICMP 报文装在 IP 分组里，协议号是 1。IP 本身不通知丢包原因，ICMP 用来补上这类反馈。它不是让 IP 变成可靠传输的手段，出错报告也可以丢失。

一个 ICMP 差错报文里，通常带上引发差错的那个 IP 头，以及原始数据的前 8 个字节，方便发送方认出是哪一个 TCP 报文段或 UDP 数据报。不要把结构说成「IP 头、ICMP 头、再加一份完整的 ICMP 报文」这种循环说法。

ping 和 traceroute

ping 发送 Echo Request（类型 8），对端回 Echo Reply（类型 0）。能收到应答，说明来回路径、对方协议栈和本机都允许这种报文。收不到，可能是丢包、过滤或对端禁止 ping，不能直接断定主机不存在。

traceroute 利用 TTL。第一份探测的 TTL 为 1，第一台路由器减到 0 后丢弃，并回 Time Exceeded。源站因此知道第一跳。然后 TTL 加 1，逐跳收集，直到探测到达终点。

Linux 传统实现发送 UDP，目的端口从 33434 起。Windows 的 tracert 发送 ICMP Echo。终点的反应也不同：UDP 探测常收到端口不可达，ICMP 探测收到 Echo Reply。两种都叫 traceroute 一类的工具，报文不一定相同。

类型与代码

类型 代码 含义
0 0 Echo 应答
3 0 网络不可达
3 1 主机不可达
3 2 协议不可达
3 3 端口不可达
3 4 需要分片但设置了不分片
5 0～3 重定向
8 0 Echo 请求
11 0 TTL 超时
11 1 分片重组超时
12 0 参数问题

连到一个没有进程在听的端口，会收到类型 3、代码 3。这和端口号是否小于 1024 无关。1024 以下只是特权端口的历史划分，不是 ICMP 的判断条件。

类型 11、代码 0 就是 traceroute 收集中间路由器的依据。代码 1 表示目的主机在规定时间内没能把分片重组完。

源抑制（类型 4）曾经用来要求发送方放慢速度。它没有配套的「可以恢复」报文，也容易被滥用，已经废弃，不能再当成现网的拥塞控制。

时间戳请求是类型 13，应答是类型 14，用来估算两端时钟差和往返时间。很多系统直接不回答。

什么时候不应再产生差错

收到 ICMP 差错后，不要再为这份差错产生新的 ICMP 差错，否则会形成风暴。组播、广播、非首分片以及源地址无效的分组，通常也不应触发差错报告。重定向只应来自本网段的原路由器，盲目接受会被人把默认网关改掉。

注意

  • ping 通只说明 ICMP Echo 通，不说明 80 端口或某条应用一定通。
  • 中间设备可以限速或丢弃 ICMP，路径看起来「不通」有时只是控制报文被滤掉。
  • traceroute 的某一跳显示超时，可能是那台路由器不回 Time Exceeded，后面的跳仍可能有响应。

和 TCP 的差错各管一层

连一个关闭的 TCP 端口，可能先看到 ICMP 端口不可达，也可能看到 TCP RST。前者是网络层或主机协议栈用 ICMP 拒绝，后者是传输层明确重置。两者都表示「这一次没连上」，排查时要看抓到的是哪一种，不能只写「网络不通」。

需要分片但 IP 头设了不分片时，返回类型 3、代码 4，并带上下一跳的 MTU。路径 MTU 发现靠的就是这条，不是靠 ping 的默认小包。ping 大小超过路径 MTU 又禁止分片时，同样会收到这条差错。

一份 Echo 里有什么

Echo Request 的 IP 协议号是 1，ICMP 类型 8、代码 0。标识和序号用来把应答配回某一次 ping。数据部分通常是时间戳或填充字节，长度由发送方决定。应答把类型改成 0，标识和序号原样带回。中间路由器一般不改 ICMP 载荷；它若因为 TTL 丢弃分组，回的是类型 11，而不是一份改过的 Echo。

注意

  • 允许 ping 不表示允许 traceroute。有的防火墙只放行 Echo，丢掉 UDP 高端口和 Time Exceeded。
  • 差错报文本身若再丢失，发送方只能依赖上层超时。ICMP 没有重传。
  • 重定向报文可以合法优化本网段的下一跳，也可以被人伪造。主机应只接受来自当前网关、且原分组确实从该网关出去的重定向。

不要用 ping 代替端口测试

ping 192.0.2.10 通，只说明 Echo 的来回都没被丢掉。对方的 443 仍可能拒绝，中间防火墙仍可能只放行 ICMP。反过来，ping 不通而网页正常，是很多服务器故意不回答 Echo。排查应用时看 TCP 是否握手，排查路径时再看 TTL 耗尽和不可达代码。

类型 3 的代码要一起读。代码 1 是主机不可达，代码 3 是端口不可达，代码 4 是 MTU 问题。只写「收到不可达」分不清该改路由、改端口还是改报文大小。

端口不可达与特权端口无关

向没有进程监听的 UDP 端口发送数据，返回类型 3、代码 3。端口是 80 还是 8080 都一样，小于 1024 只说明这个端口在一些系统上需要特权才能监听，不是 ICMP 的判断条件。连接被拒绝时也可能看到 TCP RST，那是传输层的答复，不要和 ICMP 记成同一种包。

traceroute 的第一份探测 TTL 是 1，第一台路由器回类型 11、代码 0。TTL 逐次加 1，直到终点。Linux 传统工具发 UDP，Windows 的 tracert 发 Echo。终点的回答因此一个是端口不可达，一个是 Echo 应答。某一跳星号只说明那台设备没回 Time Exceeded。

差错报文若丢失，发送方只能等上层超时。ICMP 不会为另一份 ICMP 差错再生成差错，避免循环。分片重组失败用类型 11 代码 1，和 TTL 耗尽的代码 0 不同。
