网络 HTTP 和 HTTPS

2018-03-02
  • 网络
本文总阅读量次

春未老，风细柳斜斜。试上超然台上看，半壕春水一城花，烟雨暗千家。

HTTP 是什么

HTTP（HyperText Transfer Protocol）在 Web 上传送资源的表述。浏览器是常见客户端，但客户端不限于浏览器。现在仍大量使用 HTTP/1.1，HTTP/2 和基于 QUIC 的 HTTP/3 也已经普及。默认端口是 80。

工作方式

客户端按 URL 把请求发给服务器，服务器返回状态码和表述。

  1. HTTP 本身无状态：服务器不因为协议而记住上一次请求。登录态要靠 Cookie、令牌或服务器会话，缺这些就得把上下文重传。
  2. 媒体类型独立：Body 可以是 HTML、JSON、图片或任意字节，由 Content-Type 说明。
  3. 连接行为取决于版本。HTTP/1.0 默认发完一个响应就关闭 TCP 连接。HTTP/1.1 默认持久连接，一条 TCP 上可以连续处理多个请求。把「HTTP 无连接，处理完就断开」当成所有版本的定义是不准确的。服务器也不需要先收到「客户对响应的应答」才断开。

报文

请求由请求行、头部、空行和可选的 Body 组成。响应由状态行、头部、空行和可选的 Body 组成。

方法 含义
GET 获取资源的表述
HEAD 只要头部，不要 Body
POST 按资源的语义提交数据，例如表单
PUT 用请求体替换目标资源
PATCH 对已知资源做局部修改
DELETE 删除目标资源
OPTIONS 询问资源允许哪些方法，不是查看服务器性能
CONNECT 让代理把连接改成隧道，常用于代理 HTTPS
TRACE 回显收到的请求，用于诊断，生产环境通常关闭
状态码 含义
1xx 临时响应，请求还在处理
2xx 成功
3xx 重定向，客户端还需再请求
4xx 客户端错误，如 404 找不到、401 未认证
5xx 服务器处理失败

Content-Length 表示 Body 的字节数。持久连接需要它或分块传输来划分报文边界；非持久连接同样可以用它。分块传输时可以不带 Content-Length。它不是「只有持久连接才需要」的字段。

Location 给出重定向或新资源的 URL。Set-Cookie 让客户端保存状态。WWW-Authenticate 说明 401 之后应该提供哪种认证材料。Allow 列出允许的方法。

内容类型

Content-Type 告诉对方 Body 是什么媒体类型、用什么字符集。

类型 常见用途
text/html HTML
text/plain 纯文本
text/xml、application/xml XML
application/json JSON
image/gif、image/jpeg、image/png 图片
application/pdf PDF
application/octet-stream 不透明的二进制，常用于下载

HTTP/1.1 相对 HTTP/1.0

持久连接、分块传输、Host 强制携带（同一 IP 上的虚拟主机）、范围请求、更明确的缓存指令和状态码，都是 1.1 的实质变化。HTTP/2 在一条连接上多路复用；HTTP/3 改走 QUIC，不再为每一条连接单独完成一次 TCP 握手。

HTTPS

HTTP 明文传输，路径上的人能阅读和篡改。HTTPS 是 HTTP 跑在 TLS 之上，默认端口 443。SSL 由 Netscape 设计，3.0 之后由 IETF 发展为 TLS。现在应说 TLS；SSL 3.0 已经淘汰。

TLS 1.2 用 RSA 密钥传输时，过程可以收成下面几步。现网更常见的是 ECDHE，服务器的长期私钥只用于签名，会话密钥由双方临时协商。

  1. 客户端发送 ClientHello：支持的版本、随机数和密码套件。
  2. 服务器回 ServerHello，并送出证书。
  3. 客户端验证证书链和主机名，再用证书里的公钥保护预主密钥，或完成 ECDHE。
  4. 双方从预主密钥和两个随机数导出对称会话密钥。
  5. 之后的 HTTP 报文用会话密钥做对称加密，并带完整性校验。

证书可以向公共 CA 申请。Let’s Encrypt 等机构提供免费证书，「免费证书很少」已经不符合现状。HTTPS 加密的是传输，HTTP 语义仍然无状态。它比明文 HTTP 多了机密性、完整性和服务器身份认证，不能防止应用自己把数据写进错误的日志。

持久连接和长度

HTTP/1.1 默认一条 TCP 上连续发送多个请求，不是处理完就拆连接。Body 的边界靠 Content-Length 或分块传输。持久连接更依赖这个长度，但短连接同样可以用它。OPTIONS 询问允许的方法，CONNECT 用来建隧道，两者都不是「查看性能」或「服务器主动断开」。

TLS 1.2 可以再用证书公钥保护预主密钥。现网更多使用临时椭圆曲线，长期私钥只签名，会话密钥双方各自算出来。图上的「用公钥加密会话密钥」是 RSA 密钥传输的简化，不要把它写成 TLS 1.3 的唯一过程。

免费证书已经常见。HTTPS 没有取消 HTTP 的无状态，Cookie 仍然要自己带。端口 443 与 80 不同，路径上的明文代理看不见 Body。
