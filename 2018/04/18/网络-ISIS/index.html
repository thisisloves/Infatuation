网络 IS-IS

本文总阅读量次

一生一世，如梦初醒。逐梦令，浮生半醒。泪满襟，笑缘尽。

IS-IS 是什么

IS-IS（Intermediate System to Intermediate System）是链路状态内部网关协议，源自 DECnet Phase V，算法和 OSPF 同类：Hello 发现邻居，链路状态泛洪，SPF 计算最短路径。它最初承载 CLNP，后来扩展为集成 IS-IS，也能算 IP 路由。报文直接装在数据链路帧里，不装在 IP 里。

特征

  1. 每个路由器维护链路状态数据库，用 SPF 计算最佳路径。
  2. 用 Hello 建立和维护邻接。
  3. AS 内分两级：连续的 Level-2 组成骨干，Level-1 在各个区域内部。
  4. 区域边界可以汇总，减少骨干上的明细。
  5. 支持 VLSM、CIDR，以及明文、MD5、Keychain 认证。
  6. 网络类型只有广播和点到点。广播网上选举 DIS（Designated IS）负责创建伪节点并协助泛洪。
  7. 窄度量下接口默认开销常为 10。度量类型历史上有默认、时延、费用和差错四类，实际几乎只用默认度量。宽度量才能表示大带宽。
  8. 华为设备上 IS-IS 路由的外部优先级默认是 15。

DIS 的优先级默认 64，数值大的优先，相同再比 MAC。DIS 可以抢占，也没有备份 DIS。OSPF 的 DR 选出后不因后来者优先级更高而退位，并且有 BDR。这是两者在广播网上最容易记混的地方。

区域和路由器类型

区域按整台路由器划分，不是按接口。一台路由器的所有接口属于同一区域。OSPF 相反，区域配在接口上，一台路由器可以跨多个区域。

类型 能看到什么 位置
Level-1 本区域内部路由，去其他区域靠默认路由指向最近的 L1/L2 非骨干区域内部
Level-2 区域之间的前缀 骨干
Level-1-2 同时参加本区域和骨干，是两者的边界 区域边缘

骨干是所有连通的 Level-2 和 Level-1-2，不是「把 L2 和 L1/L2 都摆进一个叫骨干的机房」。L1 类似只了解区域内拓扑；L1/L2 才把区域内的前缀带进骨干。把 L1 说成 OSPF 的 1 类、2 类 LSA，只是粗略类比，报文和泛洪范围并不相同。

NET 地址形如 49.0001.0000.0000.0001.00。49 是私有 AFI，中间是区域号，系统 ID 占 6 字节，最后的 SEL 对 IP 路由必须是 00。同一区域的区域号相同，系统 ID 全网唯一。

和 OSPF 的比较

相同之处：都是 IGP，都是链路状态，都用 Hello 和 SPF，都分层次，都支持较大规模的网络，收敛后没有协议自身造成的环路。

IS-IS OSPF
最初环境 CLNP，后支持 IP 只针对 IP
封装 数据链路帧 IP 协议号 89
网络类型 点到点、广播 还有 NBMA、点到多点
区域 按路由器 按接口
广播网代表 DIS，可抢占，无备份 DR/BDR，DR 不抢占
邻接条件 主要是层次和区域匹配 还要核对掩码、Hello、认证等，条件更多

点到点链路上，OSPF 要求数据库描述严格确认后才算邻接稳定；IS-IS 的同步过程更简单。不能因此说某一个「更可靠」，只是状态机不同。

配置

每台路由器进入 IS-IS 进程，指定级别和 NET，再在需要参与的接口上 isis enable。R2 与 R6 的串行链路两端都要启用，只在一端启用则邻接无法建立。防火墙区域、空接口不属于 IS-IS 配置。

其余路由器换用自己的 NET 和接口地址。R5 若只承担区域内路由，级别设为 level-1，并和同一区域的 L1/L2 路由器使用相同的区域号。Level-1 和 Level-2 之间不会因为各发一份 Hello 就自动交换对方那一层的明细。

注意

  • 系统 ID 不要复制粘贴成两台一样，否则 LSP 会冲突。
  • 只开了 IP 地址、没在接口上 isis enable 的链路不参与邻接。
  • 需要承载很大的度量或很多前缀时使用宽度量，窄度量的范围不够。

NET 不要复制错

49.0001.0000.0000.0005.00 里，系统 ID 是 0000.0000.0005，区域是前面的 49.0001，最后的 00 是 SEL。同一区域的 Level-1 路由器区域号必须相同，系统 ID 必须不同。R2 连向 R6 的串行口若只写了 IP、没有 isis enable，R6 一侧启用了也形成不了邻接。

Level-1 只会和同一区域的 Level-1 或 Level-1-2 建立 Level-1 邻接。一台纯 Level-2 路由器即使网线连着，也不会和对方交换 Level-1 的链路状态。层次要在进程里写明，不要依赖默认值碰运气。

注意

  • DIS 优先级高的后来者可以抢占，OSPF 的 DR 不会。把 OSPF 的选举习惯套到 IS-IS 上会判断错谁在泛洪。
  • 接口地址配好不等于协议已经打开。漏掉 isis enable 时，邻居表是空的，路由表里只有直连。
  • 区域按路由器划分。想让一台设备的两个接口分属两个区域，IS-IS 做不到，那是 OSPF 的模型。

漏启用的接口

串行链路两端都要 isis enable。只配 IP、不进进程，邻居不会出现。防火墙 zone、空接口不是 IS-IS 的配置。NET 最后的 SEL 对 IP 必须是 00，系统 ID 不能两台相同。区域按整台路由器划分，不能把两个接口划进两个区域。
