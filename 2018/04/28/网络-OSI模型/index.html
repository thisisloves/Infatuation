网络 OSI 模型

2018-04-28
  • 网络
本文总阅读量次

夜阑风静欲归时，惟有一江明月碧琉璃。

OSI 是什么

OSI（Open Systems Interconnection，开放系统互连）是 ISO 给出的网络互连参考模型，把通信功能分成七层。它用来对齐概念；因特网上实际运行的是 TCP/IP。英文全称是 Open Systems Interconnection，不是 Open System Interconnect。

七层与协议数据单元

每一层处理的数据单位不同。网络层的单位是分组（包），不要把 IP 包叫成「报文」；报文多指应用层的一条消息。

层 数据单位 这一层解决什么
应用层 数据 直接为应用程序提供服务，如 HTTP、DNS、FTP、SMTP
表示层 数据 编码、压缩、加密，让两端对同一份数据的解释一致
会话层 数据 建立、维持、拆除会话，并用检查点支持恢复
传输层 TCP 报文段，UDP 数据报 端到端交付、端口、可靠或尽最大努力
网络层 分组（包） 逻辑寻址和选路，把分组送到目的网络
数据链路层 帧 成帧、MAC 寻址、差错检测、介质访问
物理层 比特 在介质上传送原始比特
  1. 物理层把比特变成电信号、光信号或无线电信号。线路编码、调制属于它的手段，整层并不等于「数模转换」。
  2. 数据链路层把比特组成帧，用 MAC 标识同一条链路上的接口，并用帧校验序列做差错检测。以太网查出错误后丢弃该帧，并不负责纠错。
  3. 网络层按 IP 地址选路。路由器工作在这一层。
  4. 传输层用端口区分同一主机上的不同进程。TCP 提供面向连接的字节流，UDP 保留报文边界。两者的数据单位不能都叫「段」。
  5. 会话层不管端口、IP 或 MAC。端口属于传输层，IP 属于网络层，MAC 属于数据链路层，名字到地址的映射属于 DNS。
  6. 表示层在需要时做格式转换，例如一端用 EBCDIC、另一端用 ASCII。转换用的是双方约定的通用格式。
  7. 应用层最靠近用户，决定业务数据的含义。

和 TCP/IP 的对应

OSI TCP/IP 四层 常见协议
应用、表示、会话 应用层 HTTP、DNS、DHCP、FTP
传输 传输层 TCP、UDP
网络 网际层 IP、ICMP、OSPF
数据链路、物理 网络接口层 以太网、Wi-Fi、PPP

课堂上也常用五层模型：应用、传输、网络、数据链路、物理。会话层和表示层的功能并进应用层。看分层图时先确认是七层还是五层，避免把端口和 MAC 记串。

封装

发送方自顶向下加头部。

  1. 应用层产生数据；表示层按需编码或加密。
  2. 传输层加上 TCP 或 UDP 头，关键字段是源端口和目的端口。
  3. 网络层加上 IP 头，关键字段是源 IP 和目的 IP，得到分组。
  4. 数据链路层加上帧头尾。以太网帧头的关键字段是源 MAC 和目的 MAC，帧尾通常带校验。
  5. 物理层把帧变成信号送上介质。

路由器转发时拆掉入方向的帧头，按目的 IP 选路，再用出接口 MAC 和下一跳 MAC 重新封装。只有目的主机才会一路拆到应用数据。

解封装

  1. 物理层把信号还原成比特流。
  2. 目的主机核对本机 MAC、广播或需要接收的组播，校验通过后去掉帧头。交换机按 MAC 地址表转发，不是「目的 MAC 不是自己就丢弃」。
  3. 目的主机核对目的 IP，是自己才去掉 IP 头。路由器则继续转发。
  4. 传输层按端口交给对应套接字。TCP 还要按序号重组并确认。
  5. 应用层按协议解释字节，得到页面、文件或一条消息。

注意

  • 下层为上层提供服务，上层不关心介质是铜缆还是光纤。
  • 同一层的对等实体在逻辑上对话，比特实际只从物理层穿过介质。
  • ARP 直接装在帧里，作用却是把 IP 解析成 MAC。有的教材放在网络层，有的放在数据链路层，两种归类都要能对上它的功能。

一次访问网页时各层加上什么

浏览器要打开 http://192.0.2.10/。应用层产生 HTTP 请求。传输层加上目的端口 80 和临时源端口。网络层加上对方 IP 和自己的 IP。若对方在同一网段，数据链路层 ARP 出对方 MAC；若不在，目的 MAC 是网关。物理层把这一帧变成信号。

回来的路径相反：先核对 MAC，再核对 IP，再按端口交给浏览器那个套接字。中间的路由器只改链路层帧头，不拆 TCP，也不理解 HTTP。

注意

  • 会话层不分配端口。把「端口用来建立会话」写进会话层，是把传输层的工作上移了。
  • 表示层的格式转换现在大多由应用自己做，例如 JSON 和 TLS。模型里仍给它留一层，是为了说明「编码」不等于「业务」。
  • 物理层不保证比特无差错。差错检测从数据链路层的帧校验开始。

单位对照

物理层是比特，链路层是帧，网络层是分组，TCP 是报文段，UDP 是数据报。把 IP 包叫成报文，和把端口写进会话层，是同一类错层。路由器转发时更换帧头，不把分组拆到 HTTP。交换机看 MAC，不是「目的 MAC 不是自己就丢弃」。

应用层产生业务数据，表示层负责编码和加密的位置，会话层负责会话和检查点。端口不在这三层分配。TCP/IP 四层把这三层合成应用层，所以 HTTP 既可以说在 OSI 第七层，也可以说在 TCP/IP 的应用层，不要因此把它说成传输层。

同一层对等实体在逻辑上对话，比特只从物理层穿过介质。下层提供服务，上层不关心介质是电还是光。模型用来对齐概念，网上跑的协议栈是 TCP/IP。
