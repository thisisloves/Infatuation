不畏浮云遮望眼，自缘身在最高层。

用元素嵌入音视频

  • HTML 用 <video>、<audio> 播放媒体。能不能播，取决于浏览器是否支持该容器和编码，以及有没有给出对应的 <source>。
  • 开始、结束标签之间的文字是旧浏览器的后备内容。支持媒体元素的浏览器不会显示这段文字。

video

  • controls 显示控件。不加的话页面上只有画面，用户无法暂停，除非自己用脚本补按钮。
  • poster 在第一帧就绪前显示封面。preload 取 none、metadata 或 auto，只是建议，浏览器可以按省流量策略忽略。
  • playsinline 让 iOS 在页面内播放，否则可能强制全屏。
  • 多个 <source> 按书写顺序挑第一份能播的。type 写 MIME（可带 codecs），浏览器就能跳过明显不支持的文件，避免先下载再失败。
  • <track> 的 kind 有 subtitles、captions、descriptions、chapters、metadata。字幕文件用 WebVTT。default 表示默认打开这一条。

audio

  • MP3 的类型是 audio/mpeg，Ogg 是 audio/ogg，WAV 常见 audio/wav。类型写错时，浏览器可能直接跳过这份资源。

自动播放

  • 带声音的 autoplay 会被多数浏览器拒绝。静音自动播放（autoplay muted）通常允许，用户有过手势之后再 play() 更稳妥。
  • loop 循环。广告式自动播放还应提供明显的暂停方式，controls 或自己的按钮都行。

脚本：HTMLMediaElement

方法 行为
load() 重新选择资源并回到初始状态
play() 播放，返回 Promise；策略拒绝时 reject
pause() 暂停
canPlayType(type) 返回 ""、"maybe" 或 "probably"，空字符串表示不支持
  • 常用属性：currentTime、duration（元数据未到时是 NaN）、paused、ended、volume（0 到 1）、muted、playbackRate、buffered、readyState。
  • 常用事件：loadedmetadata、canplay、play、pause、timeupdate、ended、error。timeupdate 频率不稳定，进度条可以听它，精确计时不要假设固定间隔。
  • error 之后看 media.error.code：1 用户中止，2 网络，3 解码，4 源不合适。
  • 把视频画进 canvas 时，跨域资源要在元素上加 crossorigin="anonymous"，服务器也要回 CORS 头，否则画布被污染，toDataURL 会失败。

常见坑

  • 只有画面没有声音时，先查编码：MP4 容器里的视频常用 H.264，音频常用 AAC。只有视频编码对、音频编码不对，就会静音或整段失败。
  • width 和 height 同时写，能在元数据到达前留出比例，减少布局跳动。只写 CSS 宽度时，用 aspect-ratio 或 height: auto 配合固有比例。
  • <source> 写在脚本已经调用 load() 之后才插入，需要再调一次 load() 才会重新挑选。
  • 完整成员以 MDN：HTMLMediaElement 为准。

轨道与多份资源

  • codecs 写进 type 后，canPlayType 才有机会返回 probably。只写 video/mp4 时，很多浏览器只回答 maybe，仍可能下载后才发现编码不对。
  • 一份 kind="captions" 给听不到声音的人看台词，subtitles 给听得见但语言不同的人看翻译。需要默认打开时加 default，多条 default 时浏览器只采用其中一条。
  • WebVTT 的时间轴用 00:00:01.000 --> 00:00:04.000。文件编码用 UTF-8，第一行是 WEBVTT。

脚本里改地址

  • 直接改 src 会丢弃 <source> 列表里的其它候选。要换一组多格式资源，改每个 source 的 src 再调用 load()。
  • playbackRate 设为 1.5 是 1.5 倍速，Pitch 是否跟着变由浏览器决定。直播流常常不允许随意 seek，currentTime 写上去会被拉回可播区间。
