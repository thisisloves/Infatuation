Git 框架

2018-09-16
  • Git
本文总阅读量次

梦里过客笑眼望，望回廊，秋螽藏，人世短，人间长。

Git 是什么

  • Git 是分布式版本控制系统，由 Linus Torvalds 为 Linux 内核协作设计。每个克隆都带有完整对象库，断网时仍可提交、分支、查看历史，再与远程同步。
  • 集中式工具（如 Subversion）的许多操作要往返中央服务器。Git 的远程仓库是协作枢纽，本地仓库本身就是一份完整历史。

提交里存的是什么

  • 对象按内容哈希寻址，默认算法是 SHA-1（40 位十六进制）。使用 SHA-256 的仓库则是 64 位。改一个字节，哈希就变。
  • 四类对象：
    1. blob：文件内容，不含文件名。
    2. tree：某一层目录，记下名称、模式和子对象哈希。
    3. commit：指向一棵根 tree，并记下父提交、作者、说明。
    4. tag：给某个提交起的固定名字，可带说明和签名。
  • 逻辑上每次提交是一棵完整快照。内容相同的文件只存一份 blob。打包（pack）时再对相似对象做增量压缩，所以磁盘上并不是「每个版本一份完整拷贝」。
  • 分支是指向某次提交的可移动引用。新建分支几乎只是多写一个指针，因此创建和切换都很快。HEAD 通常指向当前分支名，分离 HEAD 时直接指向某次提交。

本地三层

  • 工作流分成三层：工作区（正在编辑的文件）→ 暂存区（索引，下一次提交要收录的快照）→ 版本库（.git 里的对象与引用）。

层 常见命令
工作区 → 暂存区 git add、git restore --staged
暂存区 → 版本库 git commit
版本库 → 工作区 / 暂存区 git switch、git restore、git reset
与远程交换 git fetch、git push
  • git status 同时比较这三层：未暂存的改动、已暂存的改动、未跟踪的文件。
  • 远程跟踪分支（如 origin/main）是上次 fetch 时远程分支的位置，存在本地 .git 里，不等于远程服务器此刻的最新提交。

和 SVN 的差别

  1. 架构：Git 克隆即完整仓库；SVN 工作副本依赖中央库完成日志、分支等操作。
  2. 存储：Git 是内容寻址对象；SVN 工作副本旁常见 .svn 元数据。
  3. 分支：Git 分支是轻量指针。SVN 里分支通常是版本库中的一条目录拷贝，成本和语义都不同。
  4. 版本号：SVN 有全局递增的 revision。Git 用哈希标识提交，在本仓库内稳定，短哈希只要不冲突即可使用。
  5. 完整性：取对象时按哈希校验，传输或磁盘损坏更容易被发现。

常见坑

  • 提交说明、作者和父提交都算进 commit 哈希。同样的文件树，父提交不同就是另一次提交。cherry-pick 因此会生成新哈希。
  • 索引里记的是 blob 哈希和路径。git add 之后再改工作区，暂存的仍是 add 那一刻的内容，需要再 add 一次。
  • .gitignore 只阻止未跟踪文件进入暂存区。已经跟踪的文件改名规则后，要用 git rm --cached 停止跟踪。
  • 裸仓库（--bare）没有工作区，适合当中央远程。普通克隆里的 .git 才是对象库，删掉它就只剩工作区文件，历史不在文件本身里。

从一次提交往回看

  • git cat-file -t <哈希> 能看出对象是 blob、tree 还是 commit。git cat-file -p <哈希> 打印内容。日常不必手动拆对象，但排错时能分清「文件内容变了」还是「只是改名、tree 变了」。
  • git rev-parse HEAD 打印当前提交的完整哈希。HEAD~1 是父提交，HEAD^2 是合并提交的第二父提交。~ 沿第一父提交往上数，^ 用来选第几个父提交。

引用存在哪

引用 位置
分支 .git/refs/heads/
标签 .git/refs/tags/
远程跟踪分支 .git/refs/remotes/origin/
HEAD .git/HEAD，内容多半是 ref: refs/heads/main
  • 这些文件里只放哈希或指向另一条引用。对象本体在 .git/objects。打包之后松散对象会收进 pack，引用仍然指向同一个哈希。
  • git switch 改的是 HEAD 指向哪条分支，并按那次提交的 tree 更新工作区和暂存区。未提交的修改若与目标 tree 冲突，切换会停下来，避免盖掉工作区。

三条命令各自动哪一层

  • git commit 不扫描工作区里还没 add 的修改。索引里是什么，这次提交就是什么。
  • 远程在第四层。git push 把本地已有的对象和分支指针送到远程，不负责把工作区里没提交的修改也送出去。
  • 对象写进库之后，分支和标签只是指向它的名字。删掉分支不会立刻删掉提交；还有别的引用或 reflog 指着它时，历史还在。
  • git gc 才会在引用过期之后回收不可达对象。刚 reset 掉的提交，短时间内仍能用 git reflog 找回。
