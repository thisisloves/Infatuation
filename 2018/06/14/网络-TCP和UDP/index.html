TCP 提供什么

TCP（Transmission Control Protocol）是传输层协议，面向连接，提供可靠、有序的字节流。它在两个端点之间工作，不负责替中间路由器选路。可靠性来自序号、确认、重传和校验，不是因为「经过了三次握手」这一句话本身。

TCP 如何保证可靠

  1. 按接收窗口和 MSS 把字节流分段，接收端按序号重组。分片大小由双方协商，不是只由发送方单方面决定。
  2. 接收端用确认号告诉对方：此序号之前的连续字节已经收到。
  3. 发送端为未确认数据维护重传定时器。超时仍未确认就重传。
  4. 滑动窗口做流量控制。接收端通告自己还能收多少，发送端不能超出这个窗口，避免快的一方灌满慢的一方。
  5. IP 不保证顺序，TCP 用序号重排后才交给应用。
  6. 重复的报文段按序号丢弃。
  7. TCP 对头部和数据计算端到端校验和。校验失败则丢弃且不确认，交给对端超时重传。

连接只在两个端点上维护。中间设备转发的是 IP 分组，不必理解这条 TCP 连接，除非它是做连接跟踪的防火墙或 NAT。

拥塞控制

慢启动阈值记作 ssthresh，不是「阐值」。拥塞窗口记作 cwnd。

阶段 发生什么
慢启动 初始 cwnd 很小。每收到一个对新数据的 ACK，cwnd 大约增加一个 MSS，每个 RTT 近似翻倍
拥塞避免 cwnd 超过 ssthresh 后，每个 RTT 大约只增加一个 MSS，改为线性增长
超时 ssthresh 设为当前窗口的一半，cwnd 降为 1 个 MSS，重新慢启动
快速重传 收到三个重复 ACK，认为该序号丢失，立即重传，不等待 RTO
快速恢复 快速重传后不回到 cwnd = 1。Reno 把 ssthresh 设为 cwnd/2，cwnd 设为 ssthresh + 3，随后进入拥塞避免

收到三个重复 ACK 时进入快速恢复，用的是 cwnd，不是不存在的 ewnd。超时和三个重复 ACK 是两条不同的恢复路径，不能都写成「重新慢启动」。

三次握手

TCP 用三次握手建立连接，避免过期的连接请求把双方带进一条并不存在的会话。流量控制用的是滑动窗口，和握手是两件事。

  1. 客户端发送 SYN，序号为 x，进入 SYN_SENT。状态名是 SYN_SENT，不是 SYN_SEND。
  2. 服务器回 SYN + ACK。序号为 y，确认号为 x + 1，进入 SYN_RCVD。
  3. 客户端回 ACK，确认号为 y + 1，进入 ESTABLISHED。服务器收到这个 ACK 后也进入 ESTABLISHED。

第三次之前，服务器还不能把这条连接交给应用。双方的初始序号独立选择，确认号总是「期望收到的下一个序号」。

四次挥手

TCP 全双工，每个方向要单独关闭，所以正常释放是四次挥手。

  1. 主动关闭方发送 FIN，表示本方向没有更多数据，进入 FIN_WAIT_1。
  2. 被动方确认这个 FIN，进入 CLOSE_WAIT。主动方收到 ACK 后进入 FIN_WAIT_2。应用若还有数据，仍可从被动方向主动方发送。
  3. 被动方的应用关闭套接字，再发送自己的 FIN，进入 LAST_ACK。
  4. 主动方确认这个 FIN，进入 TIME_WAIT，等待 2MSL 后彻底关闭。被动方收到最后的 ACK 后进入 CLOSED。

TIME_WAIT 保证最后的 ACK 丢失时还能重传，并让旧连接的迟到报文从网络中消失。主动关闭的一端才会进入 TIME_WAIT。若被动方在确认对方 FIN 时自己也没有数据了，ACK 可以和 FIN 放在同一个报文段里，线上就可能只看到三段。

UDP

UDP 在 IP 之上提供无连接的数据报。头部只有源端口、目的端口、长度和校验和，共 8 字节；TCP 头部至少 20 字节。应用一次写入的报文，UDP 既不合并也不拆开，边界由应用自己保持。IPv4 中 UDP 校验和可以是 0，表示不校验；IPv6 中必须校验。

UDP 没有拥塞窗口，发送速率由应用、带宽和主机处理能力决定。网络差时丢包不会被 UDP 自动重传。实时音视频、DNS 查询、DHCP 常用它。早期一些即时通信以 UDP 为主，现在的产品经常是 UDP、TCP 和 QUIC 混用，不能再说「聊天软件就是 UDP」。

TCP 与 UDP

TCP UDP
连接 握手后通信 不建立连接
可靠性 确认、重传、按序 尽最大努力，不确认
数据形态 字节流，无消息边界 数据报，保留边界
传输方式 单播 单播、组播、广播
头部 至少 20 字节 8 字节
拥塞控制 有 无

TCP 的「可靠」指字节最终按序交给应用，或由应用得知连接失败。它不承诺时延，也不代替应用层的业务确认。

状态名

握手用 SYN_SENT 和 SYN_RCVD，不是 SYN_SEND、SYN_RECV。挥手的主动方在发出最后一个 ACK 后进入 TIME_WAIT，时长约两个 MSL。这段时间里同一四元组不能马上重用，是为了让旧报文消失，不是因为实现「反应慢」。

拥塞窗口的变量是 cwnd。三个重复 ACK 之后进入快速恢复时，ssthresh 取当前窗口的一半，cwnd 设为 ssthresh 加 3 个报文段，不要写成不存在的 ewnd。超时则把 cwnd 降回 1 个报文段再慢启动，两条路径不要合成一句「丢失就慢启动」。

UDP 头部固定 8 字节，没有序号和窗口。应用若需要可靠，就得自己做确认，或者改用 TCP、QUIC。

半关闭

主动方的 FIN 只表示自己不再发送，对端仍可以继续送数据，直到它也发送 FIN。所以正常关闭是四次，而不是把握手的三次倒过来。最后的 ACK 丢失时，TIME_WAIT 里的主动方还能重传。被动方进入 CLOSED，不等待 2MSL。

慢启动阶段每收到一个确认，拥塞窗口大约增加一个 MSS，一个往返里近似翻倍。超过 ssthresh 后每个往返大约只加一个 MSS。阈值的名字是 ssthresh，不是阐值。UDP 没有这套窗口，发送多快由应用决定，网络拥塞时它不会自己退让。
