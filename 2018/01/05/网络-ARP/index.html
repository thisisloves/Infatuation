网络 ARP

2018-01-05
  • 网络
本文总阅读量次

多少黄昏烟雨斜檐，翻开诗篇，勾起一纸江南。

ARP 解决什么

ARP（Address Resolution Protocol）把 IPv4 地址解析成同一条链路上的 MAC 地址。分组要装进帧才能发送，只知道下一跳 IP 不够。协议名是 ARP，不是 APR。

报文直接装在以太网帧里，类型是 0x0806。功能上它服务网络层，封装上它紧贴数据链路层。教材把它放进网络层或链路层都可以，只要说清「用 IP 找 MAC」。

同一网段

  1. 主机 A 先查 ARP 缓存。已经有 B 的 MAC，就直接封装帧。
  2. 没有表项时，A 广播 ARP 请求。帧的目的 MAC 是 FF:FF:FF:FF:FF:FF。请求里发送方 IP 和 MAC 是 A 的，目标 IP 是 B 的，目标 MAC 填 0。
  3. 只有 IP 等于目标 IP 的主机会回答。B 把 A 的映射写入自己的缓存，再单播 ARP 应答，里面带上 B 的 MAC。
  4. A 记下 B 的映射，把刚才等待的分组发出去。

同网段的其他主机看到请求可以学习 A 的地址，但只有 B 应该应答。

不同网段

A 发现 B 的 IP 不在本网段，解析的是网关的 MAC，不是 B 的 MAC。A 把帧交给网关，目的 IP 仍是 B。网关若没有 B 或下一跳的表项，就在出接口所在链路上再做一次 ARP，然后重新封装帧。源主机永远 ARP 不到远端主机，除非对方恰好在同一条二层上。

缓存

动态表项由报文学习而来，会老化，也能被新的报文更新。老化时间因系统而异：有的主机大约几十秒到数分钟，Windows 的可达表项最长可以到约 10 分钟量级。不能把某一种操作系统的 2 分钟、10 分钟写成协议规定。过期表项删除，不是「ARP 表现」被删除。

静态表项手工配置，不老化，动态学习不能覆盖它。它一直保留到被删除或设备重启。把网关做成静态映射，可以避免伪造的应答改掉网关 MAC。

免费 ARP 的发送方 IP 和目标 IP 都是自己。主机用它检测地址冲突，也会让链路上的其他设备更新缓存。

报文

字段 请求 应答
操作码 1 2
发送方 MAC / IP 自己的 自己的
目标 MAC 全 0 请求者的 MAC
目标 IP 想解析的 IP 请求者的 IP
以太网目的 广播 单播给请求者

RARP

RARP 用 MAC 反查 IP，请求和应答的操作码是 3 和 4。它要求网络里有 RARP 服务器，已经被 BOOTP 和 DHCP 取代。了解它是为了和 ARP 的方向对照，新网络不要再部署。

欺骗

ARP 没有认证。攻击者可以发送伪造的应答或免费 ARP，把「某 IP 对应的 MAC」改成自己的。

  1. 攻击者先从广播的请求里看到 A、B 的 IP 和 MAC。这是广播，不是交换网络里说的泛洪。
  2. 向 B 发送应答：发送方 IP 填 A，发送方 MAC 填攻击者自己。
  3. B 更新缓存后，发给 A 的帧会送到攻击者。
  4. 攻击者可以窥看、篡改后再转发给 A，形成中间人。只把缓存改成一个不存在的 MAC，则会造成断网，攻击者并不因此得到数据。

交换机学的是端口和 MAC 的关系，伪造的是主机缓存里 IP 和 MAC 的关系。两种表不是同一张。防御靠静态绑定、动态 ARP 检测（DAI）和把不可信端口隔离开，而不是把老化时间调长。

代理 ARP

路由器可以替「看起来不在本网段、但路由上能到」的主机回答 ARP。源主机掩码配得过短，以为对方在本地，就会 ARP 一个本不该本地解析的地址。路由器若开了代理 ARP，会用自己的 MAC 应答，再帮它转发。通信能通，但广播和「谁在本网段」的边界被掩盖了。排障时若看到远端 IP 的 MAC 等于网关 MAC，先检查掩码和代理 ARP，不要先断定对方伪造。

同一网段的时序

B 在应答前就学习了 A。因此即使 A 的第一条数据还在排队，B 稍后访问 A 也不必再广播一次。这个学习来自请求本身，不需要额外的协议。

注意

  • 免费 ARP 的目标 IP 等于发送方 IP。地址冲突时，已占用该地址的主机会看到「别人宣称拥有我的地址」。
  • 动态表项老化后，下一包会再次广播。把老化时间调到几小时，伪造的映射也会留几小时。
  • 跨 VLAN 必须先到网关。在 VLAN 10 里 ARP VLAN 20 的主机，正常情况下没有人应答。

静态表项做什么

动态表项谁最后应答就信谁，所以伪造的应答能改缓存。静态表项把「网关 IP 只能对应这个 MAC」写死，动态学习不能覆盖，直到管理员删除或设备重启。它不能防止攻击者伪造别人的表项，只能保护已经写死的那几条。

老化时间是实现细节。有的系统几十秒，有的可达数分钟。协议没有规定「2 分钟不用就删、最长 10 分钟」。把某家操作系统的数字写成标准，换一台设备就会对不上。

请求里的目标 MAC

以太网目的地址是广播。ARP 载荷里的目标 MAC 填 0，目标 IP 填想解析的地址。应答改为单播，操作码从 1 变成 2。协议名是 ARP。它装在帧里，用来为 IP 找 MAC，归到网络层或链路层都可以，只要不把它说成和 IP 路由是同一张表。

不同网段时，源主机 ARP 的是网关，不是远端主机。帧的目的 MAC 是网关，IP 的目的仍是远端。网关在出接口上再 ARP 下一跳。看到远端 IP 对应网关 MAC，可能是代理 ARP 或掩码配得过短，要先核对掩码，再怀疑欺骗。
