网络 DNS

本文总阅读量次

DNS 做什么

DNS（Domain Name System）是把域名和资源记录对应起来的分布式数据库。最常见的记录是 A 和 AAAA：域名到 IPv4、IPv6。PTR 做反向解析，CNAME 是别名，MX 指向邮件服务器，NS 指出谁是权威服务器。

查询通常用 UDP 53。响应过大被截断，或要做区域传送时，改用 TCP 53。一个标签最长 63 个字符，整个域名在线上不超过 255 个字节。

域名的层次

自右向左依次是根、顶级域、二级域，再往下是子域。

www.xxx.com 里，com 是顶级域，xxx 是二级域，www 是主机名或下一级标签。末尾的根点 . 存在，只是输入时可以省略。每一层都有自己的权威服务器。

递归和迭代

递归：被问的服务器负责追问下去，最后把最终答案或错误交还给查询方。

迭代：被问的服务器如果不是权威，就返回更接近答案的服务器地址，由查询方自己继续问。

常见分工是： stub 解析器向本地域名服务器做递归；本地域名服务器向根、顶级域和权威服务器做迭代。

一次完整查询

  1. 浏览器先查自己的 DNS 缓存。
  2. 未命中则交给操作系统的解析器。解析器会看 hosts 文件，也会查操作系统的 DNS 缓存。hosts 是管理员手写的静态映射，不是操作系统缓存本身。
  3. 仍未命中，则把查询发给配置好的本地域名服务器。本机到这一步一般是递归查询。
  4. 本地域名服务器缓存未命中时，开始迭代：向根要顶级域服务器，向顶级域要权威服务器，再向权威服务器要记录。权威服务器是 authoritative server，不是「权限服务器」。
  5. 本地域名服务器按 TTL 缓存答案，再返回给操作系统。
  6. 操作系统缓存后交给浏览器，浏览器再按自己的策略缓存。

缓存的是答案和 TTL，不是永久绑定。TTL 到期前可以不再向上游查询；到期后必须重新解析。权威数据变更后，旧缓存仍可能存活到 TTL 结束。

记录类型

类型 作用
A / AAAA 域名到 IPv4 / IPv6
CNAME 别名指向另一个域名，解析还要再查目标
MX 邮件交换，带优先级数字，越小越优先
NS 该区的权威服务器
PTR IP 到名字，用于反向区
TXT 任意文本，常用于 SPF、校验

注意

  • 递归服务器替客户端跑完整个流程；权威服务器只对自己的区给出肯定或否定答案。一台机器可以兼做两者，角色不要混。
  • 否定答案也可以被缓存。刚加上的新记录，有时要等负缓存过期才看得见。
  • DNS 查询默认不加密。解析器到递归服务器的路径上可以用 DoT 或 DoH，那是另外的传输，不改变上面的层次。

hosts、缓存、权威各看一次

权威服务器回答的 SOA 里带有负缓存时间。查一个不存在的名字，递归服务器会把「没有这个名字」缓存一段时间。刚创建的记录若落在这段时间里，会表现为时好时坏，直到负缓存过期。

注意

  • CNAME 不能和同名的 A、MX 等记录并存。别名要继续解析目标名字，多一次查询是正常的。
  • 递归服务器和权威服务器最好分开。把权威数据放在给客户用的递归服务器上，策略和缓存会缠在一起。
  • TTL 改成 60 秒可以加快切换，也让递归服务器的查询量上升。不是改完权威记录，全世界马上一致。

hosts 不是缓存

hosts 是静态文件，改完通常立刻生效。操作系统 DNS 缓存是以前查询留下的答案，带着 TTL。浏览器还有自己的一层。三处都未命中，才向递归服务器发起递归查询；递归服务器再向根、顶级域和权威服务器做迭代。权威服务器回答自己的区，不替客户跑完整个流程。

标签最长 63，整条域名在线上不超过 255 字节。www.xxx.com 里 com 是顶级域，xxx 是二级域，www 是再下一级。末尾的根点可以不输入。CNAME 要继续查目标，多一轮是正常现象。负缓存会让刚添加的名字暂时解析不到。

递归服务器可以缓存权威答案，缓存时间不超过 TTL。权威数据改了，旧答案仍可能留到 TTL 结束。把权威和递归放在同一台机器上，排障时角色容易看混。
