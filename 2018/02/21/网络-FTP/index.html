网络 FTP

2018-02-21
  • 网络
本文总阅读量次

其实这世上有很多事情不是你想就能做到的，总有些命运你无法逃避，总有些悲伤让你永远铭记。

FTP 是什么

FTP（File Transfer Protocol）用 TCP 传送文件，位于应用层。按 OSI 它在第七层；按四层 TCP/IP 模型，它也在应用层。它使用 TCP 而不是 UDP，因此控制连接和数据连接都要三次握手。协议用统一的命令在不同操作系统之间传送文件，不修改文件内容的业务含义。

一台服务器由监听新连接的主进程和负责单次传输的子进程组成，可以同时服务多个客户。

两条连接

连接 端口 传什么
控制连接 服务器 21 命令和应答，会话期间一直保持
数据连接 主动模式时服务器源端口 20 文件内容、目录列表

21 是命令端口，20 是主动模式下服务器的数据源端口。两者不能对调。被动模式下服务器的数据端口是临时端口，不再是 20。

  1. 服务器在 21 端口等待。
  2. 客户连上后，每项数据传输另开一条数据连接，传完即可关闭。
  3. 控制连接回到命令等待，可以继续接受同一客户的下一条命令。

目录列表也走数据连接。登录成功但列目录失败，通常是数据连接没建立，不是用户名错了。

主动模式

服务器从 20 端口连向客户事先用 PORT 给出的数据端口。

  1. 客户用临时端口 N（N > 1024）连接服务器的 21。
  2. 客户发送 PORT h1,h2,h3,h4,p1,p2。端口号是 p1 × 256 + p2，教材常写成 N+1，协议并不强制与 N 相邻。
  3. 服务器用源端口 20，主动连接客户公布的那个端口。
  4. 这条连接上传或下载数据。数据连接由服务器发起，客户不必再去连服务器的 20 端口。

主动模式要求客户侧允许服务器连进来。客户在 NAT 或防火墙后面时，这步经常失败。

被动模式

客户两条连接都由自己发起。

  1. 客户用端口 N 连接服务器 21，发送 PASV，不是发送 PORT。
  2. 服务器打开临时端口 P（P > 1024），用 227 应答告诉客户地址和端口，格式同样是 h1,h2,h3,h4,p1,p2。这是应答，不是一条 PORT 命令。
  3. 客户再开一条连接连到服务器的 P，开始传数据。
主动模式 被动模式
命令连接 客户连服务器 21 客户连服务器 21
谁公布数据端口 客户用 PORT 服务器用 227 应答
谁发起数据连接 服务器连客户 客户连服务器
服务器数据端口 20 临时端口 P
典型障碍 客户防火墙挡住入站 服务器要开放一段被动端口

IPv6 和复杂 NAT 下用 EPRT / EPSV，不再把地址拆成四个十进制字节。

命令、应答与传输类型

常见命令：USER、PASS、CWD、LIST、RETR（下载）、STOR（上传）、TYPE、PORT、PASV、QUIT。

应答第一位表示结果：1 初步成功，2 完成，3 还要后续命令，4 暂时失败，5 永久失败。227 是进入被动模式，150 是数据连接即将开始，226 是传输完成，530 是未登录。

这里要分开两套词：

  • TYPE 是表示类型。A 是 ASCII，两端转换行结束符（CR LF 与 LF）。I 是二进制，按字节原样传送。图片、压缩包和程序必须用 I；用 ASCII 传它们会损坏。
  • MODE 是传输模式。现网几乎都是流模式 S。块模式、压缩模式很少见，不要把 MODE 和 TYPE 当成同一件事。

注意

  • 控制连接上的用户名和口令在传统 FTP 里是明文。FTPS 是在 FTP 上加 TLS（显式一般仍走 21，隐式常见 990）。SFTP 是 SSH 的文件传输子系统，不是 FTP 的被动模式。
  • 主动模式和被动模式可以在同一台服务器上同时支持，由客户发的是 PORT 还是 PASV 决定。
  • 匿名 FTP 只是用约定用户名 anonymous，链路该加密时仍然没有加密。

被动模式下载时控制连接上看到什么

文件字节不走 21 端口。227 应答里的端口要还原：7 × 256 + 138 = 1930，客户接着连的是这个高端口，不是 20。

客户在 NAT 后面时用被动模式，两条连接都由客户向外发起。服务器应把被动端口限制在一段，防火墙上只放行 21 和这一段。列目录也走数据连接，所以登录成功但 LIST 失败，多半是数据连接没建立，不是用户名错了。
