JS 原型和原型链

2019-12-23
  • JS
本文总阅读量次

人生若只如初见，何须感伤离别。

概念

JavaScript 的对象通过原型委托复用属性。class 只是构造函数和原型的语法，底层仍是这条链，不是另一套类型系统。

多数函数有 prototype。用 new 调用时，新对象的内部槽 [[Prototype]] 指向这个 prototype。读属性时先看对象自身，没有再沿 [[Prototype]] 走，直到 null。Object.prototype 的原型是 null，它是普通对象链的尽头，不是「所有值包括数字和 null 的终点」。原始值没有属性，读 'a'.length 时才会临时装箱。

__proto__ 是访问 [[Prototype]] 的历史写法。读用 Object.getPrototypeOf，设对象的原型用 Object.create 或 Object.setPrototypeOf（后者会影响优化，初始化时一次设好即可）。

箭头函数没有 prototype，也不能 new。typeof 的结果是小写 "function" / "object"，没有 "Function" 或 "Objetct"。

正确示例

实例上找不到 prototype 属性，那是函数上的。实例通过原型链使用 Person.prototype 上的方法，所以方法只存一份。写在构造函数里的 this.fn = function(){} 是每个实例一份。

constructor 只是原型上的普通属性，指向函数。替换整个 prototype 对象时，要自己把 constructor 指回去，否则 person.constructor 会变成 Object。

常见坑

  • console.log(aa) 在 aa 未声明时直接 ReferenceError，演示变量应使用已经赋值的 a。
  • new Function('1') 的类型是 "function"。函数体 '1' 只是一条表达式语句，不会返回字符串 "1" 的类型。
  • 原型方法写成 function () { '文本'; } 不会打印，字符串被求值后丢掉。要输出就 console.log。
  • 「每个对象都有 __proto__，每个函数都有 prototype」漏了 Object.create(null) 和箭头函数。
  • 沿原型找到 Object.prototype 仍没有该属性时，结果是 undefined，不会抛错。调用 undefined() 才会抛。
  • 在原型上放对象或数组时，所有实例共享那一个引用。一个实例 push，其他实例都能看到。状态放实例自身，方法放原型。
  • 原型链是委托，不是把父类属性拷贝到子对象上。hasOwn 为假的属性仍然可以读到。

属性怎么被找到

读取 person.say 的顺序是：自身属性，然后 Person.prototype，然后 Object.prototype，然后 null。赋值 person.say = fn 只会在自身建数据属性，不会去改原型上的 say。要改所有实例看到的方法，必须改 Person.prototype.say。

in 和 for...in 会看到原型链上可枚举的键。Object.hasOwn(person, 'say') 为假，但 'say' in person 为真。拷贝键时用 Object.keys 或 Object.entries，否则把原型方法也拷进了新对象。

instanceof 走的就是这条链：person instanceof Person 为真，因为 Person.prototype 出现在链上。把 Person.prototype 换成另一个对象后，旧实例的 instanceof 会变成假。Object.create(null) 的实例不是 instanceof Object。

覆盖原型对象时记得补回 constructor，并在替换前定义好方法。先 new、后改 prototype 的话，已经创建的实例仍指向旧原型。

小结

new 把新对象的原型设为构造函数的 prototype，查找沿这条链走到 null。读原型用 Object.getPrototypeOf。箭头函数没有 prototype，共享的方法才放上原型，可变的数据不要放。
