JS this

2019-10-18
  • JS

浮云吹作雪，世味煮成茶。

概念

this 是函数执行时的一个绑定，由调用方式决定，不是由函数写在哪个对象旁边决定，也不是闭包自动捕获的变量。箭头函数没有自己的 this，沿词法环境使用外层的那个。

调用方式 this
对象方法 obj.fn() obj
普通函数直接 fn() 非严格模式是全局对象；严格模式和模块里是 undefined
new Fn() 新对象
fn.call(obj) / apply / bind 你传入的对象
DOM 监听里的普通函数 当前元素 currentTarget
箭头函数 定义处外层的 this

new 的步骤是：创建对象，把它的 [[Prototype]] 设为构造函数的 prototype，用这个对象调用构造函数，若构造函数返回对象则用返回值，否则用新对象。并不是「自动调用 apply」这一个 API。

顶层 this 只在经典浏览器脚本里等于 window。模块顶层是 undefined。

常见坑

  • 第一段经典例子里，内层函数打印出全局名字，是因为它被 getNameFunc()() 这样单独调用，不是因为闭包「把 this 带到了全局」。闭包捕获的是 that 这种变量；默认的 this 不走作用域链。
  • 浏览器里全局 var name 会写到 window.name，而 window.name 只能是字符串，还可能影响窗口名。演示 this 时换一个属性名。
  • 箭头函数做 addEventListener 回调时，this 不是按钮。需要元素就用 event.currentTarget，或写普通函数。
  • bind 之后再用 call 改不掉已经绑定的 this。new 绑定函数时，this 仍是新对象。
  • 解构或中转方法会丢掉调用点：const fn = obj.info; fn() 不再指向 obj。回调传给 setTimeout 时同样如此，除非改成箭头函数或预先 bind。

箭头函数和监听

箭头函数不看调用点。作为对象方法时，this 也不是那个对象，而是定义箭头函数时外层的 this：

事件监听同理。需要「点到的那个元素」时，写普通函数，或读 event.currentTarget。currentTarget 只在监听执行期间有值，异步回调里再读已经是 null，要先存下来。

bind 返回的新函数和原函数不是同一个引用。removeEventListener 必须拿到 bind 的那一次返回值。多次 bind 不会叠加 this，以第一次为准。call 和 apply 立即调用，bind 不调用。

类的方法若从对象上拆下来当回调，严格模式下 this 是 undefined。类字段箭头函数 onClick = () => {} 会在每个实例上生成函数，词法 this 是实例，适合传给子组件，但不要再放到原型上指望共享。

小结

看调用点，不看定义位置。方法调用指向接收者，单独调用在严格模式下是 undefined，new 指向新对象。箭头函数使用外层 this。bind 的额外参数是逐个绑定，和 apply 的数组不同。
