JS 事件

2019-10-27
  • JS
本文总阅读量次

负你白头共老对影成孤，弃你红尘万丈自叹何苦。

概念

事件是浏览器在文档或窗口上发出的通知：用户点击、键盘输入、资源加载完成、历史变化等。JavaScript 通过监听函数和 DOM 交互。注册方式以 addEventListener 为准，可以绑多个监听，并能选择捕获阶段。

onclick = fn 只能留一个函数，再次赋值会覆盖。attachEvent 是旧 IE 接口，现在不用。

回调收到的是 Event 对象（或子类）。target 是实际触发的节点，currentTarget 是当前监听所在的节点。鼠标、键盘事件还带坐标和按键信息。

正确示例

鼠标（会冒泡的用在委托上；mouseenter / mouseleave 不冒泡）：

事件 时机
click / dblclick 点击 / 双击主键
mousedown / mouseup 按下 / 松开
mousemove 在元素上移动
mouseover / mouseout 进入 / 离开（含子孙，会冒泡）
mouseenter / mouseleave 进入 / 离开自身范围，不冒泡

键盘：用 keydown / keyup，读 event.key 或 event.code。keypress 已废弃，而且只覆盖部分字符键。keyCode、which 也已废弃。

文档与表单：

事件 时机
DOMContentLoaded HTML 解析完，不等图片
load 窗口及其资源加载完；也可用于 img
pagehide / visibilitychange 页面离开或被隐藏。unload 不可靠，且会妨碍往返缓存
input 值正在变化
change 提交一次变更。文本框多在失焦后；勾选框、<select> 往往立即触发
focus / blur 得到 / 失去焦点，不冒泡
focusin / focusout 同上，但会冒泡
submit / reset 表单提交 / 重置，可 preventDefault
scroll / resize 滚动 / 窗口尺寸变化。默认不冒泡的滚动要绑在具体元素上

常见坑

  • focus、blur、mouseenter、mouseleave、多数 scroll 不能靠父节点冒泡监听到，委托要换事件或改捕获。
  • change 不是「任意输入立刻触发」。实时搜索用 input。
  • load 绑在 window 上时，脚本若放在页面底部且用了 defer，监听可能晚于事件。需要尽早执行时改听 DOMContentLoaded，或把脚本放对位置。
  • 监听器里的 this：普通函数指向当前元素；箭头函数没有自己的 this，沿外层词法去找。
  • return false 只在旧的 onclick 属性写法里同时阻止默认行为和冒泡。addEventListener 里它没有这个效果，要显式 preventDefault / stopPropagation。

委托和默认行为

父元素上的一个监听就能处理后来插入的子节点，这是冒泡的直接用途。回调里用 event.target.closest 找到真正要处理的子元素，用 currentTarget 确认边界。

preventDefault 只取消浏览器默认动作，事件仍会继续传播。return false 在 addEventListener 里没有「既阻止默认又停止冒泡」的含义，那是旧的 DOM0 onclick = function(){ return false } 的行为。两者不要混用。

这样普通点击不跳转，用户按住修饰键仍可打开新标签。无条件 preventDefault 会破坏这个习惯。

once: true 的监听执行一次后自动卸掉。passive: true 向浏览器保证不会 preventDefault，适合滚动和触摸，能减少卡顿。需要取消滚动的监听不能标成 passive，调用 preventDefault 会被忽略并在控制台警告。

监听选项对象可以同时写捕获、只执行一次和被动：

once 执行后不用再 removeEventListener。滚动监听用 { passive: true }，浏览器知道你不会取消滚动。同一元素上后加的冒泡监听，仍会在目标阶段按注册顺序参加；祖先要等冒泡才轮到。卸掉监听时，选项里的 capture 必须和添加时一致。

小结

用 addEventListener 注册，用 key 而不是 keypress / keyCode。分清冒泡与不冒泡、input 与 change、target 与 currentTarget。页面卸载不要依赖 unload。
