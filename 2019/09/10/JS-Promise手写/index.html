概念

Promise 表示一次异步结果。状态只有三种：pending、fulfilled、rejected。从 pending 出发只能变一次，之后 resolve / reject 再调用都无效。

then(onFulfilled, onRejected) 始终返回新的 Promise，回调里的返回值决定它的结果，抛错则拒绝。规范要求回调以微任务异步执行，即使当时已经完成，也不能在 then 里同步调用。这样当时写在 then 后面的同步代码一定会先跑完。

resolve(x) 若 x 是 thenable，要跟随它的状态，而不是把 Promise 对象当成成功值。onFulfilled 不是函数时，成功值原样传到下一环；onRejected 不是函数时，拒绝原因继续往下抛。否则 .then().then(ok, err) 这种穿透无法实现。

静态 Promise.resolve / reject / all / race / allSettled 可以在这个核心上再补，状态机本身不依赖它们。

常见坑

  • 只在 pending 时 push 回调、完成后再同步调用 onFulfilled，无法链式 then，也无法保证「then 永远异步」。
  • resolve(anotherPromise) 若不展开，后面的 then 收到的是 Promise 而不是它的值。
  • 没判断 onRejected 是否为函数，拒绝后调用 undefined(...) 会抛错，错误进不了下一层 catch。
  • 执行器里同步抛错必须变成拒绝，否则 Promise 永远 pending。
  • then 的回调若再返回自己，规范要求拒绝 TypeError。上面的最小实现没写循环检测，生产 polyfill 才需要。

小结

状态只变一次，then 返回新 Promise，回调放进微任务队列。resolve 要展开 thenable，回调缺省时要穿透值或原因。同步执行 then 的手写版本和浏览器行为对不上。
