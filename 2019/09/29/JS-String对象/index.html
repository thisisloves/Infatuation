JS String 对象

  • JS
本文总阅读量次

春挽冬留独自悲，日月星辰几轮回，花间媚影谁留恋？待看红尘谁伴随？

概念

字符串原始值是不可变的 UTF-16 码元序列。字面量 'sakura' 的类型是 string。new String('sakura') 得到对象包装，typeof 是 object，和原始值用 === 比较为 false。日常只用字面量；调用方法时，引擎会临时装箱，用完即弃。

常用实例方法：

方法 作用
at(i) / charAt(i) 取字符；at 支持负索引
charCodeAt / codePointAt UTF-16 码元 / Unicode 码位
includes / startsWith / endsWith 是否包含、以前缀或后缀开始
indexOf / lastIndexOf 首次 / 末次出现的下标，没有则 -1
slice(start, end) 截取，支持负索引，不改原串
substring(a, b) 截取；会把负参数当成 0，并交换倒置的端点
split / concat 拆成数组 / 拼接（更常用 + 或模板字符串）
replace / replaceAll 替换。replace 配普通字符串或非 g 正则只换第一处
match / matchAll 匹配；matchAll 需要带 g 的正则
trim / trimStart / trimEnd 去掉两端或单侧空白
padStart / padEnd / repeat 补齐、重复
toLowerCase / toUpperCase 大小写。土耳其语等要用 toLocale*

String.fromCharCode、String.fromCodePoint、String.raw 是静态方法，不能当成某个字符串的方法来记。

substr(start, length) 是遗留语法，已从标准正文移除，用 slice。

lastIndexOf 是从后往前找，返回的下标仍从 0 起算，不是从末尾倒着编号。

常见坑

  • 字符串按下标赋值无效：'ab'[0] = 'z' 在非严格模式静默失败，严格模式抛 TypeError。要新串就用拼接或 slice。
  • length 和 charAt 数的是 UTF-16 码元。一个 emoji 可能占 2 个长度，for...of 和 Array.from(str) 按码位迭代才不会把代理对拆开。
  • slice 与 substring 对负数的处理不同，不要混用。
  • 没有 g 的 replace 只替换第一处。replaceAll 的第一个参数若是正则，必须带 g，否则抛错。
  • == 会把 new String('a') 转成原始值再比较，所以 new String('a') == 'a' 为真，=== 为假。
  • localeCompare 才适合排序人名；> 比的是码元，中文顺序不一定符合词典。

截取和比较

slice 允许负索引，-1 是最后一个码元。substring 会把负值当成 0，并且若第一个参数大于第二个会交换。迁移旧的 substr(start, length) 时，正索引可写成 slice(start, start + length)；start 为负时 substr 从末尾数，和 slice 的负索引接近，但长度语义不同，要逐个核对。

比较排序用 localeCompare，不要用 > 决定中文顺序。拆开代理对后再拼回去可能得到非法 UTF-16，for...of 给出的是完整码位。padStart 的填充按码元计算长度，用 emoji 填充时视觉宽度和 length 不一致。

new String 几乎只在需要给某一个字符串挂属性时才出现。JSON 和 DOM 属性要的都是原始字符串，包装对象会被转成 "[object Object]" 或触发额外的 toString。

小结

优先使用原始字符串。截取用 slice，全量替换用 replaceAll 或带 g 的正则，码位用 codePointAt / fromCodePoint。fromCharCode 是 String 上的静态方法，substr 不要再用。
