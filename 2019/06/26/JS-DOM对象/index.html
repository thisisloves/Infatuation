JS DOM 对象

2019-06-26
  • JS
本文总阅读量次

初闻不知曲中意、再听已是曲中人。

概念

浏览器解析 HTML 后建立文档树，这就是 DOM。脚本通过 document 查找节点、改属性、改结构和监听事件，从而更新页面。CSS 样式由 CSSOM 参与计算，改 style 或 class 会触发后续的布局或绘制。

查找：

API 返回
getElementById 元素或 null
getElementsByClassName / TagName / Name 实时的 HTMLCollection，不是数组
querySelector 第一个匹配元素或 null
querySelectorAll 静态 NodeList，不是数组

querySelector 属于 Selectors API，不是「ES5 新增的语法」。getElementsByName 按 name 属性找，不是标签选择器。

集合没有 map 时用 Array.from(list)。实时集合在你增删节点时长度会变，遍历同时改 DOM 要特别小心；querySelectorAll 的结果是当时的快照。

正确示例

class 属性在 IDL 上叫 className，因为 class 曾是保留字。classList 比整段替换 className 不容易把别的类名抹掉。自定义属性用 getAttribute / setAttribute，或 data-* 配 dataset。

关系：

没有 fristElementChild、nextElementSibing 这两个拼写，读它们得到 undefined。

textContent 按文本插入，不会把字符串当 HTML 解析。用户输入不要放进 innerHTML。

常见坑

  • console.log('auser') 打印的是这几个字母，不是节点。变量不要加引号。
  • children[2] 在子元素不足三个时是 undefined，接着访问属性会抛错。
  • 先 querySelector('.list').remove()，再对同一个选择器 removeChild，第二次已经是 null。
  • getElementsByTagName 的结果是实时的。循环里 appendChild 到同一集合对应的父节点，可能死循环。
  • 两段互不共享的脚本里，后一段注释写「id 已经是 heheh」并不成立，除非真的先执行过赋值。
  • outerHTML 赋值会用新节点替换旧节点，原来拿着的引用不再在树上，随后再改旧引用的 id 页面无变化。

创建和改动

createElement 得到的节点在插入文档前不会显示，也不会触发布局。先设好 textContent 和属性，再 append，比插进去再改几次便宜。

innerHTML 会解析 HTML，也能执行字符串里的脚本以外的标记（事件属性在赋值时不会像内联脚本那样全部跑起来，但仍能构造意外结构）。用户数据只用 textContent。insertAdjacentHTML 同样解析 HTML。

删除用 node.remove()。旧写法 parent.removeChild(node) 要求 node 确实是这个父节点的子节点，否则抛错。替换整段标记用 replaceWith 或 outerHTML，替换后原来的 JS 引用脱离文档。

matches、closest 用来从事件目标往上找，比手写 parentNode 循环少出错。选择器写错时 querySelector 抛 SyntaxError，不是返回 null。

querySelector 找不到时返回 null，接着读属性会抛错。集合长度为 0 时下标是 undefined，同样要先判断。

getElementById 全文档只应有一个该 id。重复 id 时它返回文档顺序中的第一个，后面的节点要用别的方式找。改类名优先 classList，整段替换 className 会抹掉同时存在的其他类。

小结

getElementById 得一个节点，getElements* 得实时集合，querySelectorAll 得静态 NodeList。类名用 classList，兄弟用 nextElementSibling。用户内容用 textContent，节点卸掉之后不要再沿旧引用改树。
