JS Blob 对象

2019-06-07
  • JS
本文总阅读量次

世界上有两万人会与你一见钟情，但你这辈子可能一个也遇不到，与其说是一见钟情，不如说是命运。

概念

Blob 表示一段不可变的二进制数据，名字来自 Binary Large Object。它不负责打开磁盘路径，只在内存里保存字节和 MIME。File 是 Blob 的子类，多了 name 和 lastModified。

parts 里可以是字符串、ArrayBuffer、TypedArray 或其他 Blob。字符串按 UTF-8 计入 size。type 默认空字符串，全部转成小写。

实例只有 size、type，以及不改原对象的 slice(start, end, contentType)。end 不包含在内。不传 contentType 时，新 Blob 的类型是空字符串，不会继承原来的 MIME。

URL.createObjectURL(blob) 生成的是 blob: URL，形如 blob:https://example.com/<uuid>，不是 blob://，也不是把数据嵌进地址的 data: URL。它只在当前文档里有效，用完调用 URL.revokeObjectURL。

常见坑

  • 把协议写成 blob:// 或 data://。data: URL 自带内容；blob: 只是一个指向内存对象的键。对象被回收或 revoke 之后，这个地址失效。
  • slice 第三个参数省略时类型变空，上传时服务端可能认不出文件。需要类型就显式传入 blob.type。
  • File.lastModifiedDate 已废弃。Blob 本身没有修改时间，时间在 File.lastModified 上。
  • <input type="file"> 的值不能由脚本设成某个路径，只能由用户选择。选中后得到的是 FileList。
  • 大文件用 readAsDataURL 会在 JS 堆里再放一份 Base64。预览和下载用对象 URL 即可。
  • createObjectURL 不调用 revokeObjectURL，即使用户已经离开预览界面，这份 Blob 仍可能被 URL 拽住。

和文件、下载

File 可以直接传给任何收 Blob 的 API。若只要其中一段字节，file.slice(start, end, file.type) 得到新的 Blob，原文件不动。end 是开区间，和数组的 slice 一样。

触发下载时，对象 URL 赋给 <a download> 再点击。文件名以 download 属性和 File.name 为准，Blob 自己没有文件名，不传名字时浏览器可能保存成 download 或 UUID。

fetch 的 res.blob() 在状态码 404 时也会给出一个 Blob，那是错误页的正文。先看 res.ok。把 Blob 交给 URL.createObjectURL 之后，只要 URL 还活着，这块内存就不会被回收。

类型和字节长度

字符串按 UTF-8 计算 size。中文一个字通常是 3 个字节，和 string.length 的码元数不同：

type 会被转成小写，空类型是 ''。slice 不传第三个参数时，新 Blob 的类型变成空字符串，上传前要写回原来的 type，否则服务端只看到一段无名二进制。

createObjectURL 生成的地址以 blob: 开头，后面是源和 UUID。把它放进 <img src> 或 <a href> 都能用，但不能当成可以发给另一台电脑的永久链接。文档关闭或 revokeObjectURL 之后再请求，资源就不在了。同一 Blob 可以创建多个 URL，每个都要单独释放。

小结

Blob 是带 MIME 的不可变字节块，File 是它的子类。截取用 slice，临时地址用 blob: 而不是 blob://，读内容优先 blob.text() / arrayBuffer()，URL 用完就释放。
