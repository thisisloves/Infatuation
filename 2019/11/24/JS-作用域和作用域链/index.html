JS 作用域和作用域链

2019-11-24
  • JS
本文总阅读量次

朝朝暮，云雨定何如，花日穿窗梅小小，雪风洒雨柳疏疏，人唱晚晴初。

概念

作用域是标识符（变量、函数、类）的可见范围，在代码写下来时就确定，称为词法作用域。运行时去哪一层找名字，不取决于函数在哪被调用。

常见层次：

  1. 全局作用域：经典脚本里 var 和函数声明会挂到全局对象（浏览器是 window）。ES Module 有自己的模块作用域，顶层 var 不会变成 window 属性。
  2. 函数作用域：var、函数声明、arguments 属于整个函数，能穿透内部的 {}。
  3. 块级作用域：let、const、class 只在声明所在的块（{}、for 的括号）内可见。

作用域链是内部词法环境的外层引用串起来的链表。查找从使用处所在的最内层开始，找不到就沿外层走，直到全局；再没有就抛出 ReferenceError。不是「去创建这个变量的那个函数里取值」——变量只在声明它的作用域里创建一次，内层函数是顺着链去读它。

bar 写在 fn 里面，bar 的外层就是 fn 的环境，和 bar 将来在哪被调用无关。不同作用域的同名绑定互不影响。

正确示例

暂时性死区：let / const 会提升到块顶，但在声明语句执行前访问会抛错，不是「没有提升」。

常见坑

  • JavaScript 没有 global 关键字。那是 PHP。浏览器全局对象是 window（或 globalThis），Node 里是 global 这个名字，不是语法关键字。
  • 「window 上的内置属性都拥有全局作用域」不准确。alert 是全局对象的方法；模块里的顶层绑定、块里的 let 都不是它的属性。
  • var 没有块级作用域。在 if / for 里写 var，整个函数都能看到，循环变量会被闭包共享。
  • 赋值给未声明的名字，在非严格模式会变成全局属性；严格模式和模块里直接 ReferenceError。
  • catch (e)、函数参数、import 各自有独立环境。eval 和 with 会动态改作用域，严格模式禁用 with，不要用它们组织代码。
  • 作用域链决定能不能看见名字；this 由调用方式决定，不在这条链上。箭头函数没有自己的 this，沿词法环境去找外层的 this。

和闭包、提升

内层函数被返回后，仍然沿着定义时的链找到外层的 let。调用发生在全局并不把查找起点改成全局。这就是闭包能留下私有变量的原因。

var 的作用域是函数，声明会提升到函数顶，块拦不住。let 的作用域是块，提升到块顶但处于暂时性死区。两者都不是「从调用栈往下找同名参数」。

catch 的参数、函数的形参也是独立环境。形参和函数体里的 let 同名是语法错误；和 var 同名则会共享绑定，看起来像赋值被提升搅乱。模块每个文件一个作用域，顶层名字要被别的文件看见必须 export，不会因为同名就串到另一个文件。

模块各自一个作用域。A 文件的顶层 const name 不会和 B 文件冲突，要共享就 export / import。经典脚本里省略声明的赋值会变成全局属性，模块里同一行直接 ReferenceError。

查找从使用处的块开始，然后函数，然后模块或全局。调用栈不参与决定这条链。

小结

作用域在书写时确定。查找从使用处向外，而不是从调用处向内。var 是函数作用域，let / const 是块级作用域并存在暂时性死区。模块顶层不再等于 window。
