JS 事件冒泡

2019-11-05
  • JS
本文总阅读量次

山下梅子酒，十里故清欢。

概念

事件流描述同一个事件经过哪些节点。网景当年走捕获（从外到内），IE 走冒泡（从内到外）。DOM 标准把两者都留下，顺序固定：

  1. 捕获：window → document → <html> → … → 目标的父节点。
  2. 目标：在被点中的节点上调用监听。
  3. 冒泡：目标的父节点 → … → window。

addEventListener(type, fn, true) 在捕获阶段调用，false 或不传在冒泡阶段调用。IE8 及更早的 attachEvent 只有冒泡。IE9 起支持标准监听。

点中的是嵌套最里面的那个节点（事件目标），不是视觉上含糊的「最上层父盒子」。祖先比目标更靠外。

不是每个事件都冒泡。focus / blur 不冒泡，对应的 focusin / focusout 才冒泡。

常见坑

  • HTML 里用 <script> 开头却不再用 </script> 收尾，后面的脚本会被吃进字符串，监听没有注册。
  • onclick = 只能保留一个函数，后写的覆盖先写的。多个监听用 addEventListener。
  • 在内层 stopPropagation 之后说「不再向下」。冒泡的方向是向祖先，也就是向外、向上走 DOM。
  • 委托绑在父节点上时，子节点一停冒泡，父节点就收不到。
  • 目标节点上同时有捕获和冒泡监听时，按注册顺序调用，不要以为目标上还会严格分成两段。
  • stopPropagation 不阻止默认行为。链接仍会跳转，除非再 preventDefault。

捕获和目标阶段

同一个节点可以同时有捕获和冒泡监听。祖先上的捕获一定先于目标，目标一定先于祖先的冒泡。在目标上，两个监听按添加顺序执行，第三参数不再把它们拆成两趟。

点击 div3 时，这两句的先后取决于注册顺序，不要写成「目标上一定先跑完所有 true」。

stopPropagation 写在目标的第一个监听里，后面同节点的监听仍会执行，祖先不再执行。连同节点的其他监听一起停掉，用 stopImmediatePropagation。两者都不取消默认动作，链接的跳转、表单提交还要 preventDefault。

不冒泡的事件没有第三段。focus 绑在父元素上，焦点进入子输入框时父元素收不到。换成 focusin，或在捕获阶段听 focus。滚动事件绑在真正滚动的那个盒子上，不要假设会冒泡到 window；window 的 scroll 只表示视口在滚。

小结

先捕获后冒泡，起点包含 window。点击内层节点，冒泡向外层父节点走。stopPropagation 切断后续传播，但不代替 preventDefault，也不必为了「成对」而去 removeEventListener。
