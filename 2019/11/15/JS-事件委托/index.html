JS 事件委托

2019-11-15
  • JS
本文总阅读量次

故里有长安，长安归故里。

概念

事件委托是把监听注册在祖先节点上，利用事件流在回调里辨认真正的 event.target，从而处理一批现有或将来才出现的子节点。

事件传播分三段：

  1. 捕获：从 window 经 document、<html> 走到目标的父节点。addEventListener(type, fn, true) 的监听在此阶段执行。
  2. 目标：在 event.target 上按注册顺序调用监听。对目标自己而言，第三个参数并不分成「先捕获、后冒泡」两趟。
  3. 冒泡：从目标的父节点走回 window。第三个参数为 false（默认）的监听在此阶段执行。

捕获阶段会执行捕获监听。说「捕获阶段不会响应任何事件」是错的。委托通常用冒泡，因为子节点先成为目标，事件再经过父节点。不冒泡的事件（focus、blur、mouseenter、多数元素上的 scroll）不能用冒泡委托，可以改听 focusin，或在捕获阶段听。

target 是点中的节点，currentTarget 是绑了监听的那个祖先。

常见坑

  • HTML 里 element.nodeName 是大写 'LI'，XML 或 SVG 不一定。用 closest 或 matches 比写死标签名稳。
  • stopPropagation 会让祖先收不到事件，委托随之失效。组件库里随手停掉冒泡，外面的委托就哑了。
  • 一个父节点上只有一个监听，内存开销通常小于一万个子节点各绑一个。现代引擎对监听数量并不那么敏感；委托更重要的收益是动态节点不用重复绑定，而不是「杜绝循环引用内存泄漏」。旧 IE 的循环引用泄漏不能套到当前浏览器上。
  • attachEvent / detachEvent 只存在于已淘汰的 IE，this 和事件模型都和标准不同，不要写进新代码。
  • 若子节点自己调用了 stopImmediatePropagation，同级和祖先的监听都不会再跑。

什么时候不该委托

列表项里如果有按钮和复选框，一个父级 click 里要用 closest 分清点的是按钮还是行，避免点按钮时把整行逻辑也跑一遍。若按钮调用了 stopPropagation，父级委托收不到，这时把行点击和按钮点击分成两个监听，按钮不要去停父级需要的事件。

mouseenter 不冒泡，移入列表项不会通知 ul。移入移出用会冒泡的 mouseover / mouseout，并在回调里比较 relatedTarget，忽略在子元素之间移动造成的抖动。焦点委托用 focusin。

一次点击只会有一个 target。若列表项被禁用或被透明层盖住，target 是那层遮罩，closest('li') 得到 null，回调应直接返回，而不是把遮罩当成条目。

动态行用父节点的一个监听即可。点到按钮内部的图标时，target 是图标，closest('button') 才能找回按钮。找不到就 return，避免把表格空白处当成一次删除。

小结

委托 = 祖先监听 + 事件流 + 辨认 target。捕获监听在捕获阶段就会执行。优先 addEventListener 和 closest，并确认所用事件确实会冒泡。
