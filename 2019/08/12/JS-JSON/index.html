概念

JSON 是一种文本格式，不是 JavaScript 里的一种对象类型。JSON.parse 把文本变成 JS 的对象、数组、数字、字符串、布尔或 null；JSON.stringify 反过来。解析结果就是普通数据，叫它「JSON 对象」容易让人以为还有一个单独的 JSON 类。

语法比 JS 对象字面量严：

  • 键必须是双引号字符串，不能单引号，不能无引号。
  • 不能有注释、尾逗号、undefined、函数、Symbol。
  • 数字不能是 NaN 或 Infinity（序列化时会变成 null）。

stringify 的第二参数可做白名单或替换函数，第三参数是缩进。parse 的第二参数是 reviver，适合把日期字符串还原成 Date。

常见坑

  • JSON.parse 对空字符串、undefined、单引号文本抛 SyntaxError。接口可能返回 HTML 错误页，要 try/catch，不要假设正文一定是 JSON。
  • stringify 会丢掉函数、undefined 的属性、Symbol 键。数组里的 undefined 和函数变成 null，对象里的这些属性直接消失。两者不一致。
  • 循环引用会抛 TypeError。带父子指针的树不能直接序列化。
  • toJSON 若存在，会被 stringify 调用。Date 因此变成字符串。
  • 键的顺序在现代引擎里是插入序，但 JSON 规范不保证顺序，不要用键序表达业务含义。
  • uniqueBy(list, 'device_Name') 只看名字。三条设备同名时只留下第一条，device_Id 不同也会被丢掉。去重键要选稳定且唯一的字段。
  • 大整数超过 Number.MAX_SAFE_INTEGER 时，parse 会丢精度。雪花 ID 应让接口用字符串。

替换和缩进

stringify 的第二个参数可以是数组，只保留这些键；也可以是函数，返回 undefined 就丢掉该属性。第三个参数是美化用的空格数，最大有效值 10。

键必须能变成字符串。Symbol 键会被忽略，数字键会变成 "1" 这种字符串，和对象字面量一样。不要把 JSON.parse 用在用户能控制、且你准备 eval 的内容上——parse 本身不执行函数，这是它比 eval 安全的原因；解析之后再把字段拼进 HTML 仍可能造成 XSS，那是输出问题，不是 JSON 的问题。

大整数 ID 用字符串传输。一旦被 parse 成 Number，超过 2 ** 53 - 1 的部分就回不来了。

小结

JSON 是文本。parse / stringify 只覆盖一套纯数据，函数和 undefined 保不住，Date 会变成字符串。解析要捕获异常，去重是数组运算，和 JSON 类型无关。
