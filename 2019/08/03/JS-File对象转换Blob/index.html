JS File 与 Blob

概念

Blob（Binary Large Object）表示一段不可变的二进制数据，带有 size（字节数）和 type（MIME）。File 继承 Blob，额外有 name、lastModified，所以 File 本身就是 Blob，能传给 FormData、URL.createObjectURL、FileReader 的地方，File 可以直接用。

需要「转换」的场景通常是：

  • 改 MIME、改文件名，或只取文件的一段字节
  • 把字符串、ArrayBuffer、Canvas 导出成 Blob 再上传
  • antd Upload 的 fileList 项不是原始 File，真正的文件在 originFileObj

File 不能改内容。要得到新数据，用 Blob / File 构造函数或 slice() 生成新对象。

createObjectURL 的协议是 blob:（形如 blob:https://example.com/uuid），不是 blob://。用完应 revokeObjectURL，避免占着内存。

常见坑

  • beforeUpload 返回 false 只阻止上传组件自己发请求，不会把 File 变成 Blob。readAsText 得到的是字符串。
  • FormData.append(name, file) 时，File 会带上文件名；普通 Blob 没有名字，第三个参数要自己传文件名，否则服务端可能拿到默认名 blob。
  • antd 的 file 是包装对象。把整个包装对象 append 进去，上传的不是文件内容。
  • slice 的结束下标不包含在结果里，和 String.prototype.slice 一样。省略 MIME 时，新 Blob 的 type 是空字符串，不会自动沿用原文件类型。
  • FileReader.readAsBinaryString 已废弃。要字节用 readAsArrayBuffer，要预览用 readAsDataURL。
  • 同一份大文件反复 readAsDataURL 会把内容扩成 Base64 字符串，体积约增三分之一。能用 Blob URL 就不要转成 Data URL。

截取、改名、预览

只要文件的前一段，或换一个 MIME，用 slice，不要先读成字符串再 new Blob，大文件会在内存里放两份。

File 放进 FormData 时第三个参数可以覆盖文件名。antd Upload 的列表项要取 originFileObj；beforeUpload 返回 false 只是不让组件自己上传，文件仍要你交给 FormData 或 fetch。

预览用 URL.createObjectURL，协议是 blob:。组件卸载或 <img> 的 load 之后 revokeObjectURL。把 File 读成 Data URL 再塞进状态管理，等于把整个文件的 Base64 放进 JS 堆，列表一长页面就会抖。

多个文件对应多次 append('screen_file', blob, name)，业务 id 这种普通字段只 append 一次，不要放进 forEach 里重复追加。

小结

File 是带文件名的 Blob，赋值和 append 都不用先转换。要改类型、截取或从内存数据落地，再用 slice、new Blob、new File。临时 URL 用 blob:，用完释放。
