JS Date 对象

概念

Date 表示时间轴上的一个瞬间，内部是距 Unix 纪元（1970-01-01T00:00:00Z）的毫秒数。本地的年月日通过运行环境的时区换算。没有「无时区的日历日期」这个独立类型，只格式化日期时要注意换算。

月份是 0 到 11。new Date(2018, 1, 1) 是本地时区的 2 月 1 日，不是 1 月。getDay() 是星期，0 表示星期日；月中的一天用 getDate()。

Date.parse 和 Date.UTC 是静态方法，挂在实例表里容易误用。getYear / setYear / toGMTString 已废弃，用 getFullYear、setFullYear、toUTCString。解析日期字符串的实现差异很大，不要依赖 new Date('2019-4-29') 这种非 ISO 写法。可靠的交换格式是 toISOString()。

定时器不属于 Date，但常一起用：

  • setTimeout(fn, ms) 至少等待 ms 后执行一次，返回 id，用 clearTimeout 取消。
  • setInterval(fn, ms) 重复执行，用 clearInterval 取消。两者的 id 不要交叉清除。

延时不是精确闹钟。页面在后台时浏览器会降频，嵌套的 setTimeout(fn, 0) 也可能被拉到数毫秒。

常见坑

  • 方法名是 getMilliseconds，没有 getMillisecondes。拼错会抛 TypeError。
  • setInterval(function()){ 多了一个括号，函数表达式不合法。
  • 延时示例若写成 setInterval 再用 clearTimeout，类型对不上，间隔不会按你的意思停。成对使用。
  • setMonth(12) 会进到下一年 1 月，超出的日、月会进位，而不是自动钳制。
  • 本地午夜减去时区后，toISOString().slice(0, 10) 可能变成前一天。服务端若按 UTC 的日期字段存储，要用同一套时区解释。
  • Date.now() 是毫秒时间戳，比 new Date().getTime() 短，也不产生临时对象。

时区和运算

两个日期相减得到毫秒数。比较先后用时间戳，不要比较 toString() 的本地格式，那种字符串随语言变化。

86400000 是 24 小时，不是「当地的一天」。跨夏令时的地区，本地日历可能是 23 或 25 小时。只处理公历日期时，用年月日数字增减，而不是加固定毫秒。

toLocaleString('zh-CN', { hour12: false, timeZone: 'Asia/Shanghai' }) 把时区说清楚。不传 timeZone 时用的是用户电脑的时区，同一条 ISO 时间在不同机器上显示的钟点不同，这是预期行为。

无效日期的 getTime() 是 NaN，new Date('not-a-date').toISOString() 会抛 RangeError。解析失败要先判断 Number.isNaN(d.getTime())。月份进位是特性：setDate(0) 会落到上个月最后一天，用来求上月末可以，不要误当成「设成 0 号还停在本月」。

小结

月份从 0 起，星期日是 0，毫秒方法只有一个 s。废弃的 getYear 不要用。setTimeout 配 clearTimeout，setInterval 配 clearInterval，解析日期只用 ISO 字符串或分开传入数字。
