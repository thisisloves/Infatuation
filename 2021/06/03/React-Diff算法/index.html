React Diff 算法

2021-06-03
  • React
本文总阅读量次

三世风尘仆仆，愿吾安于禅心。

它不是两棵树的通用最短编辑

任意两棵树的最小编辑距离是 O(n³) 量级，React 不做这个。它用三条启发式，把日常更新压到接近 O(n)：

  1. 只比较 同一层 的兄弟，不跨层移动。
  2. 类型不同就拆掉整棵子树再新建。
  3. 同一层用 key 识别哪个节点是移动，哪个是新建。

跨层移动在界面上很少见。若真的把一棵子树从 A 的孩子变成 B 的孩子，React 会在旧位置删除、在新位置创建，状态会丢。这是策略，不是漏实现。

类型不同：整枝替换

div 换成 span，或 UserList 换成 ProductList，key 即便相同也不会复用。旧 Fiber 标删除，新 Fiber 标插入，子树状态全部重置。

想保留状态，就保持组件类型稳定，把变化放进 props，而不是在父级用条件表达式切换两个不同类型的组件。条件切换时，把状态提升，或把 key 设成同一个稳定值并保证类型不变。反过来，若希望重置状态（例如换了一条用户记录的表单），主动改变 key。

同一层列表：key

没有 key 时，React 按索引复用。只在末尾追加，这样是对的。在头部插入或排序时，索引复用会把后面每个节点都看成「props 变了」，并且把错误的 state 留在原来的索引上。

key 要在 兄弟之间 稳定且唯一。用数组下标做 key，排序和插入时等于没有 key。用 Math.random() 或渲染时才生成的 id，等于每次都是新节点，状态和 DOM 都会重建。

单节点和多节点

只有一个子元素时，比 type 和 key。相同则更新 props；不同则卸载旧的、挂载新的。

多个子元素时，React 先从左到右扫一遍，尽量处理「没移动」的前缀。剩下的旧节点放进以 key 为索引的 map，再按新 children 的 key 去取。取到就是移动或更新，取不到就是插入。旧 map 里剩下的删除。移动与否用 lastPlacedIndex 判断：新序列里某个旧节点的旧索引如果比已经放置过的最大索引还小，说明它要往右挪，标上 Placement。

这是单层算法，不会为了最少 DOM 操作去搜索跨层方案。

和 memo 的分工

Diff 决定节点是复用、移动还是替换。memo 决定函数组件要不要重新执行。即便子组件重新执行，宿主节点的属性对比仍可能发现 className、文本都没变，从而跳过 DOM 写入。优化时先保证 key 正确，再考虑 memo，否则会把错误的复用缓存下来。
