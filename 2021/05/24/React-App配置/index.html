官方脚手架现在是 Vite 或框架

Create React App 已不再是推荐的新项目起点，官方长期维护的是 Next.js 等框架，以及 Vite 这类构建工具。已有 CRA 项目可以继续用，新项目不必再 eject。

入口使用并发根：

StrictMode 在开发环境会双调用渲染和效果，用来发现不纯的渲染和漏掉的清理。生产构建不会双调用。不要为了消掉开发期的双请求而删掉它。

环境变量

Vite 只把 VITE_ 前缀的变量暴露给客户端，读取用 import.meta.env.VITE_API。CRA 是 REACT_APP_ 和 process.env.REACT_APP_API。不要把密钥放进任何前端环境变量，打包后谁都能看到。

.env、.env.local、.env.production 按构建工具的规则加载。改 env 后要重启开发服务器。

开发服务器代理

前后端分离时，开发期把 /api 代理到后端，避免浏览器跨域。Vite：

生产环境由网关或同源部署处理，不要把开发代理当成生产方案。

路径与 JSX

保持 jsx 自动运行时（React 17+ 的默认）。ESLint 使用 eslint-plugin-react-hooks，打开 exhaustive-deps。列表 key、依赖数组这些错误靠它比靠肉眼稳。

生产构建 npm run build 产出静态文件。路由若用 BrowserRouter，服务器要把未知路径回落到 index.html，否则刷新子路径会 404。

和 React 版本对齐

react 与 react-dom 版本保持一致。React 18 的入口是 react-dom/client，不要只升级 react 而继续用已经弃用的 ReactDOM.render，否则没有自动批处理和过渡的并发行为。类型包是 @types/react 与 @types/react-dom，大版本和运行时对齐。
