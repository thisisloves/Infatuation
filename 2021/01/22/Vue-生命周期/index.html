Vue 生命周期

2021-01-22
  • Vue
本文总阅读量次

浮生不若梦，孤影照惊鸿。

实例从创建到卸载

生命周期是组件实例的一条固定时间线：初始化选项、把数据变成响应式、编译模板、挂到 DOM、数据变化时更新、最后卸载并清理。下面按 Vue 2 选项式 API 的钩子说明。图中的 beforeDestroy / destroyed 就是 Vue 2 的名字。

这些钩子不要用箭头函数，否则没有组件 this。

beforeCreate 与 created

beforeCreate：实例刚建好，data、methods、watch、事件都还不可用。

created：数据观测、计算属性、方法、侦听器已经配好。可以发请求、读取路由参数。此时还没有 DOM，$el 还不能用来量尺寸或聚焦。服务端渲染也会走到 created，所以纯数据的初始化可以放这里。

beforeMount 与 mounted

beforeMount：模板已经编译成渲染函数，尚未把结果挂到页面上。服务端渲染不会调用它。

mounted：初始 DOM 已经生成。若根实例挂到了文档中的元素上，此时 vm.$el 也在文档里。可以读取布局、初始化依赖 DOM 的第三方库。

mounted 不保证所有子组件都已挂载完成。要等整棵子树渲染完，使用：

子组件的 mounted 先于父组件的 mounted。父组件 mounted 里可以认为子组件已经挂载过。服务端渲染不会调用 mounted。不要在这里改会触发同步渲染的数据，以免多一轮更新；需要改数据时放到 created。

beforeUpdate 与 updated

数据变化后、DOM 重新渲染前调用 beforeUpdate。这时读 DOM 得到的是旧界面。

updated 在 DOM 更新之后。它不保证所有子组件也都 updated 完，需要的话在里面再 $nextTick。

不要在 updated 里无条件改数据，否则会循环更新。服务端渲染不会调用这两个钩子。

beforeDestroy 与 destroyed

beforeDestroy：实例仍完整可用。在这里清除定时器、取消请求、解绑自己加到 window 上的事件、销毁第三方实例。

destroyed：侦听器、子实例和事件监听都已移除。再读数据或操作 DOM 已经不合适。

Vue 3 把这两个钩子改名为 beforeUnmount、unmounted，调用时机对应。旧名字在 Vue 3 中不会执行。

keep-alive 多出来的钩子

被缓存的组件不会走销毁。离开时调用 deactivated，再次进入时调用 activated。首次进入的顺序是 mounted 然后 activated。详情见《Vue 页面缓存》。

错误钩子

errorCaptured(err, vm, info) 捕获子孙组件渲染、侦听器、生命周期里的错误。返回 false 可以阻止继续向上传播。Vue 3 还有全局 app.config.errorHandler。

父子顺序

挂载：父 beforeCreate → 父 created → 父 beforeMount → 子 beforeCreate … 子 mounted → 父 mounted。

更新：父 beforeUpdate → 子 beforeUpdate → 子 updated → 父 updated。

销毁：父 beforeDestroy → 子 beforeDestroy → 子 destroyed → 父 destroyed。

Vue 3 组合式 API

<script setup> 里没有 beforeCreate / created，这两段时机就是 setup 本身，顶层代码会在二者之前执行。其余钩子从 vue 引入，名字前加 on：

Vue 2 选项 Vue 3 组合式
beforeMount onBeforeMount
mounted onMounted
beforeUpdate onBeforeUpdate
updated onUpdated
beforeDestroy onBeforeUnmount
destroyed onUnmounted
activated / deactivated onActivated / onDeactivated
errorCaptured onErrorCaptured

Vue 3 的 setup 在 beforeCreate 之前执行。选项式 API 若同时写了 setup 和 created，先跑 setup。

请求放哪

不依赖 DOM 的请求放 created（或 setup 顶层）。依赖 DOM 的初始化放 mounted。离开页面必须取消的订阅放 beforeDestroy（Vue 3 是 onBeforeUnmount）。被 keep-alive 缓存的页面，每次进入都要刷新时放 activated，并避免和 created 各请求一次造成首次双发。
