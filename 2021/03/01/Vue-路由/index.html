前端路由改的是视图

单页应用里，切换「页面」通常不向服务器要下一张完整 HTML，而是由前端换成另一个组件。vue-router 负责：URL 与组件的对应、历史记录、导航钩子。

先分清两个对象：

  • $router：路由器实例，用来 push、replace、go。
  • $route：当前路由记录，上面有 path、params、query、name、meta、matched。

hash 模式

URL 里 # 后面的部分不会发给服务器。http://music.163.com/#/friend 请求的路径仍是 /。改变 hash 会触发 hashchange，浏览器前进后退也能回到旧 hash，因此不会整页刷新。

hash 模式部署简单，静态服务器只托管 index.html 即可。代价是地址里有 #，且服务器端看不到 # 后面的路径，做服务端日志和部分 SEO 时不方便。

history 模式

地址栏没有 #，依赖 History API 的 pushState 和 replaceState。这两次调用不会发请求。用户点前进后退触发 popstate。

用户刷新或直接打开 https://www.example.com/book/1 时，浏览器会向服务器请求 /book/1。服务器如果没有这个文件、也没有回退到 index.html，就会 404。所以要在 Nginx、静态托管或服务端把前端路由都指回 index.html，再由 vue-router 接管。

pushState 可以带一个 state 对象，它存在会话历史里，容量有限。刷新当前这条历史时，浏览器通常还能读到 history.state，但新开标签、复制链接给别人都不会带上它。业务参数应放在路径或查询串里，不要塞进 history state 当数据仓库。

Vue Router 4 的内存历史是 createMemoryHistory()，对应 Vue Router 3 的 mode: 'abstract'，用于测试和非浏览器环境。

路由表

动态段 :id 进入 params。子路由路径不以 / 开头时，会拼在父路径后面，页面上要再放一个 <router-view> 给子组件。

Vue Router 4 捕获全部路径的写法是 /:pathMatch(.*)*。Vue Router 3 写 * 或 /*。把 Vue 2 的 path: '*' 原样拿去 Vue Router 4 会匹配失败。

命名视图用 components（复数）对应多个 <router-view name="side">。

声明式与编程式导航

push 压入一条历史，replace 替换当前条，用户点后退不会回到替换前的地址。对同一个路由再 push 一次，Vue Router 3 可能报 NavigationDuplicated，可捕获这个失败，或在跳前比较目标。Vue Router 4 对重复导航的失败做了忽略处理。

router-link 默认渲染 <a>。当前匹配项会加上 router-link-active。完全匹配（路径一致）再加 router-link-exact-active。自定义类名用 active-class 和 exact-active-class。

滚动

Vue Router 4 里选择器字段是 el，坐标是 left / top，不再使用 selector、x、y。返回值可以是 Promise，用来等过渡结束再滚。

安装

主版本要配对：Vue Router 3 配 Vue 2，Vue Router 4 配 Vue 3。createRouter 不能装进 Vue 2。
