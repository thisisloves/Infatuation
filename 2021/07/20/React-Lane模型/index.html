React Lane 模型

2021-07-20
  • React
本文总阅读量次

若问相思何处歇，相逢便是相思澈。

为什么不用一个数字

React 16 的并发实验用 expirationTime：一个数字，越大越急。它不好表示「这几件更新优先级相同，应该一批做完」，也不好做集合运算。React 17 改成 Lane：用 31 位二进制，每一位是一条车道。位运算就能完成合并、排除和求最高优先级。

赛道这个比喻仍然成立：越靠内圈越短、越优先；相邻几条可以视为同一档，用来容纳被打断后积压的更新。低优先级更容易被打断，所以分到的位数更多。同步更新几乎不会积压，一条 SyncLane 就够。

React 17 的位图已经过期

旧稿里的 SyncBatchedLane、InputDiscreteHydrationLane、InputDiscreteLanes 属于 React 17。React 18 稳定版拿掉了这两组：离散交互（点击等）多数进入 SyncLane，连续输入单独留下 InputContinuousLane，普通更新收成一条 DefaultLane，过渡更新扩成 16 条。把 17 的常量抄进 18 的源码对不上。

下面是 React 18.2 ReactFiberLane 的布局。这是内部实现，19 以后位数还会调，应用不要写死这些掩码。

TransitionLanes 是 bit 6 到 bit 21，共 16 条。RetryLanes 是 bit 22 到 bit 26，共 5 条，给 Suspense 重试。OffscreenLane 占最高位，给屏幕外的子树（例如隐藏的 tab），不是口头说的「离屏渲染优先级」。

更新落在哪条车道

概念上的对应（随小版本会微调，用来建立直觉）：

  • flushSync、legacy 同步渲染、需要立刻提交的离散更新：SyncLane，workLoopSync，不让出。
  • mousemove、滚动、拖拽这类连续事件：InputContinuousLane。
  • setTimeout、Promise 里的普通 setState：DefaultLane。React 18 会把同一轮里的多次更新批到一起，但车道仍是 Default，不是 Sync。
  • startTransition、useDeferredValue：TransitionLane。可被 Sync 打断，被打断的过渡下次换一条过渡车道重做，所以需要多位。
  • 空闲、离屏：IdleLane、OffscreenLane。

根上的 pendingLanes 是集合。本次渲染选出一个子集 renderLanes。WIP 树上每个 Fiber 的 lanes / childLanes 记录「这棵子树还有哪些车道没处理」。子树车道为 0 就可以跳过（bailout）。

和 Scheduler 优先级的关系

Scheduler 的五档（Immediate 到 Idle）决定宏任务何时到期、时间片怎么排。Lane 决定协调器里哪些 Fiber 参加这一轮 render。进入 Reconciler 之前会做一次映射：例如过渡车道对应较低的 Scheduler 优先级，同步车道对应 Immediate，几乎马上占用主线程。

批处理不是车道本身

React 18 的自动批处理是「同一事件或同一任务里的多次 setState 合成一次渲染」。Lane 是「这次渲染有多急、能不能被打断」。两件事同时存在：超时里的两次 setState 会批到同一个 Default 渲染；startTransition 里的更新则是另一条更低的车道，可以被点击打断。详见《React 组件状态》。
