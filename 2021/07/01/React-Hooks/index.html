React Hooks

2021-07-01
  • React
本文总阅读量次

我们用零距离的爱，弹奏一曲琴韵笙箫，将生命畅想成天籁之音。

Hooks 是什么

Hooks 从 React 16.8 起稳定。它们让函数组件拥有状态、副作用和 context，而不必写成类。类组件仍然支持，没有被删除。

引入 Hooks 的直接原因是复用带状态的逻辑。高阶组件和 render props 能复用，但会多出一层组件、让数据和来源变远。自定义 Hook 只是一个调用了其他 Hook 的函数，没有额外的树节点。this 的绑定、生命周期里副作用和渲染缠在一起，是类组件里更常见的成本。把动机说成「类不利于 tree shaking」，并不是设计文档里的原因。

调用规则

  1. 只在函数组件或其他自定义 Hook 的 顶层 调用。不要放进条件、循环、try/catch 或嵌套函数。
  2. 不要在普通函数、类组件、事件回调里调用。
  3. 自定义 Hook 必须以 use 开头。这既是约定，也是 eslint 插件识别 Hook 的依据。

React 用调用顺序把每一次 Hook 和 Fiber 上的节点对上号。中间少调用一次，后面的状态就会错位。条件渲染要放在 Hook 之后，或者把条件挪进自定义 Hook 的内部实现（自定义 Hook 自己的调用次数在该组件里仍然要稳定）。

实现是链表，不是数组

教学里常用「state 存在数组里，下标就是调用序号」来解释规则。真实结构是挂在 fiber.memoizedState 上的 单向链表：每个 Hook 节点有 memoizedState、queue 和 next。首次渲染走 mount 版 dispatcher，按顺序创建节点；更新走 update 版 dispatcher，按同样顺序取 next。

「数组」这个比喻足够解释为什么不能条件调用，但源码里没有一个 hookStates[i] 数组。dispatcher 是当前渲染使用的那一组函数（useState、useEffect 等），mount 与 update 两套实现不同。

和 Fiber 的关系

Hook 状态保存在函数组件对应的 Fiber 上，所以组件在树里的位置（类型 + key）决定了状态身份。父组件把子组件的类型换掉或改变 key，Fiber 重建，Hook 链表一起丢掉。

并发渲染可能让函数体执行多次，未提交的那次会丢弃。Hook 的更新队列能承受「算了又重来」。这要求渲染保持纯。下面两张图是时间分片的直觉，调度细节在《React Fiber》和《React Scheduler 调度器》：切片不是 requestIdleCallback，默认大约 5ms 让出一次，而且只发生在并发 render。

常用 Hook

  • useState：保存渲染所需状态。对象不会像类的 setState 那样合并。
  • useReducer：下一次状态由 reducer 纯函数算出，适合更新依赖前一份状态、或多个子更新一起变。
  • useContext：读最近的 Provider。Provider 的 value 变了就会重渲染，memo 挡不住。
  • useRef：保存可变盒子 .current，改它不触发渲染。也可指向 DOM。
  • useEffect：绘制之后与外部系统同步，必须写清理。
  • useLayoutEffect：绘制之前，用于测量和同步改 DOM。
  • useInsertionEffect：主要给 CSS-in-JS 在布局前插入样式，业务代码很少用。
  • useMemo / useCallback：缓存计算结果或函数引用。只有下游用 memo、或依赖数组真的需要稳定引用时才有收益。
  • useImperativeHandle：配合 forwardRef，缩小父组件通过 ref 能调用的表面。
  • useTransition / useDeferredValue：把更新标成可打断的过渡。
  • useId：生成稳定唯一 id，用于无障碍属性，不要拿来当列表 key。
  • useSyncExternalStore：订阅 React 外部的 store，并发渲染下避免撕裂。Redux 等库内部在用。

React 19 起，use 可以在渲染中读取 Promise 或 context，并且允许放在条件里。它是单独的 API，不推翻上面「useState 不能条件调用」的规则。

自定义 Hook

自定义 Hook 没有魔法。它把若干 Hook 和普通函数收成可复用的逻辑，每次调用仍对应组件 Fiber 上的一段链表。

同一个自定义 Hook 调用两次，就是两套独立状态。不要把它当成单例。

类组件怎么对应

类 Hook
this.state useState / useReducer
componentDidMount + componentWillUnmount useEffect 空依赖 + 清理
componentDidUpdate useEffect 带依赖
绘制前读 DOM useLayoutEffect
实例字段 useRef
Context.Consumer useContext

生命周期里「挂载请求一次、更新按 id 再请求」应合成一个依赖 [id] 的效果，而不是模仿两个生命周期各写一个 effect 却共享同一份难以清理的状态。
