React.Suspense

2021-08-08
  • React
本文总阅读量次

鱼沈雁杳天涯路,始信人间别离苦。

Suspense 是组件，不是 Hook

Suspense 在子树还没准备好时显示 fallback。lazy 是创建懒加载组件的函数，也不是 Hook。React 16.6 起可以用它们做代码分割。在此之前常见的是 react-loadable 这类高阶组件配动态 import()。

子树准备好后，fallback 换成真实子节点。fallback 本身不要再挂起，否则没有可显示的内容。

数据获取不是随手 throw

React 18 允许支持 Suspense 的数据源在渲染期间挂起：组件读取缓存，缓存未命中就抛出 Promise，Promise 完成后再渲染。这要求缓存在重试时返回同一个 Promise，否则会反复挂起。

在组件里手写 throw fetch(url) 没有这种缓存，每次渲染都是新 Promise，不能作为数据请求的写法。数据获取用框架或库提供的 Suspense 集成（Relay、Next.js、支持 use 的缓存）。React 19 的 use(promise) 需要上层已经创建好的、稳定的 Promise，通常来自服务端框架，而不是在渲染时新发一个请求。

边界放在哪

边界越靠近挂起的组件，其余页面越能先画出来。整页只包一个 Suspense，任何懒加载都会换成整页 fallback。列表里每一项一个边界，会闪很多块，一般按区域包：侧栏一块、主内容一块。

嵌套时，最近的边界先接住挂起。外层边界不会重复显示，除非内层没有包。

和 Transition

startTransition 里触发的挂起，默认 不 立刻换成 fallback，而是先留着旧界面，等新内容准备好再替换。这样切换标签时不会闪回加载文案。若希望过渡期间也显示 fallback，使用该版本提供的方式（例如在支持的版本里为 Suspense 设置相应策略）。急切的导航（用户点了就要立刻看到加载）不要放进 transition。

和错误边界

Suspense 只处理「还没好」。加载失败、渲染抛错，需要错误边界。顺序一般是错误边界在外，Suspense 在内：失败时看到重试，等待时看到 fallback。
