React.lazy

2021-09-15
  • React
本文总阅读量次

江流天地外，山色有无中。

把组件拆成单独的包

lazy(() => import('./Heavy')) 返回一个组件类型。首次渲染到它时才去加载那个模块。模块的默认导出必须是组件。它不是 Hook，不要在条件里调用 lazy 本身；调用 lazy 应在模块顶层，保证类型身份稳定。

加载完成前，最近的 Suspense 会显示 fallback。没有边界时，加载会向上抛，最终变成错误。

和错误边界

动态 import() 失败（网络、语法错误）不会显示 fallback，而是抛出错误。用错误边界包住 Suspense，给出重试。

类组件目前仍是错误边界的写法。函数组件没有等价的 Hook。

路由里按页面拆

每个路由组件一次 lazy，用布局路由上的一个 Suspense 包住出口即可。不要在渲染函数内部 lazy(() => import(...))，那样每次渲染都是新类型，状态会丢，请求会重复。

具名导出需要包一层：lazy(() => import('./mod').then(m => ({ default: m.Chart })))。

服务端

React.lazy 在客户端打包（Vite、webpack 的动态 import）上直接可用。服务端渲染要框架配合代码分割和注水（Next.js、Remix 等有自己的懒加载）。手写 renderToString 时，lazy 没有等模块加载完的能力，不要假设它在服务端自动等待。

预加载可以提前调用同一个 import()：用户鼠标移到链接上时 void import('./Heavy')，与 lazy 共用浏览器对同一模块 URL 的缓存。
