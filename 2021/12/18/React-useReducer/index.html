React useReducer

2021-12-18
  • React
本文总阅读量次

骊山语罢清宵半，泪雨霖铃终不怨。

用动作描述下一步状态

useReducer(reducer, initialArg, init) 适合下一次状态依赖上一份状态、且更新有明确动作的情况。reducer(state, action) 必须是纯函数：同样的输入永远得到同样的输出，不发请求、不改入参。

dispatch 的引用稳定。React 按队列顺序调用 reducer，所以连续 dispatch 能看到前一条已经算出的 state。这和 useState 的函数式更新是同一套队列。

第三个参数

初始状态计算很贵，或依赖 props 做一次性初始化时，把函数放在第三个参数。React 只会用 init(initialArg) 的结果作为挂载状态，之后不会再调用。

不要在 reducer 里写「若还没初始化就请求」。初始化放在 init 或渲染之外。副作用放在事件或 useEffect 里，请求完成后再 dispatch 一个结果动作。

和 useState 的边界

一两个独立字段用 useState 更直接。出现「加一的同时还要改列表」「不可能出现的组合要被类型排除」时，收到一个 reducer 里更好检查。reducer 可以单独测试，不必渲染组件。

不要为了形式把所有 useState 都改成 reducer。Redux 的 store 是跨组件的；useReducer 的状态仍然只在这个组件的 Fiber 上，要共享就自己通过 props 或 context 把 dispatch 传下去。

不可变更新

reducer 应返回新对象。直接 state.count++ 再 return state，引用没变，React 可能跳过渲染，外部若持有旧 state 也会被污染。数组用 map / filter / 展开，或在确保只有本函数碰这份草稿时使用 Immer 一类库。React 本身不帮 useReducer 做 Immer。
