按功能切开 store

单一状态树大了以后，把用户、购物车、某个页面的共享数据拆成模块。每个模块有自己的 state、getters、mutations、actions，最后挂到根 store 的 modules 上。

命名空间

namespaced: true 之后，mutation、action、getter 都会带路径前缀，避免两个模块都有 setName 时互相覆盖。

模块的 state 写成函数，每个 store 实例一份，服务端渲染时不会串数据。写成对象时，多个 store 会共享这份对象。

模块里访问根

命名空间模块的 commit("setName") 默认提交到本模块。要提交根或别的模块：

getter 与 action 的参数里有 rootState、rootGetters。根 getter 的全名要带对方的命名空间：rootGetters["user/id"]。

没有命名空间时

namespaced: false 或不写时，action、mutation、getter 注册到全局名字上，只有 state 按模块嵌套。两个模块导出同名 mutation 都会执行。新代码打开命名空间。

Vuex 4 可以用 store.hasModule("home") 判断。Vuex 3 没有这个方法，注册前看 store.state.home 是否已经存在。卸载模块会丢掉它的 state。不要在还有组件映射着该模块时卸载。

和 Pinia 的对应关系

Vuex 模块大致相当于 Pinia 里的一个 store。Pinia 没有命名空间字符串，也没有 mutation。维护现有 Vuex 项目时继续用模块；新项目不要在一个页面里同时引入两套状态库去改同一份数据。
