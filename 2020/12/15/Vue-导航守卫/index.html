Vue 导航守卫

2020-12-15
  • Vue
本文总阅读量次

红藕香残玉簟秋，轻解罗裳，独上兰舟。云中谁寄锦书来？

守卫决定这次导航是否完成

导航守卫在路由真正切换前插入逻辑：校验登录、拉取权限、取消未保存离开。守卫可以留下、重定向或取消。异步守卫完成之前，导航会处于等待。

下面先写 Vue Router 3（Vue 2）的 next。Vue Router 4 的返回值写法和它不是同一套，不能在一个函数里混用。

完整顺序

  1. 离开组件里的 beforeRouteLeave
  2. 全局 beforeEach
  3. 复用组件时的 beforeRouteUpdate（例如只改了 /user/1 → /user/2）
  4. 路由配置里的 beforeEnter
  5. 进入组件里的 beforeRouteEnter
  6. 全局 beforeResolve
  7. 导航确认
  8. 全局 afterEach
  9. DOM 更新
  10. beforeRouteEnter 里交给 next 的回调，此时组件实例已经创建

afterEach 没有 next，它不能取消导航。

Vue Router 3：必须调用 next

调用 结果
next() 放行
next(false) 取消，地址回到 from
next('/login') 或 next({ name }) 中断当前导航，改去新地址
next(error) 传入 Error 实例时，导航失败并交给 router.onError

一次导航里 next 只能走一条出路，不要在 if 和后面又各调用一次。漏掉 next() 时，导航会一直挂起，表现为点了链接地址不变。

三个参数：

参数 含义
to 即将进入的路由对象
from 即将离开的路由对象
next 确认这一钩子。Vue Router 3 里每个前置守卫都要调用

全局后置：

解析守卫 beforeResolve 在组件内守卫之后，适合最后确认。它仍然使用 next。

组件内守卫

路由独享守卫写在路由记录上：beforeEnter: (to, from, next) => { next(); }。它没有组件 this。

Vue Router 4：用返回值

Vue Router 4 仍接收 next，但官方推荐直接返回，第三个参数可以不写。两种风格不要混在同一次守卫里：又 return 又调用 next() 会触发警告，导航结果也不稳定。

返回值 结果
undefined 或 true 放行
false 取消导航
路由地址对象 重定向
Promise 等待结束后按上面的规则处理
抛错或返回被拒绝的 Promise 导航失败

Vue Router 4 里「不调用 next」是合法的。把 Vue Router 3 的「一定要调用 next」抄到 createRouter 项目里，会和返回值风格冲突。

组件内守卫同样可以返回 false 或路由对象。beforeRouteEnter 若还要在实例创建后执行代码，Vue Router 4 仍通过 next(vm => {}) 传入回调，这是少数还需要 next 的地方。

meta 字段

meta 会沿 matched 合并。父路由写了 auth: true，子路由可以覆盖。判断登录时看整条匹配链，而不是只看 to.meta：

Vue Router 4.1 起也可以在路由上写函数形式的 meta，用得少，阅读现有项目时以对象形式为准即可。

和异步组件

导航确认后才加载的异步组件，若加载失败，会进入 router.onError。守卫里的请求失败应显式重定向或取消，不要留下未处理的拒绝。
