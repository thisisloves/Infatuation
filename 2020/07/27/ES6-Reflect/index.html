和 Object 上那些操作对应的函数

Reflect 不是构造函数，也不能 new。它上面的方法和 Proxy 的陷阱一一对应，参数顺序也一致。在陷阱里调用同名 Reflect 方法，就是「按默认语义做完，并且接收者正确」。

Reflect.get(target, key, receiver) 在属性是 getter 时，把 receiver 当作 this。Object 上没有这个三参数形式。代理若要转发 getter，必须把 receiver 传下去，否则子对象上的 getter 会跑在错误的 this 上。

返回值更适合做判断

Reflect.set、Reflect.deleteProperty、Reflect.defineProperty 返回布尔，失败不一定抛错。Object.defineProperty 失败会抛 TypeError。在不希望用异常做分支的代码里，Reflect 更好写。

Reflect.ownKeys(obj) 同时包含字符串键和 Symbol 键，等价于 Object.getOwnPropertyNames 与 Object.getOwnPropertySymbols 合在一起。Object.keys 仍然只含可枚举字符串键。

apply 与 construct

Reflect.apply(fn, thisArg, args) 对应 Function.prototype.apply。Reflect.construct(Target, args, newTarget) 可以指定 new.target，子类实现陷阱 construct 时要用它，否则 new.target 会错成父类。

它不是响应式 API

修改对象不会经过 Reflect，除非你只通过 Reflect.set 写。想拦截所有写入，包一层 Proxy，在陷阱里再调用 Reflect。把业务改成全部走 Reflect.set 并不能监听别人的 obj.x = 1。

Reflect 也没有 Reflect.definePrivate 这类私有能力。不要把它当成元编程的全部，它只是把语言内部的对象操作暴露成了可转发的函数。

转发 getter 必须带上 receiver

若陷阱写成 return target[key]，getter 的 this 是 target，上面没有 _name，结果是 undefined。子对象把代理当作原型、字段写在子对象上时，必须把 receiver 交给 Reflect.get。Reflect.set 同理。

和 Object 的差别

  • Reflect.defineProperty 失败返回 false。Object.defineProperty 失败抛 TypeError。
  • Reflect.ownKeys 含字符串键和 Symbol 键。Object.keys 只有可枚举字符串键。
  • Reflect.construct(Array, [3]) 等价于 new Array(3)，是长度为 3 的空槽数组，不是 [3]。单元素数组用 Array.of(3)。
  • Reflect.set 返回 false 时，严格模式的赋值抛 TypeError，非严格模式静默失败。

Reflect 不会监听 obj.x = 1。要拦截写入，先包 Proxy，再在陷阱里调用 Reflect。

delete 返回布尔，不抛错

同样的 delete frozen.a 在严格模式抛 TypeError。Reflect.deleteProperty 用返回值表示失败，适合写在代理的 deleteProperty 里原样转发。Reflect.has 会看原型链，和 in 一样；只查自身用 Object.hasOwn。Reflect.construct(Array, [3]) 不要当成 Array.of(3)。
