拦截对对象的操作

new Proxy(target, handler) 返回代理。对代理的读取、赋值、in、delete、函数调用等，可以在 handler 里改道。没有提供的陷阱会落到目标对象上。

set 返回 false 时，严格模式下赋值会抛 TypeError。陷阱里用 Reflect 把默认行为做完，才能配合原型链和 getter 的 receiver。直接 target[key] = value 在有继承的代理上会丢接收者。

不变量

代理不能撒谎到破坏语言不变量，否则引擎抛 TypeError。例如：

  • 目标上不可配置、不可写的属性，get 必须返回原来的值。
  • 不可配置的属性不能被 deleteProperty 报成功。
  • getPrototypeOf 若目标不可扩展，必须返回真实原型。
  • 对不可扩展对象，ownKeys 返回的键必须和真实自身键一致。

这些检查发生在陷阱返回之后。写「什么都能伪造」的代理，一碰到 Object.freeze 过的对象就会爆。

能拦截和不能拦截

常见陷阱：get、set、has、deleteProperty、ownKeys、apply、construct、getPrototypeOf、setPrototypeOf、defineProperty、getOwnPropertyDescriptor、preventExtensions、isExtensible。

代理拦截不到内部槽。Map 的 set 方法若从代理上拆出来再调用，仍要求 this 是真正的 Map，把 Map 包一层代理不能当 Map 用，除非在 get 里把方法 bind 回目标。日期、Promise 同理。

私有字段 #x 的访问不走普通 get，代理拦不到。

使用场景

Vue 3 的响应式用 Proxy 收集依赖。校验、只读视图、负索引，都可以。不要用代理做安全沙箱：它挡不住通过原型、通过未代理的引用直接改目标，也挡不住同一进程里的其他代码。热路径上每层代理都有调用成本，不要无意义地套多层。

Proxy.revocable 返回 { proxy, revoke }。revoke() 之后再操作代理会抛错，用来关掉交出去的访问权。目标对象本身不受影响。

set 返回 true 不等于已经写上

只 return true 而不调用 Reflect.set，严格模式不抛错，目标上却没有这个属性。返回 false 或不返回值，严格模式抛 TypeError。非严格模式则静默失败，容易当成写成功了。

不可配置且不可写的属性，get 若返回别的值，引擎在陷阱返回后检查不变量并抛 TypeError。Object.freeze 过的对象不能被代理谎报成另一套数据。
