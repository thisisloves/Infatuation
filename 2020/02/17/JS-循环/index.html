JS 循环

概念

循环在条件成立时重复一段代码。计数循环要有初始值、继续条件和步进，三者缺一个就可能停不下来。

语句 行为
for 先判断再执行，适合已知次数
while 先判断再执行，次数不固定
do...while 先执行再判断，至少一次。条件一开始就为假时，才比 while 多跑一轮；条件一直为真时，两者次数相同
for...in 遍历对象可枚举的字符串键，包含继承来的，顺序不要依赖
for...of 遍历实现了可迭代协议的值：数组、字符串、Map、Set、arguments、NodeList

break 结束整个循环，continue 进入下一轮。forEach 的回调里这两句管不到外层，因为回调不是循环语句本身。

生成器作为迭代器时，yield 出去的就是循环变量的值。done: true 由生成器结束来表示，不能 yield { done: true } 指望循环停下来，那只会多产出一个普通对象。

常见坑

  • 对象字面量里写两次 age，前一个值会被丢掉，循环里看不到 '女'。
  • for...in 遍历数组会走到下标字符串，还可能走到原型上后来加上的键，不要用它扫数组。
  • for (var i ...) 配合异步回调，回调看到的是最终的 i。循环头改成 let。
  • 在 for...of 遍历数组时 splice 当前项，会跳过元素。先收集下标再删，或从后往前删。
  • do...while 的条件写在后面，若循环体里把计数器改错，仍然会先产生一次副作用。

for…of 和异步

for...of 会消费迭代器。生成器函数执行到 yield 暂停，for...of 每轮向它要下一个值，生成器返回或抛错时循环结束。手动写的 { value, done } 只有在迭代器的 next() 返回值上才有意义，写进 yield 的对象只是普通数据。

这里会按顺序等待。list.forEach(async (item) => { await item(); }) 不会等待，所有异步函数几乎一起开始。for await...of 用于异步可迭代对象，不要把它和普通数组的 for...of 加 await 混成一个语法。

break 可以带标签跳出外层循环。没标签时，它只结束最内层。在 switch 里 break 结束的是 switch，若 switch 写在循环中，要跳出循环需要标签，或改用 return。死循环至少留一个会变化的条件，或在内部 break，否则页面主线程不再处理点击。

小结

次数清楚用 for，先判断用 while，必须先做一次再用 do...while。对象键用 for...in 或 Object.entries，数组用 for...of。迭代器 yield 的是值本身，不是 { value, done } 包装。
