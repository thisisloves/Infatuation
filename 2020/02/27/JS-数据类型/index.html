JS 数据类型

2020-02-27
  • JS
本文总阅读量次

花自飘零水自流，一种相思，两处闲愁。

概念

原始类型七种：undefined、null、boolean、number、bigint、string、symbol。除此之外的普通对象、数组、函数、日期都是对象，typeof 对函数单独返回 "function"，其余对象返回 "object"。

Object 不是基本类型。把 Object、Function、Array、Date 和 undefined 列在同一组「基本数据类型」里，分类就反了。

typeof 对未声明的变量也返回 "undefined" 且不抛错。真正去读未声明的名字才会 ReferenceError。所以「未定义变量的数据类型是 undefined」只对 typeof 成立。

NaN 是 number，表示无效的数值结果。NaN === NaN 为假，判断要用 Number.isNaN(x)。标识符 Nan 并不存在。

1 + { name: 'admin' } 实际是字符串 '1[object Object]'，Object 的 O 大写。1 + [3, 4, 5] 是 '13,4,5'，因为数组先 join(',')。对象和数组参加 + 没有稳定的业务含义，先取出字段再算。

parseInt('a2344', 10) 得到 NaN，typeof 仍是 "number"。parseInt('2344a', 10) 得到数字 2344，不是字符串。parseInt 会在第一个非法字符处停下，所以 '2344a' 能解析出前缀；带基数更安全。

假值只有：false、0、-0、''、null、undefined、NaN。[]、{}、'0'、'false' 都是真。

常见坑

  • 1 + null 不是 NaN。只有 undefined 转数字才是 NaN，null 转数字是 0。
  • console('假') 不是输出，console 本身不是函数，要 console.log。
  • == 会转换。null == undefined 为真，但两者与 0、'' 用 == 比较为假。判断用 ===。
  • typeof null === 'object'，判断空对象要 value === null 或 Object.prototype.toString.call(value)。
  • BigInt 不能和 Number 直接 + 或 === 以外的混算，1n + 1 抛 TypeError。
  • new String('a') 的 typeof 是 "object"。日常不要用构造函数装箱。
  • Symbol() 每次都是新值，不能 JSON.stringify，也不能当成对象键之后用字符串再取出来。

数值和字符串

Number('1') 比 parseInt 更严格，'2344a' 得到 NaN 而不是 2344。parseInt 适合从 '12px' 这种前缀里取整数，并且要写上基数 10，避免旧环境把前导 0 当八进制。

String(null) 是 'null'，String(undefined) 是 'undefined'，和模板字符串一致。对象的 + 会先走 valueOf / toString，数组 toString 等于 join(',')，所以 1 + [3, 4] 是 '13,4'。普通对象默认 toString 是 '[object Object]'。

空数组在数值上下文里常常变成 0（+[] === 0），在布尔上下文里却是真。判断「有没有选中项」不要写 if (arr)，空数组也是真；应看 arr.length。判断 null 用 ===，因为 typeof null 帮不上忙。

== 会把对象转成原始值。[] == false 为真，因为两边都变成了数字 0。=== 不会。判断空数组看 length，判断 null 用 === null。

BigInt 和 Number 不能混在同一次算术里。Symbol 每次调用都是新值，不能 JSON.stringify。这些都不是「对象的子类」，typeof 分别是 "bigint" 和 "symbol"。

小结

原始类型没有 Object。typeof null 是 "object"，NaN 是数字且不等于自己，1 + null 等于 1。假值只有那七个，空数组和空对象都是真。
