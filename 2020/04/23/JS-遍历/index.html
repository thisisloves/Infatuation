JS 遍历

2020-04-23
  • JS
本文总阅读量次

流水潺潺，素手纤纤，青丝束，惊鸿若舞，衣袂飘飘，所谓倾心相许。

概念

遍历是按某种顺序访问结构里的每一项。数组上最常用的是 for...of 和这几个方法，签名都是 arr.method(callback, thisArg)，不要把 forEach、filter 的语法抄成 array.map。

回调参数依次是当前元素、下标、原数组。thisArg 作为普通函数回调里的 this；箭头函数忽略它。

方法 返回值 是否改原数组
forEach 永远 undefined 不改，除非回调里自己改
map 等长新数组 不改
filter 由通过测试的元素组成的新数组 不改
some / every 布尔，可提前结束 不改
reduce 你累加出来的任意值 不改

空槽会被这三个方法跳过。它们也不能被 break 打断。forEach 里的 return 只结束本次回调，相当于 continue。

正确示例

对象不要用数组方法。键用 Object.keys / Object.entries，所有自有键含不可枚举时用 Reflect.ownKeys。Map 用 for...of。

需要中途停止：

常见坑

  • forEach 不会返回新数组。把它的结果再 .map 会抛错，因为 undefined 没有 map。
  • map 忘了 return，得到一排 undefined。
  • 回调是异步函数时，forEach 不会等待。要串行 await，用 for...of；要并行，用 Promise.all(arr.map(...))。
  • 遍历时 splice 会让后面的下标前移，从而跳项。过滤用 filter 生成新数组。
  • filter + indexOf 去重是 O(n²)，而且 NaN、对象按引用比较。原始值去重用 Set：[...new Set(arr)]。
  • thisArg 对箭头函数无效。写成箭头还期望 this 是第二个参数，打印出来的是外层 this。

对象和类数组

NodeList、arguments 有长度和下标，但不是数组，没有 map 的旧环境要 Array.from 或 Array.prototype.forEach.call。能用 for...of 的就不要先变成数组。

for...in 会枚举原型上后来添加的可枚举键，数组下标也会以字符串形式出现。扫纯数组用 for...of 或 forEach。只关心自有键时用 Object.hasOwn 过滤，或直接 Object.keys。

map 的回调若返回 Promise，得到的是 Promise 数组，不会自动等待。并行用 Promise.all，要按顺序等待就在 for...of 里 await。reduce 不传初始值时，空数组抛错，第一项还会被当成累加器而跳过回调，求和时写成 reduce((s, n) => s + n, 0)。

Map 和对象键

数组方法不能直接用在普通对象上。键的顺序若要稳定，用 Object.keys 得到自身可枚举字符串键，再决定要不要排序。Map 用 for...of 按插入顺序给出 [key, value]，键可以是对象，不会被转成字符串。

在 map 里修改原数组的其他下标是允许的，但当前下标之前的项已经被访问过，改它们不会让回调再跑一次。要删除不满足条件的项，用 filter 得到新数组，而不是在 forEach 里 splice。some 在第一次返回真值后停止，适合查找，不要用它做「对每一项都要发生的副作用」。

小结

map 出新数组，forEach 只执行副作用并返回 undefined，filter 出子集。三者语法相同，都不能 break。要停下来或要 await，用 for...of。
