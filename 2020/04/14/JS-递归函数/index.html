JS 递归函数

概念

函数直接或间接调用自己，就是递归。每一次调用压入一层调用栈，返回时弹出。栈帧里的局部变量互不干扰，所以递进时外层的值还在。

递归必须有基准情形：不再调用自己、直接返回结果的分支。没有它，栈会一直涨，直到 RangeError: Maximum call stack size exceeded。

JavaScript 没有 C++ 的 inline。规范里的尾调用优化在主流引擎（包括 V8）中基本没有实现，把递归写成尾调用也不能当成不会爆栈。

递归适合树、嵌套目录、分治。线性的累加、斐波那契用循环或记忆化更合适，因为朴素递归会重复计算。

常见坑

  • 基准条件写错会少算或多算。if (n === 1 || n === 2) return n - 1 得到的是 F(1)=0、F(2)=1，再往下才和常见数列对齐；若以为 F(1)=1，结果会整体错位。
  • map 的返回值被丢掉时，只是在用它做循环。递归收集结果应该 return，或改用 forEach。
  • 箭头函数没有 this。写成 const getId = () => { this.getId(...) } 会到外层去找 getId，经常是 undefined。
  • 深度优先遍历大树、或 n 上万的阶乘式递归，会先爆栈而不是先算完。这种输入改成显式栈循环。
  • 共享同一个数组参数是有意的副作用。调用方如果复用这个数组，下次结果会叠在旧数据上。

小结

递归 = 基准情形 + 规模更小的同问题 + 调用栈。JS 不要指望尾调用优化，也不存在「内联函数」这条规定。树可以递归，重复子问题要记忆化或改循环。
