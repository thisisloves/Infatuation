ES6 Symbol

2020-08-14
  • ES6
本文总阅读量次

始于初见，止于终老。

每个 Symbol() 都是新值

Symbol('id') 的参数只是调试用的描述，不参与相等。两次调用得到两个不相等的值，即使描述相同。new Symbol() 会抛错，它不是构造函数。

Symbol 键不会出现在 for...in、Object.keys、JSON.stringify 里。Object.getOwnPropertySymbols 和 Reflect.ownKeys 能看到。它不是私有属性，只是不容易撞名。真正的私有是类的 #field。

全局登记

Symbol.for('id') 按字符串在全局登记表里查找，没有就创建。同一描述永远得到同一个 Symbol，包括跨 realm 时运行库共享的那张表。Symbol.keyFor(sym) 只对 Symbol.for 登记过的值返回描述，对 Symbol('id') 返回 undefined。

库的扩展键若希望全程序唯一且可复现，用 Symbol.for。只想要「这块代码自己的键」，用 Symbol()，避免别的脚本 Symbol.for 到同一个键改你的字段。

内置 Symbol

语言用一批知名 Symbol 当钩子，而不是往对象上加普通字符串方法，避免和业务字段冲突。

  • Symbol.iterator：可迭代协议。
  • Symbol.toStringTag：影响 Object.prototype.toString 的标签。
  • Symbol.toPrimitive：对象转原始值时调用。
  • Symbol.hasInstance：自定义 instanceof。
  • Symbol.species：内置方法派生新对象时用哪个构造函数。

覆盖这些等于参与语法行为，只在写集合、写类库时做。业务对象用普通方法名即可。

容易错的点

JSON.stringify 会丢掉 Symbol 键和 Symbol 值。描述可以用 sym.description 读取（ES2019）。把 Symbol 放进 Set 或当 Map 的键，按引用相等，Symbol.for 的同一个键只会有一条。

拷贝会带走，JSON 不会

Object.assign 和对象展开复制可枚举的自身 Symbol 键。Object.keys、for...in、JSON.stringify 都忽略它们。以为「Symbol 键拷贝时一定丢」只对 JSON 成立。

Symbol.iterator 的值必须是函数，调用后返回带 next 的迭代器。把一个已经造好的迭代器对象直接赋给这个键，for...of 会把它当函数调用，抛出 TypeError。

描述不是身份

Symbol('a') === Symbol('a') 是 false。description 只用于调试。需要跨文件拿到同一个值时用 Symbol.for('a')。Symbol.keyFor 只认登记表里的值，对 Symbol('a') 返回 undefined，不会返回 'a'。

new Symbol() 抛 TypeError。要用包装对象只能 Object(Symbol('a'))，一般没有这个必要。Symbol 不能和字符串做隐式拼接，`${id}` 也会抛 TypeError，先读 id.description。

内置 Symbol 会改变运算

只写 toString / valueOf 时，运算走默认的原始值转换。一旦定义 Symbol.toPrimitive，hint 为 'number'、'string' 或 'default'，返回值必须是原始值，返回对象会抛 TypeError。Symbol.iterator 写错则 for...of 直接不能用。业务对象不要覆盖这些钩子。
