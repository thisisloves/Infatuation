JS 条件语句

2020-03-07
  • JS
本文总阅读量次

枕上一书三生誓，殷切与君语迟迟。 佛铃花落醉尘火，执念难绝情成痴。

概念

条件语句按布尔结果选择分支。if 括号里的值会先被转成布尔值：false、0、-0、''、null、undefined、NaN 为假，其余为真（包括 '0'、'false'、[]、{}）。

  • if：条件为真才执行。
  • if...else：一真一假两条路。
  • if...else if...else：从上往下，命中第一条就不再看后面。
  • switch：用严格相等 === 比较表达式和每个 case，命中后会一直执行到 break 或 switch 结束。

switch 没有 break 就是穿透（fall-through），不是自动只跑一个分支。

正确示例

getDay() 里 0 是星期日。多个 case 叠在一起可以共享一段逻辑，这是有意穿透，最后仍要 break。

需要范围判断时，if 比 switch 合适。switch (true) 能写条件，但可读性差，一般不必用。

常见坑

  • switch 不用 ==。switch (1) 对不上 case '1'。
  • 在 case 里直接 let / const 且不加大括号，相邻 case 会因为同一个块里的重复声明而语法错误。要声明变量就写成 case 1: { const x = 1; break; }。
  • 漏写 break 会把后面的赋值也执行掉，label 停在最后一个写过的值。
  • 使用尚未声明的 time、x 会在进入条件前就抛 ReferenceError。先赋值，或在 switch 外声明 let label。
  • if (value = 1) 是赋值，结果永远为真。比较要用 ===。
  • 不要用 switch 去匹配 NaN：NaN === NaN 为假，会掉进 default。

真值以外的分支

value == null 同时覆盖 null 和 undefined，这是少见的还值得用 == 的地方。其余比较用 ===。

switch 的表达式只计算一次。把会变的函数调用放进去是安全的，但 case 里的赋值不会回头再影响已经算完的那个值。分组用 case 1: case 2: 共享一段，并在结束处 break。需要块级变量时，每个 case 自己包一对花括号。

空字符串、0 和 null 都是假值，业务上却常常要区分。缺省用 ??，它只替换 null 和 undefined：

switch 使用 ===。case 里要声明 let 时，给该分支单独加花括号，否则相邻分支会因为重复声明而语法错误。漏掉的 break 会继续执行下一支，这是穿透，不是自动只选一个。

小结

if 看真假值，switch 看 ===。范围用 else if，枚举用 switch 并写上 break。case 里的 let 要单独分块，条件里不要写成赋值。
