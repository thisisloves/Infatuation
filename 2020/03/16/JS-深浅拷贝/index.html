JS 深浅拷贝

2020-03-16
  • JS
本文总阅读量次

真正的情谊，无关风月，纤尘不染，只因你在，我也在，你未离，我亦未弃。羁绊，本就如此简单。

概念

先把三件事分开：

  • 赋值 const b = a：多一个名字。对象时两个名字指向同一块内存，没有新容器。这不是浅拷贝。
  • 浅拷贝：新的数组或对象，只复制第一层属性的值。第一层若是原始值，内外互不影响；若是对象，复制的是引用，改内层两边都能看到。
  • 深拷贝：新容器，并且嵌套的可拷贝对象也各自新建。函数、DOM、类实例通常无法变成「同一语义的新函数」，要单独约定。

判断时要写明改的是哪一层。改拷贝后的顶层属性不影响原对象，只能说明这一层没有共享；再改 copy.child.x 仍变，就是浅拷贝。不能「只要 B 变了就是浅拷贝」一句话带过。

pop、push、splice、reverse 是就地修改，不产生副本。

JSON.parse(JSON.stringify(value)) 只适合纯 JSON 数据。函数、undefined、Symbol 会丢，Date 变成字符串，NaN 变成 null，循环引用直接抛错。数组里的函数变成 null，不是原函数。

自己写递归时，typeof null === 'object'，数组的 typeof 也是 'object'。不先判断就会把 null 当成对象、把数组做成 {}：

这个版本对函数仍是共享同一引用，因为函数不是普通数据。这和「多层都变成新对象」不矛盾，但不要说函数也被复制出了新的函数对象。

常见坑

  • a.flat() 得到的是拉平后的新数组，维度已经变了，不是同结构的深拷贝。数字被拆成原始值后，改新数组不会影响原数组的内层，原因是结构变了。
  • join / String(array) 得到字符串，split 之后全是字符串，数字 1 变成 '1'。
  • 只对数组 map 递归时，遇到普通对象会原样返回，内层对象仍然共享。
  • Object.assign 和扩展运算符不复制原型、不可枚举属性，访问器会被读成当前值再写成数据属性。
  • 旧环境没有 structuredClone 时再考虑 JSON 或库。有循环引用就不要用 JSON。

数组方法里的拷贝

会改原数组的方法没有「复制」这一步：push、splice、sort、reverse。名字上像拷贝的 slice、concat、扩展运算符、Object.assign、map 只复制第一层。

flat 改变的是维度，拉平后的数字是原始值，所以改新数组不影响旧的内层数组，但这不是深拷贝成功，是结构已经不同。join 再 split 还会把数字变成字符串。

structuredClone 不能克隆函数、DOM 节点和某些类实例。遇到它们会抛 DataCloneError。要保留函数引用时，在递归里对 typeof value === 'function' 直接返回原函数，并在注释里写明这是共享而不是复制。

改顶层和改内层

判断是不是深拷贝，要改嵌套字段，而不是只改第一层：

第二次先把引用接回去，再改属性，所以原对象变了。第一层换成新对象，并不说明内层也被复制过。

structuredClone 遇到函数、DOM 节点会抛错。纯数据用它；要跳过函数时再手写递归，并记住函数仍然是同一个引用。JSON 路线会把 Date 收成字符串、把数组里的函数收成 null、在循环引用上报错。拷贝之后用 === 比较嵌套对象，深拷贝应为 false。

小结

赋值共享同一个对象。浅拷贝只新开第一层，深拷贝才断开嵌套数据。优先 structuredClone。手写递归要排除 null、分开数组和对象，并接受函数无法被真正复制。
