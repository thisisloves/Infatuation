JS 继承

2020-03-26
  • JS
本文总阅读量次

人世间有百媚千红，唯独你是我情之所钟。

概念

构造函数负责初始化每个实例自己的数据。new 调用它时，this 是新对象；不加 new 直接调用，非严格模式下 this 是全局对象，属性会漏到全局。方法放在 prototype 上，所有实例共享一份。

「继承」在这里是原型委托：子实例沿 [[Prototype]] 找到父原型上的方法，不是把方法拷贝进子对象。class Child extends Parent 就是寄生组合继承的语法，新代码直接用类。

下面用 Parent / Child 说明几种手写方式各自真正共享了什么。父方法若要可见，必须 console.log，只写一个字符串表达式不会有输出。

正确示例

原型链：Child.prototype = new Parent()。子实例能用父原型上的方法，但所有子实例共享那一个父实例上的 colors。子构造函数也不方便把参数传给 Parent。

借用构造函数：在子构造函数里 Parent.call(this, name)。每个子实例有自己的 name 和 colors，但 Parent.prototype 不在链上，say 找不到。可以连续 call 多个构造函数，那是混入数据，不是多条原型链。

另一个 new Child('小华') 的 colors 仍是 ['红']。Object.create(Parent.prototype) 不会调用 Parent，也不会把 childFn 误放到父原型上。

Object.create(obj) 是原型式继承：新对象直接委托 obj，适合没有构造函数的对象。共享的仍是 obj 上的引用类型属性。寄生继承是在这个新对象上再挂自己的方法后返回，方法每个实例一份，不能复用函数对象。

常见坑

  • Child.prototype = new Parent() 之后若不修 constructor，child.constructor === Parent。
  • 给 F.prototype = parentObject 再写 F.prototype.speak = ...，是在改父对象本身。所有拿这个对象当原型的实例都会多出 speak。
  • 寄生组合若写成「先造一个带 childFn 的实例，再让子原型等于这个实例」，childFn 挂在唯一的原型对象上，而且 constructor 指向临时函数。这不是 extends 使用的模式。
  • 父构造函数里定义的方法每个实例一份，继承几次就复制几次。方法应在原型上。
  • extends 的子类构造函数在 this 之前必须先 super，否则抛 ReferenceError。

class 实际做了什么

class Child extends Parent 会把 Child.prototype 的原型设为 Parent.prototype，构造时先 super，也就是只调用一次父构造函数，并把静态方法沿 Child.__proto__ === Parent 委托。这和上面的 inherit 加上 Parent.call 是同一套，只是语法替你补了 constructor。

子类方法里要调用父类同名方法，用 super.say()。此时 super 不是父实例，方法里的 this 仍是子实例。写成 Parent.prototype.say() 而不 call 的话，父方法里的 this 会错。

不要为了「继承多个类」去拼多条原型链。JavaScript 只有一条 [[Prototype]]。需要两套行为时，用组合：把另一个对象放进属性里，转发方法。连续 call 多个构造函数只会复制它们赋到 this 上的数据，原型方法仍然只有一条链。

父类字段若是数组，写在构造函数里 this.colors = []，每个实例一份。写在原型上就会被所有子类实例共享，push 会串数据。

小结

实例数据用构造函数，共享方法用原型。手写继承用 Object.create(Parent.prototype) 再 Parent.call(this)，避免调用两次父构造函数，也避免子实例共享父实例上的数组。业务代码写 class。
