ES6 Iterator

2020-06-19
  • ES6
本文总阅读量次

清影渺难即，飞絮满天涯。

两个协议

迭代器：对象有 next()，返回 { value, done }。done 为真表示结束，此时 value 可有可无。

可迭代对象：有 Symbol.iterator 方法，调用后返回迭代器。for...of、展开、Array.from、Promise.all 的参数、解构数组，都走这个方法。

数组、字符串、Map、Set、arguments、NodeList 默认可迭代。普通对象不行，for...of 一个没有该方法的对象会抛 TypeError。for...in 遍历的是可枚举的键，包含原型链，和迭代器不是一回事。

手写

生成器函数返回的对象同时是迭代器和可迭代对象，[Symbol.iterator]() { return this }。写惰性序列时直接用 function* 更短。

提前结束

消费者可能不读完。for...of 中 break、抛错、或展开没用完，会调用迭代器的 return()。里面释放资源。没有 return 也可以，调用方会检查方法在不在。

字符串迭代器按码点产出。for (const ch of '😀') 循环一次，得到完整字符；str[0] 和 str.length 才按 UTF-16 码元，一个增补平面字符会占两个码元。由多个码点组成的字形簇（家庭 emoji）仍会被拆开，那是 Intl.Segmenter 的事。

和 Generator 的边界

迭代器是协议，生成器是生产迭代器的语法。不是所有迭代器都要写成生成器。第三方对象只要加上 Symbol.iterator 就能进 for...of。不要为了遍历去改 Object.prototype，那会让所有对象变得可迭代，破坏假设对象不可迭代的代码。

普通对象没有默认迭代器

for...in 走的是可枚举键，包含原型链上的键，顺序也不保证。for...of 只认 Symbol.iterator。键值对用 Object.entries(user)。

Symbol.iterator 必须是函数。方法里返回的对象要有 next()，并且结束时返回 { done: true }。漏写 done: true，for...of 和展开都不会停。无限序列可以写成迭代器，但不要 [...infinite]。

消费者中途 break 时会调用 return()。在里面关闭文件或取消订阅。没有 return 时调用方会先判断方法在不在，不会因此抛错。

迭代器只能走一遍

生成器对象既是迭代器也是可迭代对象，第二次展开从已经结束的位置继续，得到空数组。数组可以反复 for...of，因为它每次都新建迭代器。要把生成器的结果用两次，先收进数组。

类数组（有 length 和下标）不等于可迭代。旧的 arguments 两者都有；自己造的 { 0: 'a', length: 1 } 不能 for...of，用 Array.from 或 Array.prototype 上的方法。
