JS 回流和重绘

2020-01-20
  • JS
本文总阅读量次

多情自古伤离别。更那堪，冷落清秋节。

概念

浏览器生成一帧的主路径：

  1. 解析 HTML 得到 DOM，解析 CSS 得到 CSSOM。
  2. 合成渲染树：只包含可见节点及其计算样式。display: none 的子树不进渲染树。
  3. Layout（回流 / 重排）：计算位置和尺寸。
  4. Paint（重绘）：把渲染树画成像素层。
  5. Composite（合成）：把图层交给 GPU。transform、opacity 往往只走合成。

改布局会让相关节点重新 Layout，通常还要重绘再合成，代价最高。只改颜色、背景、visibility，一般跳过 Layout，仍要重绘。只改 transform / opacity，可以不回流也不重绘。因此「回流一定触发重绘」对会走到绘制的布局变更成立，不能套到合成器属性上。

table 的列宽互相依赖，布局往往要多趟计算，大数据表不要用它做页面骨架。

常见坑

  • 「内边框」不是 CSS 概念。影响布局的是 padding（内边距）、border 和 margin。
  • display: none 上的改动不会布局；visibility: hidden 仍占位，改尺寸仍可能回流。
  • 循环里交替读 offsetWidth 和写 style.width，每一轮都强制同步布局，这是布局抖动（layout thrashing）。
  • getComputedStyle 的第二个参数是伪元素，传 null 即可，不要依赖旧教程里的 false。
  • 现代浏览器会合并同一帧里的多次修改，但一旦你中途读取几何属性，合并就被打断。
  • will-change: transform 能提示提升图层，滥用会占内存。动画结束应取消。

读写要分批

若在 forEach 里先读 offsetWidth 再写 style.width，每一轮都强制同步布局。动画改 transform: translateX 或 scale，不要每帧改 left。opacity 和 transform 可以留在合成阶段。

测量可以用 getBoundingClientRect，它同样会触发布局。滚动位置用 scrollTop 读取也会刷新布局队列。把结果放进局部变量，后面的计算不要反复读 DOM。

display: none 的子树不在渲染树里，适合大批量改完再显示。已经显示的节点连续改 class 比逐条改 style 更容易合成成一次。表格布局、多层百分比高度会让一次小改动牵动更多祖先，大列表避免用 table 做骨架。

小结

布局最贵，重绘次之，只改 transform / opacity 最便宜。读写几何属性要分开批次，大量节点用 DocumentFragment 一次插入，动画不要靠改 top / left 硬推。
