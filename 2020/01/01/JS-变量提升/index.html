JS 变量提升

2020-01-01
  • JS
本文总阅读量次

一朝春尽红颜老，花落人亡两不知。

概念

引擎创建执行上下文时，会先处理声明，再执行语句。这个「声明先登记」就是提升（hoisting）。

  • var：提升到所在函数或全局作用域顶部，初始值是 undefined，赋值留在原处。
  • function 声明：整个函数体一起提升，声明之前就可以调用。
  • let、const、class：绑定也会提升到块顶，但在声明行执行前处于暂时性死区（TDZ）。提前访问抛出 ReferenceError: Cannot access 'x' before initialization。
  • function 表达式和箭头函数：只有左边的变量按它的声明方式提升，右边的函数要执行到赋值才存在。

所以「只有 var 会提升」不完整。let 同样提升，只是提升之后不能用。

同一作用域里，函数声明的初始化优先于 var。后面的赋值仍会覆盖这个名字。

正确示例

var greet 被提升为 undefined，调用发生在赋值之前，读到的不是函数。

暂时性死区和「根本没声明」不是同一句报错：

常见坑

  • 在块里写 var，提升范围是整个函数，不是这个块。if 没进去，变量也已经是 undefined。
  • for (var i = 0; ...) 只有一个 i。异步回调里看到的是循环结束后的值。改成 let 后，每次迭代有自己的绑定。
  • 重复的 function foo(){} 后者覆盖前者，而且覆盖在执行前就完成。重复的 let 则是语法错误。
  • class 不会像函数声明那样提前可调用，提前使用同样落在暂时性死区。
  • 条件里的函数声明（if (ok) { function f(){} }）在严格模式和旧浏览器里行为不一致，不要依赖它提升。把函数写在块外，或用 let f = function () {}。

和闭包、重复声明

var 提升的是声明，不是赋值。循环里的函数若读取 var i，创建函数的时候 i 还没到最终值，调用时才去读，于是大家都看到最后一次赋值。let 在每次迭代创建一个新绑定，提升范围只是这一轮的块，暂时性死区也只到这一轮的声明执行完。

未声明的名字用 typeof 得到 'undefined' 且不抛错。死区里的 let 用 typeof 照样抛错。这是区分「没有这个绑定」和「有绑定但不能用」的办法。

同一作用域里 function f(){} 和 var f 共用一个绑定，函数声明先把值设成函数，随后的赋值语句再覆盖。块内部的函数声明在严格模式下属于该块，不要写成 if 里的函数还指望在块外调用。

块级绑定和函数声明

let 提升到块的开头，而不是函数的开头。同一个函数里两个块可以各有一个同名 let。var 做不到，第二个 var x 只是重复声明。

函数声明整体提升，所以可以写在调用后面。条件块里的函数声明不要依赖：严格模式下它属于那个块，块外看不见。需要按条件选择实现时，用变量接住函数表达式，变量的提升规则就和 let / const 一致，调用前处于暂时性死区或还是 undefined（若用 var）。

class 也在暂时性死区里。它不会像函数声明那样在上一行就能 new。

小结

var 提升并初始化为 undefined；函数声明整体可用；let / const / class 提升后留在暂时性死区，报错是 cannot access before initialization，不是 is not defined。
