JS 堆和栈

2020-01-29
  • JS
本文总阅读量次

望君烟水阔，挥手泪沾巾。飞鸟没何处，青山空向人。

概念

调用栈（stack）和堆（heap）是引擎管理内存的两块区域，不要和数据结构课里的栈、队列混成一件事。

  • 栈：当前正在执行的函数帧，后进先出（LIFO）。帧里放参数、局部绑定，以及指向堆对象的引用。函数返回，帧弹出。这不是先进先出；先进先出是队列。
  • 堆：存放大小和生命周期不固定的对象（普通对象、数组、函数、闭包环境等），由垃圾回收决定何时释放。通过栈上或寄存器里的引用去访问。

规范只规定原始值按值比较、对象按引用比较，并不规定「数字一定在栈上」。V8 里小整数可以放在指针的标记位里，超出范围的数字、字符串往往在堆上。面试里说的「原始值在栈、对象在堆」只是帮助记忆的简化，要以引擎为准。

原始类型：undefined、null、boolean、number、bigint、string、symbol。
引用类型：对象以及一切以对象实现的值（数组、函数、日期、正则等）。

浅拷贝是新容器加上第一层属性的值；那些值若是引用，内外仍共享内层对象。深拷贝会把可拷贝的嵌套结构也做成新对象。两者都不是「栈上传地址、堆上传值」一句话能说完的。

常见坑

  • 把堆说成先进先出，或把栈说成用来放大对象，方向就反了。后进先出的是调用栈；堆不按入栈顺序弹出。
  • 「基本类型和引用类型的区别就是传值与传址」不成立。JavaScript 只有按值传递。共享的是引用这个值。
  • const a = { n: 1 }; const b = a 不是拷贝，只是多了一个名字。
  • 闭包让内部函数抓住外层绑定后，那些绑定会留在堆上的环境记录里，不能假设函数一返回栈帧里的值就全部消失。
  • 递归过深会撑爆调用栈（RangeError: Maximum call stack size exceeded），这和堆内存用尽是两类错误。

引擎还会把不再被任何根（栈、全局、闭包）引用的堆对象收走。标记-清除看的是「还有没有引用」，不是变量出了作用域就立刻把堆内存还回去。局部对象若被返回或放进监听器，函数返回后仍然活着。

引用只是值的一种

把对象放进数组、再从数组里取出来，取出的仍是同一个引用。函数参数、返回值也一样，返回 { ...obj } 才是新对象：

若函数内部 obj = { n: 0 }，外面的 a 不变。这就是「按值传递引用」和 C++ 引用参数的差别。调用栈弹出后，没有别的根指向这块对象，垃圾回收可以收掉它；若返回值被变量接住，堆对象继续活着。

递归每深入一层多一个栈帧，帧里只存当前的局部绑定和返回地址。爆栈报的是 Maximum call stack size exceeded，堆被大数组占满时则是另外的内存错误，两种提示不要互换。

小结

栈管函数调用，后进先出；堆管对象，靠引用访问，由垃圾回收释放。赋值对象时复制的是引用。参数按值传递，不存在改掉外部变量绑定的「传址」。
