jQuery 遍历

2020-11-26
  • jQuery
本文总阅读量次

人去空流水，花飞半掩门。乱山何处觅行云。又是一钩新月照黄昏。

沿 DOM 树移动

遍历是从当前匹配的元素出发，按亲子、兄弟关系再找一层。选择器是「从文档里搜」，遍历是「从手头这份集合挪一步」。

以常见的 div > ul > li 为例：

  1. div 是 ul 的父元素，也是里面所有节点的祖先。
  2. ul 是 li 的父元素，是 div 的子元素。
  3. 左侧 li 是 span 的父元素，是 ul 的子元素，是 div 的后代。
  4. span 是该 li 的子元素，是 ul 和 div 的后代。
  5. 两个 li 互为兄弟。
  6. 右侧 li 是 b 的父元素。
  7. b 是右侧 li 的子元素，也是 ul、div 的后代。

向上

方法 结果
.parent() 直接父元素。可传选择器再滤一层
.parents() 所有祖先，直到 <html>，不含自己
.parentsUntil(selector) 祖先里停在匹配元素之前，不含起点，也不含那个匹配元素
.closest(selector) 从自己开始向上，含自己，找到第一个就停

.closest 和 .parents 的差别：前者包含自己且只要最近的一个，后者不含自己且收集整条链。事件委托里判断「点在哪一行」用 closest。

向下

.children 只看直接子元素，不看更深的孙子。.find 看所有后代，不看自己。.contents 连文本节点和注释也包含，处理表格或 iframe 的内容文档时才会用到。

平级

方法 结果
.siblings() 全部兄弟，不含自己
.next() / .prev() 下一个 / 上一个兄弟元素
.nextAll() / .prevAll() 后面 / 前面的全部兄弟
.nextUntil() / .prevUntil() 直到某个匹配之前，不含那个匹配

这些方法都不把文本节点当兄弟。要滤一层就传入选择器：.siblings(".on")。

过滤当前集合

遍历方法会换成新集合。若只是在当前这些元素里挑选，用过滤：

.eq 下标从 0 开始，负数从末尾数。.filter 可以传选择器、DOM 节点、函数。函数里 return true 的元素会留下，this 是 DOM 元素，下标是第二个参数。

.is(selector) 只回答当前集合里有没有元素符合，返回布尔值，链在这里断开。

.map 返回新的 jQuery 对象，回调的返回值会变成集合里的项。.each 用来做副作用，返回原集合。

回到上一步

.end() 弹出遍历栈，回到调用 find、children、eq、filter 之前的集合。没有上一步时得到空集合。链太长时，用变量接下中间结果，比叠很多 .end() 清楚。
