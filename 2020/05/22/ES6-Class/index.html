所谓爱情，就是你总会遇到一个对的人，他让你感觉生活越来越美好，而不是再黏着过去不肯放手。

class 是构造函数的语法

typeof User 仍是 'function'。User.prototype.greet 是方法，但 class 里的方法默认不可枚举，for...in 扫不到。这和手写 User.prototype.greet = function () {} 不同，那种赋值默认可枚举。

必须用 new 调用。普通调用会抛 TypeError。类体运行在严格模式，即使文件没有 'use strict'。

不会像 var 那样提前可用

class 的绑定在暂时性死区里，声明语句执行前不能用。它不会被提升成可以提前调用的函数。同一作用域不能重复声明同名类。

上面的顺序会在 new 处抛 ReferenceError。

实例字段与方法里的 this

公共字段写在类体顶层，每个实例一份，在 constructor 开头、super() 返回之后初始化（有父类时）。

inc = () => {} 是每实例一个箭头函数，this 固定为实例，拿去当回调不用 bind。代价是它不在原型上，子类不会通过原型共享这一份函数。普通方法 inc() { this.n += 1 } 在原型上共享，但拆出来调用时 this 会丢。

静态成员

static 挂在构造函数上，不在原型上，实例访问不到，除非你再写 this.constructor。静态字段同样每类一份，求值时机是类定义执行时。

私有字段以 # 开头，只能在类体内部访问，外部没有反射 API 能读到。这是语言级私有，和 TypeScript 编译掉的 private 不是一回事，也和 Symbol 键不同。# 字段从 ES2022 起标准化，比 class 语法本身晚。

和工厂函数

只需要闭包里的私有变量、不需要 instanceof 时，工厂函数更短。需要继承、instanceof、把方法放原型上共享时用 class。不要为了「更面向对象」把纯函数包进类。

constructor 返回对象会替换实例

返回对象时，new 的结果是该对象，上面没有 n，instanceof Box 也是假。返回数字或字符串会被忽略，结果仍是 this。

方法在原型上，字段在实例上

m = () => {} 是每个实例一份箭头函数，this 固定为实例，拿去当回调不用 bind。它不在原型上，子类不会共享这一份。普通方法共享，但 const fn = a.m; fn() 在严格模式（类体本身就是严格模式）下 this 是 undefined。

类字段初始化器里不能写 super，里面的箭头函数也不行。私有字段 #n 外部读不到，Object.hasOwn 也看不到。这和 TypeScript 只在编译期检查的 private 不同。

类声明有暂时性死区。声明语句之前 new 会 ReferenceError，不会像函数声明那样提升后可用。
