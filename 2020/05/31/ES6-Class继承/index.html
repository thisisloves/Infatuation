ES6 Class 继承

2020-05-31
  • ES6
本文总阅读量次

我读过一本书，书上说这个世界上有两万个人是会跟你一见钟情的，可惜终你一生都未必能遇见他们中的任何一个。一见钟情不是个魔法，它是命运。

extends 接上原型链

Dog.prototype 的内部 [[Prototype]] 是 Animal.prototype。Dog 函数的 [[Prototype]] 是 Animal，所以静态方法也会继承：Dog.static 能找到 Animal.static。

子类构造函数里，访问 this 之前必须先 super(...)。漏掉会抛 ReferenceError。父类字段也在 super() 返回时初始化。没有写 constructor 时，默认就是 constructor(...args) { super(...args); }。

super 的两种用法

  • super(...) 只出现在构造函数，调用父构造。
  • super.speak() 在方法里调用父类原型上的方法，并且 this 仍是子类实例。

箭头函数没有自己的 super。类字段箭头若要调用父方法，把调用放进普通方法，或在外层方法里写 super。

覆盖与静态

子类同名方法覆盖父类。想扩展而不是替换，就在子方法里调用 super.method()。只覆盖构造、不覆盖方法时，实例方法沿原型链找到父类。

static 方法同样可以用 super。new.target 在父构造里指向真正被 new 的那个子类，可用来做不能直接实例化的基类：

内置类型可以继承

ES6 起可以 class MyArray extends Array。map 等方法返回的类型由 Symbol.species 决定，默认是子类。若希望 map 得到普通数组，覆盖 static get [Symbol.species]() { return Array; }。

ES5 用 Parent.call(this) 加 Object.create 模拟继承时，Date、Array、Error 这类内置构造往往不能正确初始化 this。不要再为新代码写那套寄生组合继承，除非要兼容极旧引擎。

instanceof

dog instanceof Dog 和 dog instanceof Animal 都为真，查的是原型链，不是构造函数的名字。跨窗口、跨 realm 的数组 instanceof Array 会失败，判断数组用 Array.isArray。

写了 constructor 就必须先 super

子类构造函数在 super() 返回之前不能读 this。父类字段也在这时初始化，然后才跑子类字段。没写 constructor 时，默认是 constructor(...args) { super(...args); }。父类 constructor 若返回一个对象，子类的 this 会被换成那个对象。

静态方法沿构造函数继承：Dog.__proto__ === Animal，所以找得到父类的 static。静态方法里的 super 指向父类构造函数。实例方法里的 super.speak() 调用父类原型方法，this 仍是子类实例。类字段初始化器（包括里面的箭头函数）不能写 super，那是语法错误。方法体里的箭头函数可以沿方法捕获 super。
