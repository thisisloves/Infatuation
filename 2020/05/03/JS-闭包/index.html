JS 闭包

2020-05-03
  • JS
本文总阅读量次

慕尔如星，愿守一人心，从天光乍破，走到暮雪白头。

概念

函数执行时会创建环境记录。如果内部函数被拿到外面，仍然可以通过作用域链访问那次执行的绑定，这一对「函数 + 它被创建时的词法环境」就是闭包。

因此：

  • 内层可以读外层和全局的 let / const / var。
  • 外层读不到内层的局部绑定，除非内层把它返回或赋给外部变量。
  • 被闭包引用的绑定，在外层函数返回后仍然活着，不会随调用栈弹出而销毁。

JavaScript 没有 global 关键字。全局绑定写在函数外面即可；浏览器经典脚本里它们也是 window 的属性。在函数里不声明就赋值，只在非严格模式会漏成全局属性，严格模式和 ES Module 会抛 ReferenceError。

常见坑

  • for (var i = 0; i < 3; i++) { fns.push(() => i); } 三个函数共享同一个 i，调用时都得到 3。这不是「闭包失效」，而是闭包忠实地记住了那个唯一的 i。
  • 闭包会延长外层变量的寿命。在长期存活的监听、定时器里引用大对象，大对象就回收不掉。解绑监听或把引用设为 null 即可。对 let 局部变量使用 delete 没有用，delete 只针对对象属性。
  • 「退出函数局部变量一定销毁」在存在闭包时不成立。反过来，没有被任何东西引用的环境可以被回收，闭包不等于必然泄漏。
  • 旧 IE 的 DOM 与 JS 循环引用泄漏是历史问题，不能当成现代浏览器使用闭包就会泄漏。
  • 闭包保存的是绑定，不是调用时的 this。普通内部函数的 this 仍由自己的调用方式决定。要固定外层 this，用箭头函数。

var 循环只有一个绑定。要在回调里留下当时的序号，用 let，或把值当成参数传进一层函数：fns.push(((k) => () => k)(i))。模块和严格模式里，函数内部裸赋值不会再悄悄变成全局变量，以前靠这个「特性」读取外层的写法会直接抛错。

定时器、订阅若持有闭包，取消订阅之前，闭包里的大数组都不会回收。组件卸载时要 clearTimeout 并解除监听。

闭包延长的是被引用的绑定，不是整个外层函数的所有局部变量。没有被内层用到的大对象，外层返回后可以回收。监听和定时器不用了就要解除，否则它们手里的闭包会一直把数据留在堆上。

小结

闭包是函数带着定义时的词法环境。它能把局部状态留在外部可调用的接口后面。用 let 避免循环共享一个 var，不用的监听要卸掉，这样闭包不会无故占着大对象。
