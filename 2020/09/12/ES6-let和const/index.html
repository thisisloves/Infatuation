ES6 let 与 const

2020-09-12
  • ES6
本文总阅读量次

我跨过山，涉过水，见过万物复苏，周而复始，如今山是你，水也是你。

块级绑定

let 和 const 的作用域是一对花括号，不是函数。if、for、以及单纯的 {} 都会形成块。var 只有函数作用域，并且会泄漏到块外面。

每次循环的 i 是新绑定，三次输出 0、1、2。换成 var，三个回调读到的是同一个 i，输出 3、3、3。

暂时性死区

let / const 也会被提升到块的顶部，但提升之后到声明语句执行之前不能读。这段区间叫暂时性死区。读取或 typeof 未声明的 let 会抛 ReferenceError，不像 typeof undeclaredVar 那样得到 'undefined'。

同一作用域里不能先 var a 再 let a，也不能重复 let。var 重复声明则是同一变量。

const 固定的是绑定

const 必须在声明时赋值，之后不能再 = 这个名字。它不让对象变成不可变。

字段仍可改。需要冻结用 Object.freeze，那也只冻浅层。要重新指向别的对象，用 let。

循环里 for (const x of list) 合法，因为每次迭代是新的绑定，不是给同一个 const 重新赋值。for (const i = 0; i < 3; i += 1) 不合法，i += 1 在改绑定。

全局不挂到 window

顶层 var 在浏览器脚本里会变成 window 的属性。顶层 let / const 是脚本作用域的全局绑定，window.n 取不到。模块里的顶层绑定都是模块私有的，无论 var 还是 let，都不会变成 window 属性。

实践

默认 const。绑定需要重新赋值再用 let。新代码不用 var。const 能表达「这个名字不会被重新指向」，阅读时少看一层赋值。

暂时性死区里 typeof 也会抛

typeof 未声明的名字通常得到 'undefined'。名字是本块里的 let / const 且还没执行到声明，typeof 同样抛 ReferenceError。这不是「变量不存在」，而是绑定已经创建但不能读。

循环闭包

for (let i = 0; i < 3; i += 1) 每次迭代一个新的 i，定时器回调读到 0、1、2。var 只有一个绑定，回调全是 3。for (const x of list) 每次也是新绑定，所以 const 可以出现在 for...of 里。for (const i = 0; i < 3; i += 1) 不合法，i += 1 在改同一个绑定。

块级 let 不会变成 window 的属性。旧脚本 var id = 1 之后用 window.id 读取，改成 let 就读到 undefined。模块顶层无论 var 还是 let，都不会挂到 window。

var 在这里不会报重复声明，但它泄漏到整个函数，循环和 switch 里都不要再用它收集「当时的值」。
