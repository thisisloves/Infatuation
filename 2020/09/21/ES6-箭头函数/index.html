ES6 箭头函数

2020-09-21
  • ES6
本文总阅读量次

一往情深深几许，深山夕照深秋雨。

写法

箭头函数是表达式，适合回调。一个参数可以省略括号，函数体只有一条表达式时可以省略花括号和 return。

要返回对象字面量，必须加括号，否则花括号会被当成函数体：() => ({ id: 1 })。

没有自己的 this

箭头函数不绑定 this，沿词法作用域去外层函数找。这解决了回调里 const self = this 的问题。

start 是普通方法，调用时 this 是 timer。箭头回调使用这个 this，而不是 setInterval 传入的全局对象。

若把对象字面量里的方法写成箭头：start: () => { this.n += 1 }，this 在定义时就固定为外层（通常是 undefined 或全局），以后用 timer.start() 也改不过来。对象方法用普通函数或方法简写。

call / apply / bind 改不了箭头函数的 this，第一个参数会被忽略。

另外没有的东西

  • 没有 arguments。要用剩余参数 (...args) => args。
  • 没有 prototype，不能 new。当作构造函数会抛 TypeError。
  • 没有自己的 new.target、super 绑定（写在类里的箭头会使用外层构造时的 super）。
  • 不能用作生成器，没有 function* 的箭头形式。

换行

return 和箭头之间不能换行，否则 ASI 会把 return 变成空返回。参数列表的换行则没问题。

这种换行是合法的。const bad = () => \n { return 1 } 返回的是函数体，不是对象。

什么时候不用

需要动态 this 的方法、需要 arguments 的包装层、构造函数，用 function。很短的转换、数组的 map / filter、以及要继承外层 this 的回调，用箭头。

对象方法写成箭头，this 就固定错了

箭头函数的 this 在定义时沿词法确定，调用点、call、apply、bind 都改不了。回调要外层的 this 时才用箭头；对象自己的方法用方法简写。

没有 arguments，也不能 new

箭头函数里出现 arguments，会去外层普通函数找。外层也没有时抛 ReferenceError。它没有 prototype，new collect() 抛 TypeError。

return 后面立刻换行会被自动分号截断，箭头函数因此返回 undefined。要返回对象就写成 () => ({ id: 1 })，花括号不加括号会被当成函数体。
