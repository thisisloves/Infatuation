thunk 是返回函数的 action creator

reducer 必须同步且纯。请求放在组件或中间件里。redux-thunk 让 dispatch 接受函数：

中间件发现参数是函数，就调用它并传入 dispatch 和 getState，不会把函数送进 reducer。普通对象照旧 next(action)。

configureStore 已经挂上 thunk。再手动 applyMiddleware(thunk) 一次会重复。若 middleware 选项写成数组，必须自己把 thunk 加回去。

返回值

thunk 函数的返回值会成为 dispatch 的返回值，组件里可以 await dispatch(fetchUser(id))。记得 return 那个 Promise。没有 return 时 await 等不到请求结束。

Toolkit 的 createAsyncThunk

重复的 pending / fulfilled / rejected 用 createAsyncThunk 生成。condition 可以在已有请求进行时跳过。abort 用来取消。

slice 的 extraReducers 监听 fetchUser.fulfilled。不要在 reducers 字段里手写同名逻辑再 dispatch 一遍，会处理两次。

和 saga 怎么选

一个请求对应一次 dispatch、逻辑就是「发请求再根据结果 dispatch」，thunk 足够，也更容易用 async/await 读懂。需要取消上一次、竞态、在后台循环监听某种 action 时，saga 的任务模型更清楚。不要两个都接上做同一件事。
