React 入口函数模式

2022-01-25
  • React
本文总阅读量次

相恨不如潮有信，相思始觉海非深。

现在只该记两个入口

React 18 把入口收成两条。React 17 实验里的 ReactDOM.createBlockingRoot 没有成为 18 的稳定 API，文档和脚手架都不应再写它。

  1. Legacy：ReactDOM.render(element, container)。同步渲染，ReactDOM.render 在 18 中弃用。
  2. Concurrent root：createRoot(container).render(element)。来自 react-dom/client。自动批处理、Transition、Suspense 的并发行为都挂在这条入口上。

服务端注水用 hydrateRoot(container, <App />)，不要再用 ReactDOM.hydrate。

createRoot 不等于每一次更新都可中断

旧稿把 legacy 示例写成了 createRoot，又把「可中断」说成两种入口的全部差别，两处都需要改回来。

Fiber 数据结构两种入口都有。差别在调度：

  • Legacy 和并发根上的 同步车道（点击、受控输入、flushSync）走 workLoopSync，render 阶段不让出。
  • 只有并发根上的 过渡车道（startTransition、useDeferredValue、部分 Suspense）走 workLoopConcurrent，每处理一个 Fiber 看一次 shouldYield()。

因此：只把 ReactDOM.render 换成 createRoot，输入框若仍在同一次渲染里绘制几万个节点，该卡还是卡。要让输入保持流畅，得把重活放进 transition。

Legacy 同步更新

下面这段若用 ReactDOM.render 挂载，每次按键都要同步协调 5 万个节点，主线程在这次渲染结束前不会绘制。Scheduler 的 5ms 时间片在这条同步路径上不生效。

「16.7ms」是 60Hz 的帧长，不是这次循环的让出间隔。同步循环没有让出间隔。

并发根加上 Transition

输入用紧急更新立刻反映到输入框；列表放进 startTransition，协调列表时可以让出，新的按键可以打断尚未提交的列表渲染。

isPending 在过渡还没提交时为 true，适合做轻量提示。它不取消过渡，只是告诉你屏幕上的 query 还是旧的。

怎么选

  • 新项目：createRoot。需要降级优先级时再包 startTransition，而不是全局把所有 setState 都放进过渡（那样受控输入会变迟钝）。
  • 老项目：可以继续 ReactDOM.render，但没有自动批处理，也没有可中断的过渡。迁移时先换入口，再逐个把重列表包进 transition，并用 Strict Mode 看副作用是否重复。
