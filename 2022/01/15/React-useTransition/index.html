React useTransition

2022-01-15
  • React
本文总阅读量次

但知前世今生石上刻，佳缘若梦又有几人得。

把一次更新标成可打断

useTransition 返回 [isPending, startTransition]。写在 startTransition(() => { ... }) 里的 setState 使用过渡车道：render 阶段可以让出，来了点击这类同步更新就丢掉算到一半的过渡，从 current 树重做。

它只在 createRoot 的并发根上有并发行为。legacy 的 ReactDOM.render 下，过渡更新不会按时间片让出。

输入框走紧急更新，每键都立刻显示。结果列表走过渡，慢也不堵住输入。isPending 表示有过渡还没提交，适合禁用按钮或显示细进度，不要用它卸载整棵旧树，否则过渡就失去「先留住旧界面」的意义。

和 useDeferredValue

useTransition 包的是你自己触发的 setState。值从父组件传下来、自己不能分成两次 setState 时，用 useDeferredValue 推迟这一份值。两者都是过渡优先级。

不要包住所有更新

把受控输入的 setText 也放进 startTransition，输入会跟着大列表一起变慢，过渡就失去了紧急和滞后的分工。过渡里的函数应是同步的 setState，不要在里面 await。异步完成之后，在那时再调用 startTransition 去提交结果。

isPending 不是加载数据的标志

它只描述 React 的过渡渲染有没有提交。请求中的 loading 仍由你的状态或 Suspense 表示。过渡期间若子树挂起，React 会尽量保留已显示的内容，而不是马上换成 Suspense 的 fallback。
