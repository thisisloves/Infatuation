Redux Reducer

月遇从云，花遇和风，今晚上的夜空很美，我又想你了。

reducer 计算下一份状态

默认参数处理 store 第一次调用时传入的 undefined。不认识的 action 必须把 原来的 state 返回去，不能返回 undefined，否则 store 会报错。

不可变

要更新嵌套字段时复制沿途的对象，其余分支保持原引用。没变的引用让 useSelector 可以跳过渲染。

数组用 map、filter、展开，不用 push、splice。sort 会改原数组，先复制再排序：[...list].sort(...)。

createSlice 里可以直接改草稿，因为 Immer 会记录改动并生成新对象。草稿不要传出 reducer，也不要在草稿上保存外部变量的引用后再在外面改。

拆开再合并

每个 reducer 只管 state 的一支。combineReducers({ counter, todos }) 生成的根 reducer 把 action 交给每一个，再用各自的返回值拼出新根。任何一支的引用变了，根对象就是新的。一支返回原 state，那一支的引用不变。

不要在子 reducer 里读另一支的 state。那样就拆不开，也测不准。跨支的后续动作由 thunk 读 getState() 再 dispatch，或在组件里分两次派发。

不要写的逻辑

  • 请求、localStorage、路由跳转。reducer 会被开发工具重复执行，副作用会执行多次。
  • 根据「第几次调用」改变结果。
  • 修改 action。后面的中间件和别的 reducer 还要读它。

初始 state 写成模块级常量，避免在 reducer 里每次 default 都新建对象。默认参数 state = initialState 只在 state === undefined 时使用，不会在每次 default 分支调用。
