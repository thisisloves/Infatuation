action 是普通对象

action 描述发生了什么，不负责怎么改 state。Redux 要求它是普通对象，并且有 type 字段，类型一般是字符串。数据放在 payload。这是社区约定（Flux Standard Action），不是语言强制的字段名，但开发工具和中间件都按这个认。

type 在整个应用里要能区分来源。Toolkit 的 createSlice 会生成 todos/added 这种带前缀的名字，避免两个模块都叫 added。

action creator

用函数生成 action，调用处不必手写 type 字符串。

creator 本身必须是纯的才好测试。crypto.randomUUID() 放在 creator 里会让测试不稳定，id 可以由调用方传入，或在 thunk 里生成。reducer 不要生成 id。

Toolkit：

prepare 把「外部参数」转成 { payload, meta, error }。reducer 只看见准备好的 payload。

不要把函数当 action 直接交给裸 store

没有 thunk 中间件时，dispatch 的参数必须是普通对象，传入函数会报错。redux-thunk 允许 dispatch 函数，那个函数不是 action，是后面再去 dispatch action 的过程。saga 则只接收普通对象，副作用在 watcher 里做。

异步的三个阶段通常是三个 action：pending、fulfilled、rejected。createAsyncThunk 会帮你生成这三种 type。不要只用一个 type: 'fetch' 然后在 reducer 里判断一堆可选字段。

序列化

开发工具的「禁止非序列化值」检查会拦住放进 action 或 state 的函数、Promise、DOM 节点。日期可以存 ISO 字符串或时间戳。确实要带元数据（例如请求 id）放 meta，不要塞进 state 树长期保存。
