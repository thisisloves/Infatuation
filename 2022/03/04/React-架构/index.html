React 架构

2022-03-04
  • React
本文总阅读量次

愿我如星君如月，夜夜流光相皎洁。

三层，不是两层

React 16 之后可以分成三层。应用代码只接触最外面的入口和组件，中间两层在 react-reconciler 里。

  1. Scheduler：决定哪件更新先做、做到何时让出主线程。
  2. Reconciler：调用组件，对比子节点，在 Fiber 上记下增删改。
  3. Renderer：commit 时把标记落到宿主上。浏览器是 ReactDOM，原生是 React Native，测试渲染器可以产出纯对象。

React 15 没有 Scheduler。Reconciler 递归调用 mountComponent / updateComponent，和 DOM 操作缠在同一次调用栈里，开始了就不能停。层级深时，一次更新超过一帧，输入要等递归结束。

Fiber 把「算出该改什么」和「真正改 DOM」拆开。算的过程在内存里，可以停、可以丢。停的时候页面仍是上一帧的完整界面。

Scheduler 不是 requestIdleCallback 的 polyfill

2017 年前后的介绍常把 Scheduler 说成 requestIdleCallback 的 polyfill。那是设计草案，不是 React 17 / 18 的实现。

requestIdleCallback 只在浏览器认为空闲时触发，页面忙时 React 更新会被推迟；回调的时间预算也不可控。React 的 scheduler 包用 MessageChannel 注册宏任务（setTimeout 仅作退路，因为嵌套定时器有 4ms 下限）。任务开始后看 performance.now()，默认大约 5ms 就 shouldYield()。这是「主动切片」，不是「等空闲」。

子树有没有任何标记，记在 subtreeFlags。React 17 起不再维护 effectList。commit 走树，子树标记为空就整枝跳过。

Renderer 只在 commit 里工作

整棵 WIP 树协调完（或同步更新协调完）才进入 commit。commit 分三段，都不能让出：

  1. before mutation：读 DOM，getSnapshotBeforeUpdate。
  2. mutation：插入、更新、删除 DOM。
  3. layout：useLayoutEffect、componentDidMount / componentDidUpdate，此时浏览器还没绘制。

useEffect 不在这三段里同步执行，而是等浏览器绘制之后再跑。

图里渲染阶段的红框可以中断，中断期间用户看不到半成品 DOM。提交阶段对应的 DOM 变更是一次性做完的。

入口决定走哪条路

  • React 15：递归 Stack Reconciler。
  • React 16–17：Fiber 已在，默认 ReactDOM.render 仍是同步提交。
  • React 18：react-dom/client 的 createRoot 打开并发特性（自动批处理、startTransition、Suspense 的并发行为）。ReactDOM.render 仍可用但已弃用，行为接近 legacy。
  • React 17 实验 API createBlockingRoot 没有进入 18 的稳定入口，新代码不要写它。
