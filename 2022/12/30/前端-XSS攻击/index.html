前端 XSS 攻击

2022-12-30
  • 前端
本文总阅读量次

无可奈何花落去，似曾相识燕归来。

XSS 是把脚本注入到页面里

XSS（Cross-Site Scripting）把脚本注入到别人正在看的页面里执行。缩写不用 CSS，是为了和层叠样式表分开。脚本一旦跑在目标站点的源上，就能读取该源允许脚本读取的内容、冒充用户操作页面。

要发生 XSS，需要两件事同时成立：不可信的内容进了页面，并且浏览器把它当 HTML 或 JavaScript 执行，而不是当文本。

三种类型

反射型。 恶意内容在请求里，服务器原样嵌进响应。常见于搜索词、错误提示直接拼进 HTML。用户要点开攻击者准备的链接才会中招，载荷一般不落库。

存储型。 恶意内容先存进服务器（评论、昵称、工单、客服消息），以后谁打开这段内容谁执行。影响面比反射型大，因为不依赖一次性链接。

DOM 型。 服务器响应可以是干净的。前端把 location.hash、document.referrer、postMessage 的数据写进 innerHTML、document.write、eval、setTimeout(字符串) 才会执行。只在服务端做转义，挡不住这类。

脚本跑起来之后能做什么

在目标源上执行的脚本可以读取没有 HttpOnly 的 Cookie、localStorage 里的令牌，改写页面做钓鱼，或替用户发起站内请求。下面是原理示意，不是可用的攻击步骤：页面若把 Cookie 暴露给脚本，脚本就能把它带到攻击者的地址。

给 Cookie 加上 HttpOnly 之后，document.cookie 读不到它。这不能阻止 XSS 改 DOM、用用户的登录态发请求，所以 HttpOnly 只是缩小损失，不是 XSS 的解法。

location 被脚本改写时，用户会离开原站。富文本、跳转地址都要当成不可信输入。

输出时编码

防护点在「插入到页面的那一刻」，按插入的位置编码，而不是只在入库时删一遍尖括号。

插入位置 做法
HTML 文本 转义 & < > " '。用 textContent、jQuery .text()、框架的默认插值
HTML 属性 同样转义，属性值加引号
URL 参数 encodeURIComponent，并校验协议只允许 http、https、mailto
JavaScript 字符串 用数据接口拿 JSON，不要拼进 <script> 字符串
CSS 不要把用户输入拼进 style

Vue 的 {{ name }} 会转义。v-html、React 的 dangerouslySetInnerHTML、jQuery 的 .html() 不会。用户内容走默认插值。必须渲染富文本时，用服务端或成熟的消毒库按标签白名单清洗，再输出。自己写正则删 <script> 挡不住事件属性、javascript: 链接和畸形标签。

内容安全策略

Content-Security-Policy 规定脚本可以从哪里来。收紧为只允许本站脚本、禁止内联脚本和 eval 后，反射进去的内联片段即使进了 HTML 也不执行。

已有内联脚本的旧站可以先用 Content-Security-Policy-Report-Only 收集违规，再改成强制。CSP 是纵深，代替不了编码。攻击者若能把文件上传成可执行的同源脚本，策略仍可能放行。

其它配套

  • Cookie：HttpOnly、Secure，会话 Cookie 再加合适的 SameSite。
  • 富文本与文件上传分开域名，上传目录不可执行脚本。
  • 接口的 JSON 使用 Content-Type: application/json，避免浏览器把 JSON 当 HTML 解析。
  • 框架要升级到已修复模板注入的版本。DOM XSS 靠代码审查：全局搜 innerHTML、insertAdjacentHTML、eval、document.write。
