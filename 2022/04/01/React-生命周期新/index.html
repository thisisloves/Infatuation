React 生命周期新

2022-04-01
  • React
本文总阅读量次

醉里挑灯看剑，梦回吹角连营。

React 16.3 之后的类组件

挂载：

  1. constructor
  2. static getDerivedStateFromProps
  3. render
  4. componentDidMount

更新：

  1. static getDerivedStateFromProps
  2. shouldComponentUpdate
  3. render
  4. getSnapshotBeforeUpdate
  5. componentDidUpdate

卸载：componentWillUnmount。子树渲染出错时，错误边界还有 static getDerivedStateFromError 和 componentDidCatch。

getDerivedStateFromProps 在每次渲染前调用，包括首次挂载和 props 没变的父渲染。它是静态方法，没有 this，返回部分 state 或 null。这里不能发请求。

shouldComponentUpdate 跳过的范围

返回 false 时，这次不调用 render，也就不会有这次的 getSnapshotBeforeUpdate 和 componentDidUpdate。子组件一起跳过。它不是「这个实例以后再也不走生命周期」。下一次父渲染、自身 setState、forceUpdate 仍会重新进入。卸载时 componentWillUnmount 仍会执行。

PureComponent 用浅比较实现 shouldComponentUpdate。深层字段就地修改时浅比较认为没变，界面不更新。更新要换新对象。

返回 false 不能代替 key。列表节点身份错了，跳过渲染只会把错误留在屏幕上。

getSnapshotBeforeUpdate

在 DOM 提交前调用，参数是更新前的 props 和 state，返回值会交给紧接着的 componentDidUpdate(prevProps, prevState, snapshot)。典型用途是记录列表的滚动高度，提交后把滚动位置加回去。不需要快照时不必实现，返回值用不到就不要存进 state。

错误边界

getDerivedStateFromError 在渲染阶段把错误转成 state，用来显示降级 UI。componentDidCatch(error, info) 在 commit 之后记日志。错误边界抓的是子树的渲染、生命周期和构造函数错误，抓不到事件回调、异步代码、以及边界自身的错误。事件回调里用 try/catch，再把失败写进 state。startTransition 不会接住事件里抛出的异常。

函数组件没有这张表

函数组件用 Hooks 对齐其中几段：useState 初始值对齐 constructor，useEffect 对齐「提交之后」但在绘制之后，useLayoutEffect 才对齐 componentDidMount 的绘制前时机。不要为了凑齐生命周期而把函数组件改回类，除非需要错误边界。
