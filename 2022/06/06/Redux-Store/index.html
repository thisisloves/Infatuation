configureStore 默认启用 thunk，开发环境挂上 Redux DevTools，并检查 state 和 action 能否序列化。

四个方法

  • getState() 返回当前树。不要改返回值。
  • dispatch(action) 同步走完中间件和根 reducer，然后通知订阅者。thunk 中间件遇到函数会先调用函数。
  • subscribe(listener) 在每次 dispatch 结束、state 已被替换后调用。返回取消订阅的函数。listener 里不要假定「哪个字段变了」，它没有参数；需要的话自己 getState() 比较。
  • replaceReducer(next) 热替换根 reducer，日常业务用不到。

在 listener 里同步 dispatch 要小心循环。渲染订阅交给 react-redux，不要在组件里手写 subscribe 再 setState，容易漏掉取消订阅，也绕过 useSelector 的比较。

一份应用一个 store

多 store 会让 DevTools、中间件和 Provider 都要分叉。代码分割用 combineReducers 或 injectReducer 模式往同一 store 上追加分支，而不是 createStore 第二次。服务端渲染时每个请求一个 store，避免用户之间串状态；浏览器里仍然是单例。

store 创建在模块作用域，测试里再单独 configureStore 一份，不要在测试之间共用被改过的那个单例。
