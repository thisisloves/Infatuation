saga 是跑在中间件里的生成器

redux-saga 启动一个不会停的生成器任务，用 yield 描述副作用：监听 action、调用 Promise、再 put 一个普通 action 进 store。reducer 仍然纯。组件仍然只 dispatch 普通对象。

它和 React 的 useEffect 无关。名字都叫副作用，一个在 Redux 中间件，一个在组件 commit 之后。

接入

run 必须在 configureStore 之后调用，否则中间件还没装上。getDefault().concat 才能同时保留 thunk。写成 middleware: [saga] 会丢掉默认中间件。

常用 effect

  • take(type)：停在这里，直到这种 action，返回那个 action。
  • takeEvery(type, worker)：每次都 fork 一个 worker，互不等待。
  • takeLatest(type, worker)：新的 action 到来时取消上一个 worker。搜索框用这个，避免慢响应覆盖新关键字。
  • call(fn, ...args)：调用函数并等待 Promise。把 fn 和参数分开传，测试才能断言「调用了谁」。不要 yield call(() => fetch(url)) 把函数包成无法比较的闭包，除非没有更好的拆法。
  • put(action)：dispatch。不要在 saga 里拿 store.dispatch，测试会变重。
  • select(selector)：读当前 state。
  • fork：不等待的子任务。call 会等完再往下。
  • cancel(task)：取消。被取消的任务要在 finally 里看 yield cancelled() 做清理。
  • delay(ms)：可取消的等待，不要 yield call(() => new Promise(... setTimeout))，那个定时器取消不了。
  • all([...])：并行等待。race({ a, b })：谁先完成用谁，另一个取消。

worker 收到的是已经 dispatch 过的 action。监听的 type 不要和 put 出去的 type 相同，否则自己触发自己。

根 saga

多个 watcher 用 all 同时 fork。一个 watcher 抛错若没有自己的 try，可能停掉聚合任务。每个 worker 内部捕获错误并 put 失败 action，不要让监听循环死掉。

测试与取舍

effect 对象可比较：expect(gen.next().value).toEqual(call(api.user, '1'))。这是 saga 相对 thunk 的优势。业务只是一次请求时，thunk 或 createAsyncThunk 更短。出现「只处理最后一次」「超时竞态」「登录后拉一串初始化」再改 saga。
