React 副作用

2022-02-03
  • React
本文总阅读量次

忆君心似西江水，日夜东流无歇时。

副作用指什么

渲染函数的职责是：给定 props 和 state，返回要显示的 React 元素。请求、订阅、改 document.title、手动改 DOM、记日志，都碰了外部世界，这些是副作用。

render 阶段可能重复执行（并发渲染重做、Strict Mode 的开发期双调用）。副作用若写在函数体或 componentWillMount 里，就会执行多次，而且可能对应一次最终被丢弃的渲染。React 把副作用留到 commit 之后，此时这次更新已经确定要显示。

两类时机

useLayoutEffect / componentDidMount useEffect
时机 DOM 改完、浏览器绘制之前 浏览器绘制之后
适合 量尺寸、同步改 DOM、避免闪烁 订阅、请求、和绘制无关的同步
阻塞绘制 会 不会

类组件的 componentDidMount / componentDidUpdate 位于 layout 阶段，和 useLayoutEffect 对齐，而不是和 useEffect 对齐。从类迁移时，若原逻辑在绘制前读布局，应使用 useLayoutEffect，不要一律换成 useEffect。

Fiber 上怎么记

函数组件每次调用 Hook，都会在 fiber.memoizedState 的链表上追加一个 Hook 节点。useEffect 的节点保存效果函数、依赖和销毁函数。

依赖用 Object.is 和上一轮逐项比较。有变化，commit 之后先跑上一轮的销毁函数，再跑这一轮的效果。依赖数组省略时，每次提交后都跑。空数组只在挂载提交后跑，卸载时跑销毁函数。

React 16 还会把带副作用的 Fiber 串成 rootFiber.firstEffect 引出的 effectList。React 17 起没有这条链表。 效果标记在 flags（含 Passive）和 subtreeFlags 上，commit 走树收集，绘制后再刷被动效果。updateQueue 里存的是该 Fiber 的更新或效果，不是「整棵树共用一条 props 链表」。

清理函数

订阅、定时器、未完成的请求，都要在清理函数里取消。清理发生在：

  1. 下一次效果执行之前（依赖变了）。
  2. 组件卸载时。

Strict Mode 在开发环境会挂载、卸载、再挂载，从而多跑一次效果和清理。这是为了让漏写的清理在开发期暴露。生产环境不会这套双调用。清理写成空函数，开发期就会看到重复请求或重复订阅。

不要用效果去同步派生状态

props 能算出来的值，渲染期间直接算，或包一层 useMemo。用 useEffect 再 setState 会多一次渲染：用户先看到旧派生值，再看到新值。

适合放进效果的，是和外部系统对齐：浏览器标题、非 React 的图表实例、WebSocket、日志。

依赖数组

效果里读到的 props、state，以及在效果里调用且会变的函数，都应出现在依赖里。漏写时，效果闭包抓住的是旧渲染的值，这是 bug，不是优化。

函数若每次渲染都新建，会导致效果每次都跑。处理办法是把函数挪进效果，或用 useCallback 固定引用，或改写成 useEffectEvent（React 19 的实验/稳定 API 以你所用版本的文档为准）去读最新值而不触发重跑。不要用空数组强行「只跑一次」来掩盖漏掉的依赖。
