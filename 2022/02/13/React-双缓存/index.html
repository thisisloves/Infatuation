React 双缓存

2022-02-13
  • React
本文总阅读量次

岁月不堪数，故人不如初。

屏幕上始终是一棵完整的树

绘制引擎常用双缓冲：后台画完一帧，再和前台交换，避免用户看到画了一半的画面。React 的 Fiber 用同一思路。

  • current：已经提交、和屏幕一致的那棵树，挂在 fiberRoot.current。
  • workInProgress：正在内存里算的下一棵。
  • 两棵树上对应的节点用 alternate 互相指向。

render 阶段只写 WIP。即便并发渲染暂停，current 仍指向旧树，DOM 不变。commit 结束时把 root.current 指到这棵完成的树，下一次更新两者角色对调，节点对象会复用，而不是每次都整树新建。

首次挂载

第一次没有 current。createRoot / legacy render 会创建 fiberRoot 和根 Fiber（host root）。根 Fiber 的 alternate 一开始为空，协调过程中创建 WIP 根，再向下创建子 Fiber。

挂载完成，WIP 成为 current。此时每个已提交节点都有一个空的 alternate 槽，留给下次更新。

更新时如何复用

setState 之后从 current 根克隆出 WIP 根（没有 alternate 就 new，有就复用并重置字段）。然后 beginWork：

  1. 对比 pendingProps 和 memoizedProps，类型和 key 相同则走更新。
  2. 子节点用 Diff 决定复用、移动还是新建。
  3. 能复用的子 Fiber 从 current.child 的 alternate 上拿，改 props，而不是重新分配整个对象。

类型或 key 变了，旧子树标 Deletion，新子树标 Placement。这就是「双缓存」和 Diff 的交界：复用的是 Fiber 对象和尽量不变的 DOM，不是强行保留类型已经变了的节点。

中断之后那棵 WIP 作废

并发渲染做到一半若来了更高优先级的更新，当前 WIP 整棵作废，从 current 重新克隆一棵再算。所以 render 阶段必须能重复执行。副作用如果写在 render 里，就会看到执行多次。

commit 不可中断。mutation 阶段按 flags 改 DOM，layout 阶段跑 useLayoutEffect。结束后 root.current 切换，旧的 current 变成下一轮的备用树。

和 effectList 的分工

React 16 还会在 WIP 上另串一条 effectList，commit 只遍历这条链。React 17 起删除了 firstEffect / nextEffect。双缓存仍然在：切换的是整棵 Fiber 树；要不要处理某个节点，看 flags 和 subtreeFlags。没有副作用的子树在 commit 里直接跳过。

应用层能观察到什么

  • 渲染函数可能执行多次，必须保持纯：不要在函数体里订阅、请求、改 DOM。
  • 屏幕在 commit 之前不会出现新状态。useLayoutEffect 能在绘制前读到新 DOM；useEffect 在绘制后。
  • Strict Mode 开发环境会额外挂载再卸载一次，用来暴露漏写的清理函数。这是开发检查，不是双缓存又多了一棵树。
