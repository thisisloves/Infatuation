React 合成事件

2022-02-22
  • React
本文总阅读量次

世间一切幸福，皆月影中一现的昙花；唯有孤独与痛，常伴在黄泉深处。

合成事件是什么

JSX 里的 onClick 不是把监听器绑到这个 DOM 节点上。React 在容器上做事件委托，触发后按组件树找到对应 Fiber，再调用你写的函数。传给函数的是 React 的事件对象，浏览器原生事件在 event.nativeEvent 上。

这样做是为了：抹平一部分浏览器差异、在组件卸载时成批卸掉监听、以及在 React 17 之前用对象池复用事件对象。委托本身今天仍然在，对象池已经不在。

绑在哪：React 16 和 17 不是同一个答案

  • React 16 及更早：原生监听绑在 document 上。组件声明的回调存在内部表里，事件冒泡到 document 再分发。
  • React 17 起（18、19 相同）：监听绑在 createRoot / render 的那个容器 上，不再绑 document。一个页面可以有多棵 React 树，事件先在各自根上处理。

React 15 曾用 enqueuePutListener 等注册路径；Fiber 之后事件系统已重写，不要再按旧源码理解现行实现。

React 17 把根从 document 挪到容器，是为了修复一个具体问题：React 16 里你在组件中 stopPropagation()，document 上的原生监听仍然收得到事件，因为 React 自己的监听就在 document 上，原生传播已经到了那里。绑到根容器之后，在 React 里停止传播，容器外面的 document 监听就收不到了。

stopPropagation 和 preventDefault

两者不要互换。

  • event.stopPropagation() 阻止事件继续传给上层节点。React 树里的父组件 onClick 不会再执行。React 17+ 也会因此到不了根外面的原生监听。
  • event.preventDefault() 阻止浏览器默认行为，例如链接跳转、表单提交、复选框切换。它不停止冒泡。
  • event.stopImmediatePropagation() 连当前节点上其余监听一并停掉，React 里很少需要。

onClick 默认走冒泡。捕获用 onClickCapture。滚动、鼠标移动等部分事件 React 会绑捕获阶段，因为这些事件在浏览器里不一定冒泡，或需要更早截住。

事件池已经取消

React 16 会在监听函数返回后把合成事件的字段清空，放回对象池。异步代码里再读 event.target 会得到 null，要先 event.persist() 或把字段拷出来。

React 17 起取消事件池。 persist() 是空函数。在 setTimeout、Promise 里读 event.target 是安全的。再写「必须 persist」是 16 的习惯。

注意：currentTarget 在函数返回后，React 仍可能把它置空（委托发生在根上，函数结束时当前目标不再有意义）。要留的字段在同步段先拷到局部变量，不要依赖函数返回之后的 event.currentTarget。

和原生监听混用

根容器上的 React 监听和你手写的 addEventListener 是两套。

  • 在 React 子节点上 stopPropagation()，父组件的 React 回调不会跑。
  • 你若在 子 DOM 上用原生监听并停止传播，事件到不了根，React 的 onClick 也不会跑。
  • React 的 onChange 在文本框上实际监听的是 input，不是浏览器的 change。表单元素的命名和 DOM 不完全一一对应。

卸载组件时 React 会卸掉根上的委托和 Fiber 上的回调引用。自己 addEventListener 的，仍要在 useEffect 的清理函数里移除。

批处理

React 17 里，合成事件回调中的多次 setState 会批到一次渲染；原生监听里的不会。React 18 的 createRoot 把原生监听、setTimeout、Promise 也纳入自动批处理。事件系统负责的是「回调何时被调用」，批处理是更新调度的事，不要当成合成事件对象的特性。
