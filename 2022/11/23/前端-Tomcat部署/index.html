前端 Tomcat 部署

Tomcat 是 Servlet 容器

Tomcat 是 Apache 软件基金会名下的项目，实现 Servlet、JSP、WebSocket 等 Java 规范，用来跑 Java Web 应用。它也能当静态文件服务器。它不是「只负责 JSP 的 Apache 插件」。

Apache HTTP Server（常说的 httpd）是另一款 Web 服务器，常用来做反向代理和静态资源。两者可以配合：httpd 对外，通过 AJP 或 HTTP 把动态请求转给 Tomcat。不配置这种转发时，Tomcat 单独监听自己的端口，常见是 8080，和 httpd 是否安装无关。

纯静态前端更适合 Nginx。已经有 Tomcat、又要把构建产物放在同一台机器上时，按下面的方式挂。

放进 webapps

构建得到 dist 或 Hexo 的 public。把这个目录拷进 Tomcat 的 webapps，目录名就是 URL 路径。放在 webapps/blog，访问 http://localhost:8080/blog/。放在 webapps/ROOT，访问 http://localhost:8080/。

先确认构建时的公共路径和这个目录名一致。Vue CLI 的 publicPath、Vite 的 base 若是 /blog/，资源才会从 /blog/js/... 去取。公共路径是 / 却把文件放在 /blog/ 下，页面会空白。

文件名 blog.xml 决定路径，访问 /blog/。docBase 指向构建目录。写在这种独立文件里的 path 会被文件名覆盖，不要靠它改地址，也不要写成 bolg。reloadable 对静态文件没有意义，保持 false。

写进 server.xml 的 <Host> 里也能工作，但改 server.xml 要重启，且容易和升级包冲突。优先使用 conf/Catalina/localhost/*.xml。

改完重启 Tomcat，再访问 http://localhost:8080/blog/。

history 路由要回退到 index.html

hash 路由只有 # 前的路径会打到 Tomcat，静态部署不用额外规则。history 路由刷新 /blog/posts/1 时，Tomcat 会去磁盘上找这个文件，找不到就是 404。

上面的 blog.xml 已经挂了 RewriteValve。规则放在构建目录的 WEB-INF/rewrite.config（应用自己带 META-INF/context.xml 时，阀门写在那一份上，不要和 blog.xml 各写一份）。

Context 上的阀门匹配的是去掉 /blog 之后的路径，-f / -d 也按这条路径在应用里找资源。替换成 /index.html 即可，阀门会把上下文路径再拼回去。规则里再写 /blog，结果会变成 /blog/blog/index.html。

已经存在的 .js、.css 不会被改写。磁盘上没有的静态文件也会落到 index.html，脚本请求的响应体是 HTML。Nginx 上等价的是 try_files $uri $uri/ /index.html。

Hexo 的 _config.yml 里 root 也要是 /blog/。hexo generate 会覆盖 public，rewrite.config 放在 source/WEB-INF/ 才会进入构建产物。

和接口放在一起

Tomcat 上若还有 Java 接口，用不同的 Context 路径，例如静态页 /blog，接口 /api。前端请求使用同一主机下的 /api，就不必为页面单独开 CORS。不要把构建源码目录当成长期文档根还不做更新流程：发布的应是一次构建产物，换版本时替换目录或切换 docBase。
