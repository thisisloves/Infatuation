前端 SSR 服务端渲染

2022-11-13
  • 前端
本文总阅读量次

斗转星移，忧伤轮回，过往成空，却绽放在我梦里最光亮的地方。一纸素笺，画满了流年的殇，一方浅墨，诉尽经年的梦。

SSR 是在服务器上先产出 HTML

单页应用若把空的 <div id="app"> 和一大包脚本发给浏览器，首屏要等脚本下载并执行后才有内容。只做有限脚本执行的爬虫，也可能看不到异步渲染出来的正文。

服务端渲染（SSR）让同一套组件在服务器上先渲染成 HTML 字符串，浏览器立刻能画出内容，随后再把事件绑回去，这个过程叫注水（hydration）。注水是拿服务器给出的标记和客户端第一次虚拟节点对齐，而不是在浏览器里再造一棵无关的 DOM。客户端仍然会启动框架。

方式 首屏 HTML 适用
CSR 基本为空，靠脚本填充 登录后的后台
SSR 每次请求现渲染 内容会变、又要首屏和抓取
SSG 构建时生成静态 HTML 文档、博客、不常变的营销页
ISR 静态页按周期或按需再生 介于静态和实时之间

博客和文档优先 SSG。后台管理系统不必为了首屏上 SSR。

Vue 的两份构建

Vue 2 常见的 webpack 方案会打出两份产物：给浏览器执行的 client bundle，以及给 vue-server-renderer 用的 server bundle。VueSSRServerPlugin 输出的 vue-ssr-server-bundle.json 是包清单，描述入口和各个 chunk。渲染器在 Node 里根据这份清单执行组件，吐出的是 HTML 字符串。这份 JSON 不是发给浏览器的页面。client manifest 是另一份 JSON，用来给 HTML 写上正确的脚本和样式地址。

源码通常分成三份入口：两边共用的应用工厂（每次请求调用一次，避免用户数据留在单例里）、entry-client.js（在浏览器里挂载并注水）、entry-server.js（返回一个接收路由上下文的渲染函数）。

Vue 3 使用 @vue/server-renderer 的 renderToString。Nuxt 把路由、预取和部署收成约定。React 生态里对应的是 Next.js 一类元框架，可以按路由选择 SSR、SSG 或流式输出。

一次请求里发生什么

  1. 服务器按 URL 匹配路由，在渲染前把这一页的数据取完。
  2. 渲染得到 HTML，并把预取数据序列化进页面。客户端用同一份数据注水，避免再请求一次导致标记对不上。
  3. 浏览器先显示这段 HTML。此时按钮还没有事件。
  4. 客户端脚本执行并 hydrate。对齐成功后页面才可交互。之后的站内跳转可以走前端路由，不必每次都整页 SSR。

只写在 mounted 里的请求，服务器渲染时不会执行，HTML 里就没有那块数据。Vue 上把预取放到 serverPrefetch，或放到框架约定的数据钩子里。beforeMount 和 mounted 不会在服务器执行。

注水失败

服务器 HTML 和客户端第一次渲染必须一致。不一致时控制台会出现 hydration mismatch，客户端可能扔掉服务器节点重画，首屏收益就没了。常见原因：

  • 渲染期间使用 Date.now()、Math.random()、window、localStorage。服务端没有 window 和 document。
  • 两边时区或语言不同，日期字符串不一致。
  • 浏览器插件改写了 DOM，或 HTML 嵌套不合法，被浏览器自动纠错。

必须依赖浏览器的分支放到 onMounted，并给服务器输出留稳定占位，避免布局跳。

代价

TTFB 变长，因为要等服务器渲染完才开始响应。热门页应缓存 HTML。服务器吃 CPU，和纯静态托管不是同一量级。全局单例 store 会在并发请求之间串数据，每次请求新建应用和 store。
