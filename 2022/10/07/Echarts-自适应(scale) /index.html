ECharts 自适应（scale 整屏缩放）

2022-10-07
  • Echarts
本文总阅读量次

曲终人不见，江上数峰青。

整屏按设计稿缩放

大屏常用固定设计尺寸（例如 1920×1080），外层用 transform: scale 铺满视口。ECharts 若画在被缩放的节点里，鼠标坐标会偏：画布的像素和事件的 CSS 像素不再 1:1。

稳妥的做法是让图表的 布局宽高用设计像素，缩放只发生在外层，并且把同一比例告诉 ECharts 的 resize。

容器本身保持设计像素的 width / height，不要再用百分比跟着视口变一次，否则等于缩了两次。

鼠标偏移

scale 作用在父节点、图表在子节点时，ECharts 5 会尝试读 getBoundingClientRect 处理一部分变换。父级使用 transform 且中间还有滚动、旋转时仍可能偏。出现点不中柱子时，检查：

  1. 是否对图表 DOM 自己做了 scale，同时又 resize 成视口尺寸。
  2. 是否在 init 之后才加上 transform，没有再 resize。
  3. 页面是否另有 zoom（不是 transform）。zoom 和 scale 对命中计算的影响不同，大屏只用其中一种。

改完样式后调用一次 chart.resize()，让它重新量容器。

和 rem 方案怎么选

整屏大屏、要求严格按 1920 设计稿出图，用 scale，字号按设计像素写死即可，因为缩放由 transform 统一完成。后台管理系统、局部一张图，用容器百分比加 resize，字号若要跟根字号走，再用 rem 那篇的 px() 换算。两套叠在同一张图上，字会过小或过大。

监听

window.resize 会很密。用 requestAnimationFrame 合并，或听容器的 ResizeObserver，只在图表容器变化时 resize。

组件卸载时 observer.disconnect() 并 chart.dispose()。大屏路由切走后若只 display: none 而不 dispose，下次显示宽高为 0 的那次 resize 会留下空白，显示时再 resize 一次。
