Seata 分布式事务

2025-07-31
  • Seata
本文总阅读量次

青山一道同云雨，明月何曾是两乡。

对应练习

  • TC：Seata 安装目录（控制台 7091，RPC 8091）
  • SQL：seata-tc.sql
  • 注册中心：Nacos 8848，服务名 **seata-server**，Group SEATA_GROUP
  • 业务：hmall 中跨服务写操作（如下单扣库存）

为什么本地事务不够用

  • Seata 提供 TC（事务协调者），协调各服务 TM / RM 完成全局事务。

角色

角色 含义
TC Seata Server
TM 事务发起方（开全局事务的业务）
RM 资源管理器（各库的代理数据源）

常见模式

模式 特点 适用
AT 自动生成回滚 SQL，侵入小 多数关系型 DB 场景
TCC Try / Confirm / Cancel，侵入大 高性能、可定制补偿
SAGA 长事务、正向 + 补偿 流程长
XA 强一致，性能差 少用

本地 Demo 多数走 AT。

  • 未单独配 service-port 时，RPC = server.port + 1000 → 8091。

客户端必须对齐的三件事

  1. 注册发现：同一 Nacos、同一 application 名 seata-server、同一 group。
  2. 事务分组映射：
  1. 鉴权：与 Nacos 一致；否则 login failed: User nacos not found。

常见报错

日志 根因 处理
User nacos not found 登录 Nacos 用户不存在 关鉴权并清空账号，或创建用户
no available service found in cluster 'default' 发现不到 TC 或 mapping 错 Nacos 有实例？group/cluster/vgroup 一致？
Address already in use 8091 重复启动 kill 后再启
Decode frame error ... exceeds 非 Seata 协议连到 8091 别用浏览器乱连 RPC 端口

重要：no available service... 出现在 业务进程 日志里时，说明客户端发现失败；TC 的 start.out 里若已 Server started，优先查 客户端 yml，而不是反复重启 TC。

AT 模式业务写法示意

  • 数据源需接入 Seata 代理（各 Boot starter 文档略有差异，按你用的 Seata 版本配置）。
  • 回滚依赖 undo_log 表；业务库要建好 AT 所需表。

推荐排障顺序

小结

  • Seata 不是「启动一个 jar 就完事」，而是 TC + Nacos 发现 + 客户端映射 + 业务 @GlobalTransactional 整条链。
  • 确认 TC 可运行、Nacos 能看见 seata-server 后，把业务工程里的 Seata 配置与 vgroup-mapping 对齐，常见报错就会收敛。
