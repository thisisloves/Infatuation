Docker

2025-07-03
  • Docker
本文总阅读量次

长风破浪会有时，直挂云帆济沧海。

对应练习

  • 在 Linux 上安装 Docker，拉起 MySQL 与 Nacos，给 hmall 的 user-service、item-service、cart-service 提供依赖
  • 用一份最小 Dockerfile 打包服务，用 compose 把中间件编排起来

镜像、容器与仓库

名称 是什么 在练习里
镜像 只读模板，按层存放 mysql:8.0、Nacos 镜像、自己构建的业务镜像
容器 镜像的运行实例，顶上多一层可写层 一个 MySQL 容器、一个 Nacos 容器
仓库 存放、分发镜像 默认 Docker Hub；内网可自建私有仓库

只读层能被多个容器共享。容器里新改的文件在可写层，容器删除后可写层一起消失。数据库文件必须进数据卷，不能只留在可写层。

docker pull mysql:8.0 从仓库拉镜像，docker push 推到仓库。标签要写明版本，避免用浮动标签导致练习环境前后不一致。

在 Linux 上安装

以 CentOS 为例：卸掉旧包，加上 Docker 仓库，安装引擎并开机自启。Ubuntu 把 yum 换成 apt，仓库地址换成对应发行版，后面的启用步骤相同。

docker version 里要同时有 Client 和 Server。只有 Client，说明守护进程没起来，用 systemctl status docker 看原因。

国内拉取慢时，在 /etc/docker/daemon.json 配置 registry-mirrors，再执行 systemctl restart docker。需要部署的账号可以加入 docker 组，重新登录后免去 sudo；这个组的权限很大，不要随便加。

常用命令

-d 表示后台运行，--name 方便后面按名字操作。六个命令覆盖练习里的主路径：

命令 作用
docker run 本地没有镜像就先拉取，再创建并启动容器
docker ps 正在运行的容器；-a 连同已退出的一起列出
docker logs 标准输出。-f 持续跟踪，--tail 只看末尾
docker exec 在运行中的容器里执行命令
docker stop 发送停止信号，留时间给进程收尾
docker rm 删除已停止的容器。仍在运行时要先 stop，或加 -f

配套命令：docker images 看本地镜像，docker rmi mysql:8.0 删除镜像，docker start mysql 再次启动已停止的容器。镜像仍被容器引用时删不掉，先 docker rm。

业务先打成 jar。基础镜像的 JDK 主版本与编译目标保持一致，下面按 17 书写。

EXPOSE 只是文档声明，对外端口仍由 docker run -p 决定。docker build 最后的 . 是构建上下文，Dockerfile 与 jar 放在同一目录。用 .dockerignore 排除无关文件，避免把本地配置打进镜像。

docker-compose

逐条 docker run 难以复现。compose 用一份文件描述一组服务。文件名为 docker-compose.yml，在该目录执行 docker compose up -d。

docker compose ps 看状态，docker compose logs -f nacos 看日志，docker compose down 停止并删除这组容器。命名卷默认保留。写了 container_name 就不能把同一个服务扩成多个副本，练习环境这样固定名字便于记忆。

端口映射与数据卷

映射格式是 宿主机端口:容器端口。左边给外部访问，右边是容器内进程监听的端口。两边可以不同，例如 -p 13306:3306，连接串就要写 13306。

  • 宿主机端口已被占用时容器起不来。docker ps 看不到它，用 docker ps -a 和 docker logs 确认
  • 进程若只监听 127.0.0.1，端口即使映射出去也会拒绝连接，服务要监听 0.0.0.0
  • Nacos 2.x 除 8848 外还要映射 9848。只开 8848 时，客户端常见现象是连上又马上断开
卷的写法 含义 适合
mysql-data:/var/lib/mysql 命名卷，目录由 Docker 管理 数据库，容器删除后数据仍在
./conf:/app/conf 绑定挂载，直接用宿主机目录 配置文件，修改后重启进程即可

docker rm 不会删除命名卷。连数据一起清掉时用 docker volume rm，或 docker compose down -v。绑定挂载的 MySQL 目录权限不对时，容器会反复退出，日志里是数据目录不可写。

排错

现象 处理
version 只有 Client 守护进程未启动，看 systemctl status docker
pull 超时 配置镜像加速后重启 Docker
端口已映射仍连不上 核对冒号左右、容器内监听地址、Nacos 是否缺 9848
容器重建后库表没了 没挂卷，数据写在可写层

小结

镜像是模板，容器是运行实例，仓库负责分发。hmall 依赖的 MySQL 和 Nacos 用 compose 固定端口与卷；业务 jar 用最小 Dockerfile 即可进容器。先确认 docker ps 里状态为 Up，再去连 3306 和 8848。
