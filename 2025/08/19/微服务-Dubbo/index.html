微服务 Dubbo

2025-08-19
  • 微服务
本文总阅读量次

业精于勤荒于嬉，行成于思毁于随。

RPC 和 HTTP

RPC 把远程调用写成一次方法调用。契约是接口，传输常用二进制和长连接。HTTP 把调用写成请求，契约是路径、动词和报文，JSON 容易被网关和其它语言接住。

Feign 写出来也是接口方法，底下仍是 HTTP。Dubbo 的代理走 RPC。两者都藏起了套接字，差别在报文、连接，以及治理能细到哪一层。

Dubbo 协议基于 TCP 长连接，序列化常用 Hessian2。Dubbo 3 的 Triple 跑在 HTTP/2 上，可以对接 Protobuf，其它语言更容易接入。选协议时看调用方是不是都在 Java 进程里。

四个角色

角色 做什么
Provider 暴露实现，启动时把地址注册出去
Consumer 按接口订阅地址，通过代理发起调用
Registry 保存并推送提供者列表，常见是 Nacos、ZooKeeper
Monitor 收集次数与耗时，异步上报，不决定这一次调用成败

提供者把「接口、地址、版本」登记到注册中心，消费者订阅同一份接口。列表到达消费端后写在本地缓存里。注册中心短时不可用时，已经缓存的地址仍可继续调用。Monitor 停掉，主调用路径还在。

一次调用怎么走

真正发请求时，消费端在本地列表里选一台，不必为这一次再问注册中心。过滤器可以放鉴权、超时日志，业务实现只处理参数和返回值。提供端线程还在执行时，消费端可能已经因为超时返回，所以写操作要能识别重复请求。

和 Spring Cloud 怎么选

Spring Cloud 里常见的调用方式是 Feign 加 HTTP，旁边还有配置、网关和限流。Dubbo 专注远程调用和接口级治理，服务发现、配置可以交给 Nacos。两边都能注册到同一个 Nacos，报文仍是各自的。

更合适 条件
Dubbo 双方主要是 Java，调用频繁，需要版本、分组、按方法设置超时
Feign + HTTP 对外、多种语言，或请求要经过 HTTP 网关
两边都留 对外走 HTTP，内部 Java 服务走 Dubbo

版本和分组用来并排放两套实现。同一接口可以有稳定版和灰度版，消费者只订阅其中一组。选 Dubbo 还是 Feign，看契约要接口还是要 HTTP 资源，以及谁来调用。注册中心选 Nacos 还是 ZooKeeper，不代替这个选择。

序列化、超时、重试、负载均衡

序列化把对象变成字节。Hessian2 比 JSON 小，字段类型一改，旧字节就可能解不开。Triple 配 Protobuf 时，用编号字段兼容新增项。两端必须是同一套序列化，发布时一起换。

超时是消费端愿意等的上限，默认大约 1000 毫秒。到点后调用方不再等。提供端那次计算未必已经停下，超时只保证调用方线程被释放。这一跳的超时要短于调用方自己的截止时间，故障才会先在这里暴露。

重试默认随 Failover：失败或超时后换一台提供者，额外再试的次数默认是 2，一共最多打到 3 台。查询可以保留重试。下单、扣款把次数设为 0，失败直接返回。若业务带了幂等号，重试才不会变成两笔。

负载均衡在本地列表上挑机器。随机和轮询把流量摊开。最少活跃把请求交给手头更空的提供者。一致性哈希让相同参数落到同一台，适合提供端按参数做了本地缓存的接口。默认是随机。

@DubboService 标在实现类上，@DubboReference 标在消费端要注入的字段上。上面的引用等待 800 毫秒，失败不换机器重试，适合不能做两次的写。读方法可以单独把 retries 放开。版本号两边写成同一个，订阅才会落到这套实现。

失败时换不换机器

请求跨过进程之后，结果分成四类。

结果 含义 重试
成功 实现已经返回 不必
业务异常 请求到达了实现，结果明确 换机器通常没用
超时 调用方停止等待，提供端可能仍在执行 写操作不要再打一遍
连不上 请求多半没进实现 可以换一台

Failover 是默认容错：超时或连不上就换提供者，额外次数默认 2。Failfast 失败立即返回，不再换机器。Failsafe 吞掉异常，适合可以丢失的通知。Forking 并行打出多台，取最先返回的，适合对延迟敏感的读。

读和写使用不同的超时与重试，可以写到方法上：

分组把同一接口的提供者划开，例如稳定组和灰度组，消费者只订阅自己的组。版本号留给不兼容的改动：语义断掉时升版本，旧消费者继续订旧版本。过滤器适合记耗时、传递追踪号，业务判断仍放在实现里。

小结

  • RPC 以接口为契约，HTTP 以资源和报文为契约。Feign 走 HTTP，Dubbo 走 RPC。
  • Provider 注册，Consumer 订阅并缓存，Registry 负责名单，Monitor 只做统计。
  • 对内高频的 Java 调用用 Dubbo，对外和多语言用 Feign，边缘与内部可以并存。
  • 写操作把重试设为 0。超时、序列化、负载均衡按接口约定，两端协议保持一致。
