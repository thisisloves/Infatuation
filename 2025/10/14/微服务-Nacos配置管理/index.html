微服务 Nacos 配置管理

2025-10-14
  • 微服务
本文总阅读量次

问渠那得清如许，为有源头活水来。

对应练习

  • 配置中心仍是 Nacos 8848，与注册发现共用同一进程
  • 共享配置：数据源等每个服务都一样的项
  • 私有配置：某个服务自己的业务参数，用 @RefreshScope 热更新
  • hm-gateway 监听 gateway-routes.json，改路由不必重启网关

配置中心解决什么

注册中心回答「实例在哪」。配置中心回答「参数现在是什么」。jdbc、日志级别、分页大小、网关路由如果写死在每个服务的 application.yml 里，改一处就要重新打包或至少重启全部进程。

这些内容放到 Nacos 后，按 dataId 管理。客户端用长轮询等变更：配置没变，请求挂起；变了马上返回。进程收到新内容后刷新 Environment。标了 @RefreshScope 的 Bean 会销毁并按新环境重建。

共享配置

多个服务相同的项抽成共享 dataId，例如 shared-jdbc.yaml。某个服务才有的键放在自己的 dataId 里，例如 cart-service.yaml。同名键以后加载的为准，所以共享放前面，服务自己的放后面。

业务键只放 Nacos，本地不要再写一份，否则分不清运行中到底用的是哪边。本地留下应用名、端口，以及 Nacos 的地址——没有地址就连不上配置中心。

控制台新建配置时 dataId 要带对扩展名，格式选 YAML。item 与 cart 的库地址不同，url 放各自的 dataId；驱动类名、连接池大小、日志格式才放共享文件。

bootstrap 与 spring.config.import

旧写法依赖 bootstrap.yml，并且要有 spring-cloud-starter-bootstrap。没有这个依赖时，bootstrap.yml 不会生效，服务能启动，配置却全部落回本地，看起来像「Nacos 没配上」。

file-extension: yaml 时，自动拼出来的 dataId 是 cart-service.yaml。若还有 spring.profiles.active: dev，还会再要一份 cart-service-dev.yaml。共享项要 refresh: true 才会参与热更新。

新写法不需要 bootstrap，在 application.yml 用 spring.config.import。值里有冒号，YAML 必须加引号，否则启动阶段就解析失败。

optional: 表示这份 dataId 暂时不存在也允许启动，适合练习时一边写代码一边在控制台补配置。正式环境去掉 optional:，缺配置就应该失败，而不是带着空数据源跑起来。两种写法选一种，不要 bootstrap 和 import 各写一半互相覆盖。

热更新

@Value 所在的 Bean，或绑定配置的属性类，加上 @RefreshScope。范围尽量小，不要标在数据源这种重建成本高的对象上。

改完没变化时，按顺序看：dataId 是否多了或少了 .yaml；refresh / refreshEnabled 是否打开；属性类有没有 @RefreshScope；键名是 page-size 还是 pageSize（松绑定可以对应，前缀必须一致）。

动态路由

网关路由也可以放进 Nacos，但这条链路不是 @RefreshScope。hm-gateway 里的 DynamicRouteLoader 用配置订阅接口直接监听一个 JSON dataId。它和 file-extension 的自动拼接无关，dataId 写什么就要在控制台建什么。

课堂用的 dataId 是 gateway-routes.json，Group 是 DEFAULT_GROUP。启动时先拉一次，再用监听器等后续修改。

updateConfigInfo 的步骤：把 JSON 解析成路由定义；保存新路由；删掉这次配置里已经不存在的 id；发布 RefreshRoutesEvent。只改内存、不发这个事件，网关仍走旧路由。

lb:// 表示按服务名负载均衡，item-service 必须已注册。Path 的参数名用 pattern（有的版本写作 _genkey_0），写错时日志是解析异常，控制台仍显示已保存。改 JSON 后不用重启网关；先用静态路由确认转发，再打开监听。

排错

现象 排查
仍是本地值 是否引入了 config 依赖；bootstrap 是否缺 starter；import 是否加了引号
控制台有配置，进程没用上 dataId、Group、命名空间 ID；profile 是否多拼了一段 -dev
改了不刷新 共享配置的 refresh，或 import 上的 refreshEnabled；Bean 是否 @RefreshScope
路由不更新 监听的 dataId 是否就是 gateway-routes.json；是否发布了 RefreshRoutesEvent
启动即失败 去掉 optional 后 dataId 不存在，或 YAML 缩进在控制台里是坏的

小结

共享配置放公共 dataId，服务差异放 ${spring.application.name}.yaml，后加载的覆盖先加载的。bootstrap 与 spring.config.import 二选一，热更新靠 @RefreshScope 加刷新开关。网关路由用单独的 JSON 监听，改完要发布刷新事件才会换成新转发规则。
