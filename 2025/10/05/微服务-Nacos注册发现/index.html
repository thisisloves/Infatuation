微服务 Nacos 注册发现

2025-10-05
  • 微服务
本文总阅读量次

山重水复疑无路，柳暗花明又一村。

对应练习

  • 注册中心：Nacos，控制台端口 8848
  • 服务：user-service、item-service、cart-service 启动后出现在服务列表
  • 调用：RestTemplate 加 LoadBalancer，用服务名访问，而不是写死 IP

注册中心在做什么

每个服务启动后向 Nacos 登记四样东西：服务名、IP、端口、健康状态。调用方只认服务名，向 Nacos 订阅实例列表，再自己挑一个去连。

实例用心跳报活。心跳断了，Nacos 把该实例摘掉，调用方的列表跟着变短。进程恢复后重新登记，列表又变长。调用方不用改配置。

注册中心自己也要能用。练习用单机；正式环境用集群，避免 Nacos 一停，所有调用方都失去实例列表。

安装和启动

解压 Nacos 后进入 bin。单机模式必须带参数，否则会按集群方式找同伴，起不来。

Windows 对应 startup.cmd -m standalone。控制台是 http://127.0.0.1:8848/nacos。

Nacos 2.x 的 HTTP 在 8848，客户端实际通信还走 gRPC 9848（端口偏移 1000）。用 Docker 时两个端口都要映射。只开 8848 时，现象经常是「控制台能开，服务却注册不上」。

鉴权关闭时，客户端不要填用户名和密码。鉴权开启时，默认账号是 nacos / nacos，客户端配置必须和开关一致，否则会报用户不存在。

启动顺序：先 Nacos，再 user-service、item-service、cart-service。

服务注册

父工程用 Spring Cloud Alibaba 的 BOM 对齐版本，子模块不各自写版本号。

spring.application.name 就是注册上去的服务名，调用方以后用这个名字访问。

namespace 留空表示公共命名空间。控制台里它的名字叫 public，ID 是空字符串。写成 public 会去找一个 ID 恰好叫 public 的空间，服务会注册到别的地方，默认列表里却是空的。

自建的 dev、test 空间要填控制台生成的 ID，不能填显示名称。group 默认 DEFAULT_GROUP，提供方和调用方必须相同。

多实例

同一服务名、不同端口，就是两个实例。在两台终端分别指定端口：

控制台中 item-service 的实例数应为 2，IP 相同、端口不同。默认是临时实例，靠心跳维持；进程退出后会从列表消失。练习不要改成持久实例。

集群名保持默认。调用方会优先选同集群实例，两边集群名不一致时，列表里明明有实例，调用却失败。

发现与负载均衡

RestTemplate 只要加 @LoadBalanced，主机名就会按服务名解析。若启动时提示缺少 LoadBalancer，补上 spring-cloud-starter-loadbalancer。新版 Nacos 发现 starter 有时已经带上它，缺了再加即可。

这里的 item-service 必须和对方的 spring.application.name 一致，大小写也要一致。路径仍是对方 Controller 的路径。LoadBalancer 从 Nacos 拿实例列表，默认轮询。在两个实例里各打一行日志（带上 server.port），连续请求应交替出现。

不要在加了 @LoadBalanced 的 RestTemplate 上再写 127.0.0.1。那个 Bean 会把主机名当成服务名去 Nacos 查。访问不在注册中心里的地址时，另建一个普通 RestTemplate。

Namespace 与 Group

维度 作用 写错时的现象
Namespace 隔离环境，如 dev 与 test 控制台选错空间，列表是空的
Group 同一空间内再分组 一边 DEFAULT_GROUP，另一边自定义组，互相看不见
服务名 调用时的主机名 能注册，但 RestTemplate 报没有可用实例

三处加上 server-addr，一共四处，必须和调用方对齐。改完要重启进程；只保存 yml 不会重新注册。

排错

现象 排查
列表没有服务 命名空间是不是把 public 写成了字面量；8848 与 9848 是否都通
有实例但调用失败 服务名、Group、集群名；是否误用了带负载均衡的 RestTemplate 去访问 IP
用户不存在 服务端鉴权开关和客户端用户名密码不一致
实例数一直是 1 第二次启动端口没改，新进程没有监听成功

小结

Nacos 回答「这个服务名现在有哪些实例」。item-service 可以起多份，cart-service 只用服务名加 @LoadBalanced 的 RestTemplate。Namespace 用 ID，Group 两边相同，2.x 记得 9848。URL 仍要手写，下一步用 OpenFeign 收成接口。
