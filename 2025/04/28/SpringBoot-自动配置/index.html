Spring Boot 自动配置

2025-04-28
  • SpringBoot
本文总阅读量次

随风潜入夜，润物细无声。

@SpringBootApplication 由什么组成

@SpringBootApplication 是组合注解，展开后主要是三块：

  • @SpringBootConfiguration：启动类本身可写 @Bean。
  • @EnableAutoConfiguration：把依赖里登记的配置类有条件地装进容器。
  • @ComponentScan：默认扫描启动类所在包及子包。启动类应放在根包，否则 Service、Controller 注册不上。

排除某一项自动配置：exclude = DataSourceAutoConfiguration.class，或配置项 spring.autoconfigure.exclude。

@EnableAutoConfiguration 做了什么

它通过 @Import(AutoConfigurationImportSelector.class) 收集候选类，再过滤：

  1. 读所有 jar 中登记的自动配置类全名。
  2. 去掉 exclude 指定的类，并处理 AutoConfigureBefore / AutoConfigureAfter 顺序。
  3. 条件不满足的配置类直接跳过，不注册其中的 @Bean。
  4. 通过的类按普通 @Configuration 解析。

「引入 starter 就出现数据源」不是约定俗成的魔法：starter 把自动配置类和第三方库一并带上 classpath，条件成立后才创建 Bean。

spring.factories 与 AutoConfiguration.imports

登记文件随版本变化，排查时两个位置都要看：

版本 位置
Boot 2.6 及更早 META-INF/spring.factories 里 EnableAutoConfiguration 键
Boot 2.7 起推荐 META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports
Boot 3 只认 .imports，不再从 spring.factories 加载自动配置

条件注解

条件用来避免「类不在 classpath 上仍去创建 Bean」。

注解 何时通过
@ConditionalOnClass 指定类能加载到
@ConditionalOnMissingClass 指定类不存在
@ConditionalOnBean 容器里已有某类型 Bean
@ConditionalOnMissingBean 还没有该 Bean，便于业务方覆盖默认实现
@ConditionalOnProperty 配置项存在且等于期望值
@ConditionalOnWebApplication 当前是 Servlet 或 Reactive Web 应用

业务工程里自己声明了 DemoClient 时，上面这个 @Bean 不会再生效。这是自动配置让出控制权的标准手法。

如何排查

  1. 配置里临时打开 debug: true（或启动参数 --debug）。日志中有 Positive matches 与 Negative matches，未生效项会写明缺类、缺配置或已有用户 Bean。
  2. 对着「没出现的那个类名」在报告里搜索，比通读整份清单快。
  3. 直接打开依赖 jar，读 *AutoConfiguration 上的条件，和当前 classpath、配置项对照。
  4. 已引入 Actuator 且暴露端点时，/actuator/conditions 是同一份报告的运行期视图。

报告很长，只在本地排错时打开。生产环境不要靠它。

自定义 starter 的思路

starter 是普通 jar，职责拆开更清晰：

  1. 自动配置类加条件，缺类就跳过。
  2. 对外暴露的 Bean 加 @ConditionalOnMissingBean。
  3. 配置项用 @ConfigurationProperties，并在配置类上 @EnableConfigurationProperties。
  4. 用 @ConditionalOnProperty(prefix = "demo", name = "enabled", matchIfMissing = true) 提供总开关。
  5. 不要在 starter 里扫描业务包，也不要写死地址、账号。

使用方只加 starter 依赖、按需改配置；要换实现时自己声明一个 Bean 即可覆盖。

小结

  • 自动配置 = 清单里的配置类 + 条件过滤，不是扫描整个 classpath 上所有类。
  • 版本不同，清单在 spring.factories 或 AutoConfiguration.imports。
  • 生效与否先看条件报告，再判断是缺依赖、被 exclude，还是被自定义 Bean 覆盖。
