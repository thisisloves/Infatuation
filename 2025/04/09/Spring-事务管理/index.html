Spring 事务管理

2025-04-09
  • Spring
本文总阅读量次

君子一言，驷马难追。

声明式事务在做什么

业务方法上加 @Transactional，成功则提交，失败则回滚。连接的获取、提交、回滚不必写在每个 Service 里。

它仍然是 AOP：容器为 Bean 生成代理，外部调用先进入事务拦截器，再执行目标方法。

默认事务管理器是 DataSourceTransactionManager（JDBC / MyBatis）。JPA 则对应 JpaTransactionManager。一次事务绑定在当前线程的 ThreadLocal 上，方法返回后清理。

最小可用写法

  • 注解加在 Service 实现类 的方法上，事务边界是业务用例，不是 Mapper 里每一条 SQL。
  • 只读查询可标 readOnly = true，便于驱动或连接池做优化，不能代替加锁。
  • 需要超时保护时设置 timeout，避免慢 SQL 一直占着连接。

传播行为

传播解决的是「方法 A 调方法 B 时，B 要不要并进 A 的事务」。

传播 行为
REQUIRED（默认） 有事务就加入，没有就新建
REQUIRES_NEW 挂起当前事务，另起一个；新事务单独提交或回滚
NESTED 已有事务则建保存点，内层失败可只回滚到保存点；没有事务则同 REQUIRED
SUPPORTS 有事务就加入，没有就以非事务执行
NOT_SUPPORTED 挂起当前事务，以非事务执行
MANDATORY 必须已有事务，否则抛异常
NEVER 必须没有事务，否则抛异常

常见组合：下单用 REQUIRED；操作日志、消息记录用 REQUIRES_NEW，避免主业务回滚时把日志也抹掉。NESTED 依赖 JDBC 保存点，不是所有资源管理器都支持。

外层捕获了内层异常时，内层若已把事务标成 rollback-only，外层再提交会得到 UnexpectedRollbackException。该回滚就让异常继续抛出。

隔离级别

isolation 不写时用数据库默认。MySQL InnoDB 默认是可重复读，Oracle 默认是读已提交。

级别 含义 代价
READ_UNCOMMITTED 可读到未提交数据 脏读
READ_COMMITTED 只读已提交数据 不可重复读
REPEATABLE_READ 同一事务内重复读取一致 幻读是否出现视数据库实现
SERIALIZABLE 串行执行 锁范围大，吞吐下降
DEFAULT 跟随数据库 / 驱动 要知道线上库的默认值

隔离解决的是并发读到什么，传播解决的是事务边界如何嵌套。两边要分开看。资金类更新仍要配合条件更新或锁，不能只调高隔离级别。

什么情况下会失效

代理只包住 从外部进来的调用。下面几种是排障时的固定检查项。

  1. 同类自调用。this.save() 不经过代理，注解形同虚设。把被调用方法挪到另一个 Spring Bean，通过注入调用。
  2. 非 public 方法。默认代理模式只拦截 public 方法。写在 protected、private 上的注解不会生效。
  3. 受检异常默认不回滚。未捕获的 RuntimeException 和 Error 会回滚；受检异常会提交，除非写明 rollbackFor。
  4. 异常被吃掉。方法内部 catch 后不再抛出，拦截器认为成功，照常提交。
  5. 对象不是容器里的代理。自己 new 出来的 Service 没有事务。SSM 里若子容器又扫了一遍 Service，事务 Advisor 可能绑在错误的那一份 Bean 上。
  6. 跨线程。事务存在调用线程上，线程池里的新任务不会继承外层事务。

和 SSM、Boot 的关系

要点 SSM Spring Boot
开启 <tx:annotation-driven/> 或 @EnableTransactionManagement TransactionAutoConfiguration 已开启
管理器 手写 DataSourceTransactionManager 并注入数据源 classpath 有数据源时自动配置
容器 Service 放在根容器，避免子容器再扫一遍 通常只有一个容器
写法 @Transactional 加在 Service 相同，语义不变

Boot 没有另一套事务模型，只是少写了管理器和开启注解。失效场景与 SSM 一致。MyBatis 的 SqlSession 加入的是 Spring 管理的同一条连接，不要在事务方法里再手动开关 SqlSession 事务。

小结

  • @Transactional 是代理上的环绕逻辑：按传播加入或新建事务，按异常规则提交或回滚。
  • 先记默认值：REQUIRED、库的默认隔离、运行时异常才回滚。
  • 不生效时按顺序查：是不是代理调用、是不是 public、异常有没有被吞、rollbackFor 是否覆盖到。
