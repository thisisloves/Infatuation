建表、改表、删表

  • 下面以 MySQL 为例。表操作是 DDL，InnoDB 里多数 DDL 会隐式提交当前事务，不能靠 ROLLBACK 收回。
  • DROP TABLE 删掉表定义和数据。TRUNCATE TABLE 清空数据并重置自增，同样是 DDL，比逐行 DELETE 快，也没有 WHERE。DELETE 是 DML，可以带条件，在事务里可以回滚。
  • INT(10) 里的数字是显示宽度，不是取值上限。整数范围由类型决定（INT 约 ±21 亿）。MySQL 8.0.17 起这个显示宽度已弃用，列定义写成 INT 即可。

  • CREATE TABLE ... AS SELECT（CTAS）按查询结果建表并写入数据。MySQL 里这样得到的表没有原表的主键、索引、外键和 AUTO_INCREMENT。WHERE 1 = 2 能造出空表，列来自查询，约束仍然不会跟过来：

  • 若写成 INSERT ... (password, user, dept) SELECT user, password, detail，第一列的用户名会进密码列。列名不会自动配对。
  • 目标表有主键或唯一键时，重复值会让整条语句失败。只补不存在的行时，改用 INSERT IGNORE 或 ON DUPLICATE KEY UPDATE，并确认忽略错误是预期行为。

查表结构

  • SHOW CREATE TABLE 能看到引擎、字符集和索引。只看 SHOW COLUMNS 会漏掉「数据复制了、索引没复制」这件事。

常见坑

  • CTAS 之后用业务 SQL 去查，优化器没有原来的索引可用，大表上会变成全表扫描。复制结构用 LIKE，再 INSERT ... SELECT。
  • SELECT * 的列顺序跟着表定义走。源表中途加过列，目标表仍是旧结构时，不写列名的插入会对错位。
  • 表名、列名若是保留字（如 user、order、like），用反引号包起来。
  • RENAME 在同一实例的库之间可以很快，因为它改的是名字。跨实例要导出再导入，那才是真正的数据拷贝。

改列与索引

  • 大表上的 ALTER 可能锁表或用瞬时 DDL 在后台重建，视版本和算法而定。先在从库或备份上看执行时间，再在业务低峰做。
  • 删除列会丢掉这一列的数据，语句本身成功就结束，没有「回收站」。拿不准时先加新列、双写，再删旧列。
  • CREATE TABLE 不写 ENGINE 时用服务器默认引擎。要事务、行锁和外键，表应当是 InnoDB。SHOW TABLE STATUS LIKE 'staff' 能看到实际引擎。
