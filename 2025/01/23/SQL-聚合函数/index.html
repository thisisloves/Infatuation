SQL 聚合函数

2025-01-23
  • SQL
本文总阅读量次

肠断相思岁岁同，事世情缘梦难通。满山烟雨桔花白，无尽相思夜夜风。

聚合把一组行收成一个值

  • AVG、COUNT、MAX、MIN、SUM 对一组行计算。没有 GROUP BY 时整张结果是一组，返回一行；有 GROUP BY 时每组一行。
  • 这些函数写在 SELECT 和 HAVING 里。WHERE 在分组之前过滤单行，不能写 WHERE AVG(age) > 20。
  • 选择列表里出现聚合时，其它列要么也聚合，要么出现在 GROUP BY 中。MySQL 打开 ONLY_FULL_GROUP_BY 时会拒绝含糊列。

AVG 与 SUM

  • 两者都跳过 NULL。全是 NULL 时结果是 NULL，不是 0。
  • 年龄有 NULL 时，AVG(age) 不会把这些行当 0 岁。业务上要把空值当 0，写 AVG(COALESCE(age, 0))，并确认口径。
  • MySQL 的 / 得到带小数的商。PostgreSQL、SQL Server 里两个整数相除会丢掉小数，可移植的写法是 SUM(score) * 1.0 / COUNT(*)，或直接用 AVG。

COUNT

写法 计数
COUNT(*) 行数，包含各列都是 NULL 的行
COUNT(age) age 非 NULL 的行数
COUNT(DISTINCT age) 不同且非 NULL 的年龄个数
  • COUNT(*) 与 COUNT(1) 在现代优化器里没有差别。判断「有没有行」用 EXISTS，不要先 COUNT(*) 再和 0 比较。

MAX、MIN 与分组

  • MAX 只给出值，不指出是哪一行。要「年龄最大的那名学生」，用 ORDER BY age DESC, id LIMIT 1，并列时靠第二排序键决定留谁。
  • 过滤行用 WHERE，过滤组用 HAVING。WHERE age >= 18 先去掉未成年人，再按专业求平均。

和 GROUP BY 的关系

子句 聚合怎么用
SELECT 可以写聚合，或与分组列一起出现
WHERE 只过滤行，不能对聚合结果过滤
GROUP BY 划定每一组
HAVING 过滤分组之后的聚合结果
  • 聚合就是给分组用的。限制在于：不能把聚合写进 WHERE，也不能在严格模式下让一个未分组、未聚合的列混进 SELECT。
  • SELECT name, AVG(age) 不写 GROUP BY：严格模式报错；旧的宽松模式会任取一个 name，平均数却是全表的。

常见坑

  • SUM(amount) / COUNT(*) 与 AVG(amount) 在金额含 NULL 时不是同一个数：SUM 和 AVG 都跳过 NULL，COUNT(*) 仍算那些行。
  • GROUP_CONCAT / STRING_AGG 把一组字符串收成一段文本，有长度上限。只要每组一行的名单时用它，要明细行时用窗口函数。
  • 窗口形式 SUM(score) OVER (PARTITION BY sid) 不减少行数。每组一行用 GROUP BY，明细旁边挂合计用窗口。详见《SQL-窗口函数》。

把一组名字收成一行

  • GROUP_CONCAT 是 MySQL 写法，标准 SQL 里相近的是 STRING_AGG。默认有 group_concat_max_len，超长会被截断且不报错。名单可能很长时先加大这个限制，或改回多行结果。
  • ORDER BY 写在函数里面，决定拼接顺序。写在查询末尾的 ORDER BY 只排组，不排组内的名字。
  • 组内没有非 NULL 名字时，结果是 NULL。要显示空串，用 COALESCE(GROUP_CONCAT(...), '')。

空组与只统计非空

  • 三列放在一起看，才知道平均年龄是按「有年龄的人」算的，还是表里根本没有空年龄。
  • 过滤条件 WHERE age IS NOT NULL 再 AVG(age)，和直接 AVG(age) 的平均数相同，但 COUNT(*) 会少掉空年龄的行。报表要同时给出人数和平均年龄时，把这两个口径写在列名里。
