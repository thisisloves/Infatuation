Spring Boot 项目实践

2025-05-16
  • SpringBoot
本文总阅读量次

行到水穷处，坐看云起时。

对应练习

  1. **bookSystem**：Spring Boot 图书后台（Maven + 常规分层）。
  2. sky-item（苍穹外卖）：sky-common / sky-pojo / sky-server 多模块；资料含原型、接口、SQL；用户端可对照 skyShop 小程序。

Boot 相对 SSM 的变化

SSM Spring Boot
手写整合 XML starter + 自动配置
外置 Tomcat 部署 war 内嵌 Tomcat，jar 直跑
多份 spring*.xml 主配置 application.yml
自己配组件扫描 @SpringBootApplication

苍穹外卖模块职责

为什么要拆？

  • pojo 可被其它端复用，避免循环依赖。
  • common 沉淀横切能力，server 保持业务清晰。
  • 为以后拆微服务预留边界（用户、订单、商品将来可独立进程）。

单体项目常见能力清单

  1. 统一返回 & 全局异常（与 SSM 篇同一套路）。
  2. 登录鉴权：Session 或 JWT + 拦截器 / Filter；管理端与用户端 token 可能分离。
  3. MyBatis / MP：分页、逻辑删除、自动填充 createTime。
  4. 文件上传：本地磁盘或 OSS；数据库存 URL。
  5. 配置分离：application.yml + application-dev.yml，用 spring.profiles.active。
  6. 接口文档：Knife4j / SpringDoc，对照「项目接口」资料联调。

推荐阅读代码顺序（苍穹）

  1. 启动类与 application.yml（端口、数据源、MP）。
  2. 登录接口 → JWT 工具 → 拦截器放行路径。
  3. 一条完整业务：例如「菜品分类 CRUD」走完 Controller → Service → Mapper。
  4. 订单状态流转（下单 / 接单 / 派送），画状态图。
  5. 再看微信登录、来单提醒等扩展点。

bookSystem 怎么用

  • 当作 Boot 入门练手：先让进程起来，再顺着用户、图书两张表走通 Controller → Service → Mapper。
  • 对照早期 bookManage：同一业务从桌面窗口变成 HTTP，原先一个类包办的逻辑拆进三层。
  • 建议顺序：建库并连上 → 启动无报错 → 一个查询接口 → 一个写入接口（确认事务加在 Service 上）。
  • 若有借阅，重点看库存或状态在 Service 里如何校验，页面可以后补。

application.yml 最小骨架

运行与排错

现象 排查
端口占用 改 server.port 或停掉占用进程
映射失败 @MapperScan 包路径是否罩住 Mapper
数据库连不上 url、账号、时区参数、库是否已建
启动后立刻退出 看最后一段 Caused by，不要只改端口
接口 404 启动类所在包是否罩住 Controller，有没有上下文路径
跨域 网关 / Nginx / CorsConfig
静态资源 404 路径是否在 static，拦截器是否误拦

和自动配置、事务

  • 启动类为何「什么都没配也能连库」：见《Spring Boot 自动配置》《Spring Boot 配置与起步》。
  • Service 上 @Transactional 失效场景：见《Spring 事务管理》。
  • 打成 jar 后调不动、内存飙高：见 JVM 三篇。

小结

  • Boot 单体是微服务的前置课：先在模块 / 包级别把 用户、商品、订单、支付 边界切清。
  • 苍穹外卖资料齐全（原型 + 接口 + SQL），建议「先跑通登录与一张业务表，再铺开」。
