Spring Boot 配置与起步

2025-05-07
  • SpringBoot
本文总阅读量次

工欲善其事，必先利其器。

starter 在依赖里做什么

父工程引入 spring-boot-starter-parent 后，版本由它的 BOM 统一管理，业务依赖通常不必写版本号。

  • spring-boot-starter-web：内嵌 Tomcat、Spring MVC、Jackson。
  • spring-boot-starter-jdbc：数据源与事务自动配置（连接池多为 HikariCP）。
  • spring-boot-starter-test：测试范围，含 JUnit 与切片测试支持。
  • 命名习惯是 spring-boot-starter-*；第三方常见 *-spring-boot-starter。

starter 本身几乎没有业务代码，它把库和对应的自动配置一起带进来。只加依赖、不满足条件（例如没有 spring.datasource.url）时，相关 Bean 仍不会创建。

application.yml 与 profile

主配置放 src/main/resources/application.yml。profile 用独立文件覆盖差异项：

  • application.yml 放各环境共用项；application-dev.yml、application-prod.yml 只写差异。
  • 激活方式：spring.profiles.active，或启动参数 --spring.profiles.active=prod，或环境变量 SPRING_PROFILES_ACTIVE。
  • 可以同时激活多个 profile，后面的同名键覆盖前面的。
  • 仓库里不要提交生产口令，生产用环境变量或外部配置文件注入。

配置优先级

同名键由高优先级覆盖低优先级，不同键会合并进同一个 Environment。实际最常碰到的顺序（高 → 低）：

优先级 来源
高 命令行参数，如 --server.port=9090
↑ Java 系统属性，-Dserver.port=9090
操作系统环境变量，SERVER_PORT
jar 包外的 application-{profile}.yml
jar 包内的 application-{profile}.yml
jar 包外的 application.yml
低 jar 包内的 application.yml

因此打好的包不必改 jar：在同级目录放一份 application-prod.yml，或用环境变量覆盖端口和数据源即可。

@PropertySource 加载的文件优先级较低，不适合压过 application.yml。随机值可用 ${random.uuid}，只在需要占位时使用。

@ConfigurationProperties

一组相关配置绑到对象上，比散落的 @Value 好维护。

  • 松散绑定：app.timeout、APP_TIMEOUT 都能对上 timeout 字段。
  • 校验：类上加 @Validated，字段加 @Min 等，并引入 spring-boot-starter-validation。
  • 自动配置模块里不要随意 @Component 扫描业务包，改为在配置类上 @EnableConfigurationProperties(AppProperties.class)。
  • 单个零散值仍可用 @Value("${app.name}")；成组、可复用的配置用 Properties 类。

改完配置需要能在启动日志或单测里看到绑定结果。字段名对不上时，表现为默认值 0 或 null，而不是立刻抛错，除非开了校验。

多环境怎么拆

  1. 本地：dev，连本机数据库，打开 SQL 日志。
  2. 联调：test，独立库与端口，避免和本地数据混在一起。
  3. 生产：prod，关闭多余日志，端口与密码来自环境变量。

切换 profile 不会替换整份配置，只覆盖同名项。公共的 Jackson、上传大小等留在 application.yml，避免每个环境复制一遍后改漏。

Actuator 简述

spring-boot-starter-actuator 提供运行期端点，默认只暴露少量 Web 端点。

端点 用途
health 进程是否存活，可挂数据库等健康项
info 版本、构建信息
metrics 内存、HTTP 耗时等指标
env 实际生效的配置，含敏感项
  • 本地可临时加上 conditions 对照自动配置是否生效。
  • 生产至少暴露 health；env、heapdump、shutdown 默认不要对公网开放。
  • 端点需要鉴权或只监听内网管理端口，不要和业务端口裸奔在同一入口。

小结

  • starter 负责把库和自动配置一起引进来，版本交给 parent / BOM。
  • profile 管环境差异，优先级管「最终哪一份值生效」。
  • 成组配置用 @ConfigurationProperties，上线前用环境变量覆盖机密项。
  • Actuator 先开 health，再按需加指标，敏感端点默认关闭。
