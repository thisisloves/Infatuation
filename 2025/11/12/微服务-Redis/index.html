微服务 Redis

2025-11-12
  • 微服务
本文总阅读量次

清水出芙蓉，天然去雕饰。

对应练习

  • 端口：6379
  • 读多写少：商品详情、类目、首页榜单
  • 用户态：购物车
  • 互斥：防重复提交、定时任务单实例执行

MySQL 承担成交和库存的最终结果。Redis 承担热点读和短时协调。搜索索引见 Elasticsearch 篇，和缓存删键是两条线。

缓存用来做什么

详情页每次都查库，热点商品会把连接打满。把读结果放进 Redis，请求先打缓存，未命中再查库并回填。

适合缓存的是可以短暂旧一点的数据：标题、图片、价格展示。库存扣减、支付状态以数据库事务为准。

String、Hash、ZSet

结构 键 场景
String item:detail:{id} 整份详情 JSON
Hash cart:{userId} 字段是 skuId，值是数量
ZSet rank:sales member 是 skuId，score 是销量
  • String 一次读写整份详情，适合整对象缓存。
  • Hash 可以只改购物车里一个 sku，不必读出整车再写回。
  • ZSet 按分数排序，首页取前十用 ZREVRANGE。

过期时间不要全写成同一个整数。详情以 30 分钟为底，再加 5 分钟以内的随机值，避免同一批键一起失效。

List、Set、Bitmap

结构 命令 适合
List LPUSH / RPOP 简单队列、按顺序留最近若干条
Set SADD / SINTER 去重、求交集
Bitmap SETBIT / BITCOUNT 签到、在线等二值状态

12 是位偏移。编号连续时，一个位就能记下一种状态；偏移很大又稀疏，Bitmap 会占掉多余空间。详情、购物车、榜单仍用前面的 String、Hash、ZSet。

穿透、击穿、雪崩

穿透：查一个根本不存在的 id，缓存没有，每次都打到库。

  • 对空结果也缓存，过期大约 1 分钟。新建的商品能较快被装进缓存。
  • 或用布隆过滤器挡掉「一定不存在」的 id。布隆说没有，就可以直接返回；说可能有，再查缓存和库。

击穿：一个热点键到期，大量请求同时未命中，一起查库。

用互斥锁只放一个请求去加载，其它请求短暂等待后重读缓存。另一种做法是键本身不过期，值里带逻辑过期时间，由异步任务刷新，读请求继续拿旧值。

雪崩：大量键在同一时刻过期，或 Redis 不可用，流量全部落到 MySQL。

  • 过期时间加随机抖动。
  • 用主从或哨兵，避免单机宕掉就没有缓存。
  • 入口还有 Sentinel 限流时，缓存失效也不会把数据库打满。

商城热点数据

数据 做法
商品详情 String 缓存；极热的 id 可在进程内再放一层短过期本地缓存
购物车 Hash，按用户一条
销量榜 ZSet，展示用；对账以订单表为准
重复提交 lock:order:{userId} 或唯一请求号

详情的更新顺序：先改 MySQL，再删除 item:detail:{id}。下次读取回填新值。删除失败要重试，否则会一直读到旧 JSON。缓存和搜索索引分别失效：删键给详情接口，发消息给 ES（见 Elasticsearch 篇）。

空缓存、互斥回填、随机过期三件套先接上，再谈本地缓存。本地缓存会多一份不一致窗口，只加在真正的热点 id 上。

RDB 与 AOF

RDB 把某一时刻的内存写成二进制快照。BGSAVE 会 fork 子进程写文件，主进程继续处理命令。文件小，适合备份，重启时加载快。大内存 fork 时，写时复制会带来额外内存压力。两次成功快照之间进程退出，这段写入不在文件里。SAVE 在主线程里写盘，会堵住命令处理。

AOF 把写命令追加到日志末尾。always 每条命令都刷盘，丢失最少，磁盘压力最大。everysec 大约每秒刷一次，宕机时大约丢掉这一秒里的写入。no 交给操作系统决定何时落盘，尚未刷出的一段都会丢。日志变长后，BGREWRITEAOF 收成更短的等价命令。重启要重放日志，恢复比加载 RDB 慢。

混合持久化（Redis 4.0 起）在重写 AOF 时先以 RDB 格式写下当时的全量，再追加其后的增量命令，重启先加载快照再重放尾部。

持久化 进程异常退出时可能丢失
仅 RDB 最后一次成功快照之后的写入
AOF always 正在落盘的那条命令
AOF everysec 大约最近一秒的写入
AOF no 操作系统还没刷出的一段
都关闭 内存里的全部数据

主从复制是另一条链路。命令还没传到从节点，主节点就退出，从节点上没有这条新写入。

小结

  • 详情用 String，购物车用 Hash，榜单用 ZSet，过期时间要错开。
  • List 做队列，Set 去重，Bitmap 按位记状态。
  • 穿透缓存空值，击穿用互斥回填，雪崩靠抖动、高可用和限流。
  • 分布式锁带 token 和过期时间；库存以数据库条件更新为准。
  • RDB 做快照，适合备份；要少丢数据用 AOF，丢多少由刷盘策略决定。
