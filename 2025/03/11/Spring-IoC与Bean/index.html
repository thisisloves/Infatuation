Spring IoC 与 Bean

2025-03-11
  • Spring
本文总阅读量次

昨夜西风凋碧树，独上高楼，望尽天涯路。

对应练习

  • 项目：spring_01_bean
  • 配置：src/main/resources/applicationContext.xml
  • 入口类：AppForDIConstructor、AppForDIAutoware、AppForDICollection、AppForLifeCycle、AppForBeanFactory 等。

IoC / DI 到底在说什么

  • 没有容器时：Service 里 new Dao()，依赖写死，难测、难换实现。
  • IoC（控制反转）：把「谁创建对象、对象怎么依赖」交给容器。
  • DI（依赖注入）：容器把依赖塞进对象（构造器 / setter / 字段）。

获取容器

  • BeanFactory 更底层、懒加载；ApplicationContext 会预实例化单例，并带上事件等能力，业务代码用它。
  • XML 用 ClassPathXmlApplicationContext；注解配置用 AnnotationConfigApplicationContext。
  • 用完调用 close()，单例的销毁回调才会执行。按类型 getBean 命中多个 Bean 时要带上名字，否则抛 NoUniqueBeanDefinitionException。

XML 装配

注入方式对比

方式 XML 优点 注意
setter <property> 灵活、可选依赖 可能出现半初始化对象
构造器 <constructor-arg> 依赖不可变、必填清晰 参数多时臃肿
自动装配 autowire 少写 ref byType 有多个候选会失败
集合 <list>/<map>/... 批量注入 注意 merge / 覆盖

作用域

scope 含义
singleton（默认） 容器内一份
prototype 每次获取新建
request / session Web 环境

单例陷阱

  • 单例 Bean 不要放可变的用户状态（和 Servlet 单例同理）。请求级数据放在方法参数里，或使用 request 作用域。
  • 单例依赖原型时，注入的是「创建单例那一刻」的原型实例，之后一直拿着那一个对象。
  • 也可以注入 ObjectProvider<BookDao>，每次使用时再 getObject()。
  • @Lookup 的方法要能被覆写，不要写成 private。

Bean 生命周期

单例从创建到销毁按固定顺序走。回调挂在对应的一步，时机才对。

  1. 实例化：执行构造器，得到还没有注入依赖的对象。
  2. 属性填充：完成构造器参数、setter 和字段注入。
  3. Aware：回调 BeanNameAware、BeanFactoryAware、ApplicationContextAware 的 setXxx。
  4. 前置处理：postProcessBeforeInitialization。@PostConstruct 在这一步执行，依赖已经填好，代理还没套上。
  5. 初始化：先 InitializingBean.afterPropertiesSet()，再执行 init-method。
  6. 后置处理：postProcessAfterInitialization。AOP 在这里把原对象换成代理；前面的初始回调已经在原始对象上跑过。
  7. 使用：getBean 与业务调用拿到的是后置处理的返回值。
  8. 销毁：容器关闭时依次执行 @PreDestroy、DisposableBean.destroy()、destroy-method。

XML 里的 init-method 和 destroy-method 就是第 5 步和第 8 步。销毁只覆盖 singleton，并且要容器执行 close()。prototype 由取用方自己释放。

BeanPostProcessor / FactoryBean

  • BeanPostProcessor：在初始化前后插手几乎每一个 Bean。AOP 代理就是在后置处理里把原对象换成代理。
  • FactoryBean：按名字取出的是 getObject() 的产品；要工厂自身时用 &beanName。MyBatis 的 SqlSessionFactoryBean 就是这个模式。
  • 后置处理里不要再 getBean 去触发一条新的创建链，容易绕进循环依赖。

练习建议

  1. 把 bookService 的 scope 在 singleton / prototype 间切换，多次 getBean 比 ==。
  2. 故意制造 byType 冲突（两个同类型 Dao），看启动报错信息。
  3. 给 Bean 加 init 打印，观察创建时机。

小结

  • IoC 是 Spring 的心脏：先搞懂 Bean 定义、依赖图、作用域、生命周期，注解与 Boot 只是换皮。
