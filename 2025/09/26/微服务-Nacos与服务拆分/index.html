微服务 Nacos 与服务拆分

更细的拆分见：《微服务 概述与拆分》《微服务 Nacos 注册发现》《微服务 Nacos 配置管理》。本篇保留作总览。

对应练习

  • 工程：hmall
  • 业务服务：user-service、item-service、cart-service、order-service、pay-service
  • 公共：hm-common、hm-api、hm-gateway
  • 注册配置中心：本机 Nacos（如 Nacos 安装目录，端口 8848）

为什么从单体走到微服务

单体痛点 微服务应对
一处改动全量发布 按服务独立发布
资源互相拖累 按需扩容热点服务
团队协作冲突 按边界分团队

代价：分布式必然带来 网络失败、超时、数据一致性、运维复杂度——后面 Gateway / MQ / Seata 都是在补这些代价。

hmall 模块地图

拆分原则

  1. 按业务能力拆，而不是按技术层硬拆（不要拆成「只有 dao 的服务」）。
  2. 服务间通过 API 模块 依赖接口，避免直接依赖对方实现工程。
  3. 数据库最好 每服务独立库/独立 schema（练习阶段可先逻辑分离）。

Nacos：注册中心

  1. 服务启动后向 Nacos 注册：服务名 + IP + 端口 + 元数据。
  2. 调用方按 服务名 发现实例列表，再负载均衡。
  3. 控制台：服务管理 → 服务列表（注意命名空间、Group）。

Nacos：配置中心

  • 把 application.yml 中环境相关项抽到 Nacos，支持动态刷新。
  • Gateway 的路由 JSON（见 Gateway 篇）也可放配置中心监听。

要点

  1. value 必须是 Nacos 服务名。
  2. 路径与提供方 Controller 一致。
  3. fallbackFactory：提供方挂了时的降级逻辑（返回默认值或抛业务异常）。
  4. 启动类加 @EnableFeignClients(basePackages = "...")。

调用链

超时、重试与幂等

  • Feign / Ribbon / LoadBalancer 都有超时配置；超时后可能重试。
  • 写接口必须幂等（扣库存用乐观锁 / 唯一键），否则重试会成双花。

小结

  • Nacos 解决「找到谁」；Feign 解决「怎么调」。
  • 服务列表里能看见实例，只是第一步；还要保证 Group、命名空间、鉴权、Feign 服务名 四面墙对齐。
