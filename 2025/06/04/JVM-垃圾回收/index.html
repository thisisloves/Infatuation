JVM 垃圾回收

2025-06-04
  • JVM
本文总阅读量次

落红不是无情物，化作春泥更护花。

怎样判断对象还活着

HotSpot 使用可达性分析，不用引用计数。引用计数实现简单，但循环引用会漏回收。

从 GC Roots 沿引用往下走，走不到的对象视为不可达，可以回收。常见根包括：

  • 虚拟机栈局部变量表中的引用
  • 方法区中类静态属性引用的对象
  • 方法区中常量引用的对象
  • 同步锁持有的对象
  • JNI 引用的对象

不可达之后还有一步：若对象重写了 finalize 且尚未执行过，会先进入终结队列。终结器不可靠，且会拖慢回收，业务代码不要依赖它释放资源。

软引用、弱引用、虚引用影响的是「还够不够格继续活」，不改变根可达这条主规则。缓存适合软引用或弱引用；PhantomReference 配合引用队列做堆外资源的清理通知。

三种基础算法

算法 做法 优点 代价
标记-清除 标出存活对象，清掉其余 不必移动对象 产生内存碎片
复制 存活对象拷到另一块空间，原空间整块清空 无碎片，分配时指针碰撞即可 需要空闲的半区
标记-整理 标记后把存活对象挪到一端 无碎片，空间利用率高 移动对象，暂停更明显

年轻代存活对象少，用复制算法划算：Eden 加一块 Survivor 作为来源，另一块 Survivor 作为目的。老年代存活比例高，复制会浪费空间，更常用标记-清除或标记-整理。

分代收集

分代不是算法名，而是按对象寿命选用不同算法：

  • 大多数对象在第一次年轻代收集时死去，所以年轻代收集频繁，但单次暂停通常较短。
  • 对象每熬过一次年轻代收集，年龄加一，到达阈值后晋升老年代。
  • 动态年龄判定：Survivor 中相同年龄对象大小之和超过空间一半时，大于等于该年龄的对象提前晋升。
  • 老年代收集更慢。老年代被快速填满，往往是晋升过快或存在泄漏，而不是「年轻代收集太少」。

年轻代收集为什么不用扫整堆

老年代指向年轻代的引用相对少。HotSpot 用卡表把老年代划成许多卡，谁持有跨代引用，就把那张卡标脏。Minor GC 把脏卡当作额外的根，不必从老年代每个对象重新走一遍。

G1 的记忆集记录 Region 之间的跨区引用，目的相同：只回收一部分 Region 时，仍然找得到外面指进来的指针。

一次 Minor GC

  • 复制之后，外部引用会被改到新地址。
  • Survivor 放不下的对象提前进入老年代，这是老年代上涨的直接来源。
  • 日志里若「等到安全点」的时间很长，要和真正复制对象的时间分开看。长时间不轮询安全点的紧循环会把停顿拖长。

并发标记时的三色

并发标记和业务线程同时进行，引用会被改写。三色只描述扫描进度：

  • 白：还没访问。本轮结束仍是白，就当作垃圾。
  • 灰：自身已访问，它指向的对象还没扫完。
  • 黑：自身以及直接引用的对象都已扫过。

漏标的典型情况：黑色对象新指向一个白色对象，原来指向白色对象的灰色引用又被删掉。写屏障会把变化记下来。G1 用 SATB，在引用被覆盖前记下旧值，交给并发标记补扫。知道「并发标记必须补上业务线程改引用造成的漏洞」就够用，不必先读屏障源码。

常见收集器

收集器 关注点 说明
Serial / Serial Old 单线程、暂停简单 堆很小或客户端场景
Parallel Scavenge / Parallel Old 吞吐量 JDK 8 服务端默认组合
CMS 老年代并发标记清除 碎片、并发失败会退化，JDK 9 起标记过时，后续移除
G1 可控暂停 JDK 9 及以后默认
ZGC、Shenandoah 更低暂停 超大堆时再评估，启用前先读对应 JDK 的支持情况

可以只选一个主收集器。Parallel 与 G1 不要在参数里互相覆盖，以启动参数里最后生效的 -XX:+Use*GC 为准。

G1 要点

G1 把堆切成许多等大的 Region（大约 1MB 到 32MB）。每个 Region 可以扮演 Eden、Survivor、老年代或大对象区（Humongous，对象大于 Region 一半）。

  • Young GC：回收全部年轻 Region，存活对象复制到新的 Region。
  • 并发标记：与业务线程交替进行，找出垃圾比例高的老年代 Region。
  • Mixed GC：除年轻 Region 外，再捎带一部分垃圾最多的老年代 Region。这是 G1 控制暂停的主要手段。
  • 目标暂停时间由 -XX:MaxGCPauseMillis 给出（默认 200 毫秒），是目标不是保证。调得过小会让每次回收太少，反而更频繁。
  • Full GC 在 G1 里是退路：疏散失败或并发标记赶不上分配时，整堆停顿收集。日志里经常出现 Full GC，说明 Region、晋升或泄漏已经不健康，而不是再把暂停目标改小就能好。

Minor GC 与 Full GC

名称 通常范围 日志里怎么理解
Minor GC / Young GC 年轻代 正常且频繁；看晋升速率是否异常
Mixed GC 年轻代 + 部分老年代 G1 特有，不等于整堆收集
Full GC 整堆，往往还涉及元空间 停顿长；应少见

Major GC 一词并不统一，有的文章用它专指老年代。以日志里的具体名称（Young、Mixed、Full）为准，不要只凭「Major」猜测范围。

System.gc() 只是建议，默认仍可能触发 Full GC。库或业务代码里不要主动调用，需要禁用时用 -XX:+DisableExplicitGC（使用直接内存的框架是否依赖显式 GC，要先确认）。

小结

  • 存活看可达性，根到不了的对象才会被回收。
  • 年轻代复制，老年代整理或清除；G1 用 Region 把这件事拆开做。
  • Minor 频繁可以接受，Full GC 频繁就要查晋升、泄漏或堆是否过小。
