JVM 类加载

2025-06-14
  • JVM
本文总阅读量次

天生我材必有用，千金散尽还复来。

加载到初始化

类要经过加载、验证、准备、解析、初始化，才能被使用。验证、准备、解析合称链接。解析在规范里位于初始化之前，执行时经常推迟到第一次用到某个符号引用。加载和链接可以先完成，没有主动使用就不会跑 <clinit>。

加载。类加载器取得 class 字节流，把元数据放进方法区，并在堆上生成 java.lang.Class。数组类由虚拟机直接创建。

验证。确认字节流可以安全执行，依次看文件格式、元数据、字节码和符号引用。格式错误抛 ClassFormatError，字节码不合法抛 VerifyError。

准备。给静态变量分配内存并写入零值。static int n = 1 准备结束时仍是 0，1 要等初始化。编译期常量（static final 的基本类型或字符串字面量）在准备阶段就写成目标值。

解析。把常量池里的符号引用换成直接引用。类名、方法名对不上时，抛出 NoSuchMethodError、NoSuchFieldError 这一类错误。

初始化。执行 <clinit>，也就是静态赋值和静态代码块，按源码顺序合成一段。父类的 <clinit> 先于子类。同一加载器下虚拟机会加锁，保证只做一次。

准备结束时 n 为 0，FIXED 已是 2。<clinit> 跑完后 n 为 4。

会触发初始化的主动使用：new、读写非常量静态字段、调用静态方法、Class.forName（默认）、初始化子类、启动 main 所在的类。读取编译期常量只是把值抄进调用方，定义常量的那个类不会因此初始化。

三类加载器

加载器 也叫 负责
Bootstrap 启动类加载器，Java 侧看到 null java.lang 等核心类
Ext / Platform JDK 8 为扩展类，JDK 9 起为平台类 扩展目录或平台模块
App 应用程序类加载器 应用类路径

启动类加载器由本地代码实现，不是 Java 对象，所以 String.class.getClassLoader() 为 null。App 的父加载器是 Ext 或 Platform，Ext 与 Platform 的父加载器才是 Bootstrap。

类的身份是「加载器 + 全限定名」。两个加载器各定义一份同名类，得到两个类型，不能互相赋值。

双亲委派

加载某个名字时，先把请求交给父加载器。父加载器能定义就由它定义；父加载器找不到，当前加载器再自己找。这就是双亲委派。实现里是一条 parent 链，请求沿 parent 往上走。

安全。java.lang.Object、java.lang.String 由 Bootstrap 定义。应用类路径上即使放了同名类，请求也会先被父加载器满足，应用代码换不掉核心类。

统一。整个进程共用一份 Bootstrap 定义的 Object。所有类的超类是同一个类型，instanceof 和集合才能按同一套规则工作。若每个加载器各有一份 Object，继承关系会对不上。

加载器会记住自己定义过的名字。同一个加载器不会把同一个名字定义两次。

在哪里打破

委派写在 loadClass 的约定里。下面两种场景会改方向。

SPI。接口在核心库里，由 Bootstrap 加载，例如 java.sql.Driver。实现类在应用类路径，Bootstrap 看不见。核心代码改用当前线程的上下文类加载器（一般是 App）去加载实现，再实例化。方向变成父加载器请子加载器完成加载。实例化会触发实现类的初始化，驱动由此完成注册。

热部署。类一旦被某个加载器定义，这个加载器不会再定义同名新版本。更新的办法是换一个新加载器读取新字节码；旧加载器不再可达，旧类才能被卸载。Web 容器给每个应用单独的加载器，应用目录里的类优先自己加载，核心包仍交给父加载器。不同应用因此可以各带一版依赖库，重新发布时替换加载器。

java.* 仍交给 Bootstrap。Object 保持全进程一份，应用类也替换不了核心类。

forName 与 loadClass

两者都会加载类，差别在会不会执行 <clinit>。

调用 初始化
Class.forName(name) 会，等价于第二个参数为 true
Class.forName(name, false, loader) 不会
ClassLoader.loadClass(name) 不会

单参数 forName 使用调用方的类加载器，并执行静态代码块。早期 JDBC 用它触发驱动类里的注册。loadClass 做到加载和链接为止，静态块留到第一次主动使用。要立刻跑静态逻辑，用会初始化的 forName；只想先拿到 Class 对象，用 loadClass 或 initialize=false。

小结

  • 准备写零值，初始化才执行静态赋值和静态块；编译期常量在准备阶段就位。
  • Bootstrap、Ext（Platform）、App 把请求交给父加载器，核心类全进程只有一份。
  • SPI 用上下文类加载器反向加载实现；热部署靠更换类加载器。
  • Class.forName 默认初始化，ClassLoader.loadClass 不初始化。
